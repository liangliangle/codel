# 技能扩展（Skills）

技能扩展（Skill）是可复用的 Prompt 包，使用特定任务的指令来拓展 Codel 的能力。它们让你只需捕获一次可重复的操作流程，而无需在每个会话中重新解释。

---

## 什么是技能扩展？

技能扩展是一个包含 `SKILL.md` 文件的目录。其 Markdown 正文告知 Codel 如何处理特定类型的任务：包含按部就班的指令、规范约定以及工具使用模式。

当某个可重复的操作流程对于 AGENTS.md 来说过于具体，但又长到不想重复输入时，就可以使用技能扩展。仅当技能扩展适用于当前任务时，Codel 才会激活它。

---

## 技能扩展的存储位置

Codel 会按照以下优先级顺序从这些目录中自动发现技能扩展：

| 位置 | 作用域 | 优先级 | 说明 |
|----------|-------|----------|-------|
| `./.codel/skills/`, `./.codel/commands/` | 本地 (CWD) | 最高 | 当前目录下的技能扩展 / 传统的命令 Markdown |
| `<repo_root>/.codel/skills/`, `…/commands/` | 仓库 | 中等 | 跨整个仓库共享 |
| `~/.codel/skills/`, `~/.codel/commands/` | 用户 | 最低 | 适用于所有项目的个人技能扩展 |
| `~/.claude/skills/`, `~/.claude/commands/` | 用户 | 最低 | Claude Code 兼容性（可配置） |
| `./.claude/skills/`, `./.claude/commands/` | 本地 / 仓库 | 高 | 项目的 Claude 技能扩展及传统自定义斜杠指令 |
| `~/.cursor/skills/` | 用户 | 最低 | Cursor 兼容性（可配置） |
| `./.cursor/skills/` | 本地 / 仓库 | 高 | 项目的 Cursor 技能扩展（在启用 Cursor 兼容技能扩展时） |

Codel 会根据名称对技能扩展进行去重 -- 较高优先级的存储位置会覆盖较低优先级的存储位置。Codel 还会扫描每个层级的 `.agents/skills/`（以及 `commands/`）（与 `.codel/` 并列），并遍历你的工作目录到仓库根目录之间的每一个目录。

位于 `commands/` 目录下的纯文本 `*.md` 文件会变为用户可调用的斜杠指令（文件名主干 = 指令名称），这与 Claude Code 传统的自定义指令布局相匹配。

技能扩展和指令的发现**不使用** `.gitignore`。已知技能扩展根目录（`.codel/`、`.agents/`、`.claude/`、`.cursor/`）下的路径只要在磁盘上存在就会始终加载 -- 团队经常将 `.claude/**` 视作仅限本地的配置加以忽略，但依然希望像 `/frontend` 风格的项目指令可以正常工作。若想隐藏某个技能扩展，请在配置中使用 `[skills] ignore`（而非仓库的忽略规则）。

默认情况下，Codel 会扫描 Claude 和 Cursor 的技能扩展目录。若要停止扫描某个厂商，在 `~/.codel/config.toml` 中的 `[compat.cursor]` 或 `[compat.claude]` 下将其 `skills` 单元格设置为 `false`，或将环境变量 `CODEL_CURSOR_SKILLS_ENABLED` 或 `CODEL_CLAUDE_SKILLS_ENABLED` 设置为 `false`。参阅[系统配置](05-系统配置.md#harness-工具链兼容性)获取详情。无论这些设置如何，Codel 总是会自动过滤掉已知厂商附带的默认技能扩展（例如 Cursor 的 `shell`、`canvas` 和 `statusline`）。

### 额外的技能扩展目录

在 `~/.codel/config.toml` 的 `[skills]` 下添加目录、排除路径或禁用单个技能扩展：

```toml
[skills]
paths = ["~/my-team-skills"]          # 额外扫描的目录
ignore = ["~/my-team-skills/wip"]     # 排除的路径 (完全隐藏)
disabled = ["wip-skill"]              # 保留在列表中但保持停用状态的技能扩展名称
```

`paths` 中的每个条目都是一个 `SKILL.md` 文件或 Codel 递归遍历的目录。`ignore` 将彻底隐藏某个技能扩展；`disabled` 将其保留在列表中，但将其从系统 Prompt 和调用中排除。`paths` 和 `ignore` 接收文件系统路径并支持 `~` 路径展开；`disabled` 接收技能扩展名称。

## 创建技能扩展

### 目录结构

每个技能扩展都保存在拥有 `SKILL.md` 文件的独立目录中：

```
~/.codel/skills/
  commit/
    SKILL.md
  review-pr/
    SKILL.md
  deploy/
    SKILL.md
```

### SKILL.md 格式

技能扩展文件包含 YAML 前言（Frontmatter），紧接着是 Markdown 指令：

```markdown
---
name: commit
description: Create well-formatted git commits following conventional commit standards. Use when the user wants to commit changes or asks for /commit.
---

# Git Commit Skill

Review staged changes and create a commit with a clear, conventional message.

## Steps

1. Run `git diff --staged` to see changes
2. Summarize what changed and why
3. Create commit message following conventional commits format
4. Run `git commit -m "..."` with the message
```

### 核心前言字段

| 字段名 | 描述 |
|-------|-------------|
| `name` | 技能扩展标识符。使用小写字母、数字和连字符，最多 64 个字符。Codel 会自动将空格和下划线转换为连字符。如果省略 `name`，Codel 将使用技能扩展的目录名称。 |
| `description` | 技能扩展的功能以及何时使用它。Codel 读取此描述以决定是否调用该技能扩展。如果省略它，Codel 将使用正文的第一段。 |

请编写具体的 `description`。它决定了 Codel 何时会自动调用该技能扩展。请指明触发短语和使用场景。

### 可选前言字段

多单词的前言 Key 使用 kebab-case 短横线连接格式（单单词 Key 如 `model` 则按原样书写）。

| 字段名 | 描述 |
|-------|-------------|
| `when-to-use` | 自动调用的触发短语，与 `description` 分开存放。 |
| `allowed-tools` | 该技能扩展使用的工具，写为 YAML 列表或以逗号/空格分隔的字符串。 |
| `argument-hint` | 在斜杠指令自动补全中显示的参数提示文本（例如 `commit message`）。 |
| `user-invocable` | 是否可以作为斜杠指令运行。默认为 `true`；设置为 `false` 在斜杠指令中隐藏。（若要阻止模型自动调用技能扩展，请改用 `disable-model-invocation`。） |
| `disable-model-invocation` | 为 `true` 时，仅能通过你的斜杠指令运行该技能扩展 -- 模型无法自动调用它。默认为 `false`。 |
| `model` | 运行该技能扩展时的覆盖模型。 |
| `effort` | 推理努力程度覆盖设置。 |
| `license` | 许可证标识符（例如 `Apache-2.0`）。 |
| `compatibility` | 环境要求（例如 `Requires git, docker, jq`）。 |
| `metadata` | 任意字符串键值对。Codel 将 `metadata.author` 和 `metadata.short-description` 提拔显示。 |

## 使用 /create-skill 创建技能扩展

`/create-skill` 命令引导你以交互方式构建一个新的技能扩展。Codel 会询问你的需求，起草文件并将其写入磁盘。

### 工作原理

当你运行 `/create-skill` 时，Codel 会：

1. **收集需求。** Codel 会询问技能扩展名称、保存的作用域以及你想捕获的工作流描述。名称请使用包含小写字母、数字和连字符的文本（2–64 个字符，以字母或数字开头和结尾）。

2. **起草描述。** Codel 会编写一段 `description`，说明技能扩展的作用、触发短语以及斜杠指令名称。你在继续之前批准或编辑草稿。

3. **创建技能扩展目录。** Codel 会创建 `<scope>/.codel/skills/<name>/` 目录，当技能扩展需要脚本或参考文档时，还会附加创建 `scripts/` 或 `references/` 子目录。

4. **写入 SKILL.md。** Codel 会写入前言（`name` 和 `description`）以及包含指令的 Markdown 正文，连同所有支持文件。

5. **校验并确认。** Codel 会读回文件，确认其写入无误，并告知你如何运行该技能扩展。

### 选择作用域

Codel 会询问将技能扩展保存在何处：

- **项目级** (`<repo_root>/.codel/skills/<name>/`) -- 仅在当前仓库中可用，并可通过版本控制与团队成员共享。Codel 推荐在 git 仓库内部使用此作用域。
- **用户级** (`~/.codel/skills/<name>/`) -- 在你的所有项目中均可用。

新技能扩展会在几秒钟内出现在斜杠菜单中，因为 Codel 会在磁盘文件发生更改时自动重新加载技能扩展。

## 使用技能扩展

### 按名称运行技能扩展

每个技能扩展都是以该技能扩展命名的斜杠指令。只需输入其名称即可运行：

```
/commit              # 运行 "commit" 技能扩展
/review-pr           # 运行 "review-pr" 技能扩展
```

运行技能扩展会将它的指令加载到对话中，并指导模型遵循这些指令。若需传递参数，请在名称后直接输入：

```
/commit fix the build
```

若需浏览你的技能扩展，输入 `/` 即可打开斜杠指令菜单。Codel 会列出每个内置指令和技能扩展，并在你打字时对其进行过滤。若想在命令行中列出技能扩展，请运行 `codel inspect`（参阅[查看技能扩展详情](#查看技能扩展详情)）。

### 限定名称（Qualified Names）

当某个技能扩展的名称与另一个技能扩展或内置指令冲突时，Codel 会展示带有技能扩展作用域前缀的限定名称 -- `local:`、`repo:`、`user:` 或插件名称。使用限定形式来指定选择具体的技能扩展：

```
/local:commit        # 来自 ./.codel/skills/ 的 "commit" 技能扩展
/user:commit         # 来自 ~/.codel/skills/ 的 "commit" 技能扩展
```

### 自动调用

当 Codel 识别出相关任务时，它可以自行调用技能扩展。Codel 会将你的 Prompt 与技能扩展的 `description` 及 `when-to-use` 字段进行匹配，因此请在两者中准确描述触发的场景。

例如，如果一个技能扩展的描述写着“在用户想要提交更改时使用”，那么输入“commit my changes”就能自动触发该技能扩展。若想要求必须使用显式的斜杠指令并防止自动调用，请在前言中设置 `disable-model-invocation: true`。

## 查看技能扩展详情

运行 `codel inspect` 可以查看 Codel 发现的所有技能扩展，以及其余配置信息：

```bash
codel inspect          # 人类可读的摘要
codel inspect --json   # 机器可读的报告
```

在人类可读的输出中，Skills 部分列出了每个技能扩展的名称及其来源 -- `project`、`user`、`bundled`、`config`（`[skills].paths` 条目）、`server`（从托管工作区中的技能扩展商店同步的技能扩展）或 `plugin: <name>`。Codel 会使用 `[disabled]` 标记任何通过 `[skills].disabled` 或通过停用的厂商表面禁用的技能扩展。

该报告以与实时会话完全相同的方式遵循你的 `[skills]` 配置：列出来自 `paths` 的技能扩展，隐藏 `ignore` 前缀下的技能扩展，而 `disabled` 中命名的技能扩展保持列出但标记为 `[disabled]`。

`--json` 报告包含了每个技能扩展的完整细节：其 `name`、`description`、`source`（带到 SKILL.md 文件的路径）以及 `userInvocable` 标记。

## 内置与插件技能扩展

Codel 将平台自带的技能扩展与你的个人技能扩展分开分发。内置技能扩展缓存于 `~/.codel/bundled/skills/`；Codel 绝不会将其写入 `~/.codel/skills/`。同名的本地、仓库或用户技能扩展会覆盖内置副本。`codel inspect` 会使用其真实来源标注每个定义。（同名的插件技能扩展不会覆盖原生技能扩展；它依然在限定的 `plugin:name` 形式下可用。）

技能扩展也可以来自于插件。当你安装了一个包含技能扩展的插件时，它们会与你的用户及项目技能扩展一起出现。`codel inspect` 会将其来源标注为 `plugin: <name>`。

参阅[插件系统指南](09-插件系统.md)了解更多关于安装提供技能扩展的插件的信息。

## 最佳实践

1. **编写具体的描述。** 描述决定了自动调用。“创建 git 提交”过于模糊；“遵循规范提交标准创建格式良好的 git 提交。在用户想要提交更改或要求 /commit 时使用。”效果更好。

2. **包含具体的步骤。** 当技能扩展为 Codel 提供清晰、有序的操作流程时效果最佳。

3. **按名称引用工具。** 当技能扩展依赖特定工具（例如 `run_terminal_command` 或 `search_replace`）时，指明它们的名称以便模型知道要使用什么。

4. **保持技能扩展的专注性。** 每个工作流编写一个技能扩展。一个 "deploy" 技能扩展和一个 "rollback" 技能扩展比单个 "deploy-and-rollback" 技能扩展工作得更好。

5. **对项目技能扩展进行版本控制。** 将 `.codel/skills/` 提交到你的仓库中，以便整个团队受益。`~/.codel/skills/` 中的用户技能扩展保持为个人私有不共享。

6. **运行进行测试。** 在依赖自动调用之前，通过输入 `/name` 运行并确认技能扩展正常工作。
