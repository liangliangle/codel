# 跨会话长期记忆 (Cross-Session Memory)

长期记忆让 Codel 能够回忆起早期会话中的事实、决策和模式。Codel 会对你保存的信息进行索引并自动进行搜索，以便新的会话可以重用相关的上下文。

---

## 什么是长期记忆？ (What Is Memory?)

如果没有长期记忆，每个 Codel 会话都将重新开始：模型对之前的会话一无所知。启用长期记忆后，Codel 可以：

- 回忆起你之前解释过的项目规范。
- 重用过去行之有效的调试步骤。
- 在跨会话期间延续架构决策。
- 避免重复提出已经得到解答的问题。

长期记忆是一项实验性功能，默认情况下处于禁用状态。

---

## 启用长期记忆 (Enabling Memory)

### 会话级标志 (Per-Session Flag)

```bash
codel --experimental-memory
```

### 环境变量 (Environment Variable)

```bash
export CODEL_MEMORY=1
codel
```

### 配置文件（持久化） (Config File (Persistent))

```toml
# ~/.codel/config.toml
[memory]
enabled = true
```

### 强制禁用 (Force-Disable)

即使其他设置启用了长期记忆，也可以强制禁用：

```bash
codel --no-memory
```

或者：

```bash
export CODEL_MEMORY=0
```

`--no-memory` 标志具有绝对最高优先级，并始终禁用长期记忆。

### 会话中切换 (Mid-Session Toggle)

在会话期间打开或关闭长期记忆，而无需重新启动：

```
/memory on
/memory off
```

此切换是会话作用域的——它不会持久化到 `config.toml` 中。关闭后会移除对记忆工具的访问权限，但会保留磁盘上现有的文件。打开后会重新初始化记忆存储并注册记忆工具。

你也可以在 `/memory` 模态框中通过按下 `t` 键进行切换。

### 优先级顺序 (Priority Order)

1. `--no-memory` CLI 标志（始终禁用）
2. `--experimental-memory` CLI 标志（启用）
3. `CODEL_MEMORY` 环境变量：`1`/`true` 启用，`0`/`false` 禁用
4. `config.toml` 中的 `[memory]` 部分
5. 默认值：禁用

## 长期记忆如何存储 (How Memory Is Stored)

长期记忆以 Markdown 文件的形式存储在 `~/.codel/memory/` 目录下：

| 位置 (Location) | 作用域 (Scope) | 描述 (Description) |
|----------|-------|-------------|
| `~/.codel/memory/MEMORY.md` | 全局 (Global) | 适用于所有项目的事实 |
| `~/.codel/memory/<project-slug>-<hash8>/MEMORY.md` | 工作区 (Workspace) | 项目特定的规范和上下文 |
| `~/.codel/memory/<project-slug>-<hash8>/sessions/` | 会话 (Sessions) | 单个会话的摘要和日志 |

Codel 会在每个工作区目录名称后面附加该仓库身份标识的一小段哈希值。该身份标识是指当该目录是带有 `origin` 远程仓库的 Git 仓库时的 `org/repo` 形式的 `origin`，或者在其他情况下的目录路径。因为同一个仓库的克隆或工作树（worktree）共享同一个 `origin` 远程仓库，它们也共用一个记忆目录。

SQLite 索引支持对所有记忆文件进行混合搜索：
- **FTS5** 提供基于关键字匹配的全文搜索。
- **vec0** 提供基于语义相似度的向量搜索。向量搜索是可选的，并需要嵌入模型（embedding）。

## 自动保存 (Automatic Saves)

当会话结束时，Codel 会将结构化的元数据摘要保存到该会话的每日日志中。该摘要包含：

- 消息计数（用户、助手的消息以及工具运行结果）。
- 主题（Topics）：会话中最先出现的实质性用户提示，最多五个。
- 会话的日期和时间（UTC）。

Codel 从对话元数据中构建此摘要，无需调用大语言模型 (LLM)，也不增加延迟。Codel 会跳过对微小会话的保存——即那些少于三个实质性提示，或用户输入文本少于 50 字节的会话。

摘要不会记录工具使用情况、文件路径或 Shell 命令。会话 ID 构成日志文件名的一部分。要关闭自动保存，请设置 `session.save_on_end = false`。如需更丰富地捕捉决策、模式和推理过程，请使用 `/flush`。

---

## 使用 /flush 保存丰富知识 (Saving Rich Knowledge with /flush)

要获取更丰富的记录——如决策、模式、调试工作流、API 探索发现——请在终端用户界面 (TUI) 中使用 `/flush`：

```
/flush
```

这会触发由 LLM 生成的当前会话最重要内容的摘要，并将其写入带日期的会话日志中。该摘要将被索引，并在未来的会话中可供搜索。

在以下情况下使用 `/flush` 以保留重要的上下文：
- 在对话压缩 (compaction) 之前（压缩会丢弃旧的对话轮次）
- 在完成了一次高效的调试会话后
- 在发现重要的模式或规范后

## 与长期记忆协同工作 (Working with Memory)

### 记住 (Remember)

要求 Codel 记住某事，它会将笔记附加到 `MEMORY.md` 文件中——对于项目特定的内容，它保存在工作区文件中；对于跨项目的偏好设置，则保存在全局的 `~/.codel/memory/MEMORY.md` 中：

```
> remember to always open PR links after pushing
```

Codel 会在诸如 `## Preferences`（偏好）、`## Project Context`（项目上下文）或 `## Debugging`（调试）等结构化标题下将条目记录为持久的声明。文件监听器会在下一次搜索记忆时重新索引变更，以便新条目可以在当前会话中被搜索到。

你也可以使用 `/remember` 命令直接保存笔记：

```
/remember always open PR links after pushing
```

如果不带任何文本运行 `/remember`，则进入“记住”模式，此时你输入的下一行将成为笔记。无论哪种方式，Codel 都会打开一个审查面板来显示该笔记（你可以通过 `Tab` 键切换重写版本，可选）；只有在确认后，笔记才会被写入。保存时，Codel 会显示 `Memory saved to ~/.codel/memory/MEMORY.md`。

### 遗忘 (Forget)

要求 Codel 忘记某事，它会寻找并移除匹配的条目：

```
> forget the snake_case convention
```

“遗忘”操作是尽力而为的：模型会搜索长期记忆并移除匹配的条目。如需保证绝对的移除，请直接编辑 `~/.codel/memory/` 目录下的文件，自行删除条目。要定位某个文件，请打开 `/memory` 浏览器并按 `y` 复制其路径。

### 回忆 (Recall)

询问 Codel 它记得什么：

```
> what do you remember?
```

Codel 会检索所有记忆文件，并按照来源分组对已知信息进行总结：全局偏好、项目特定的知识，以及会话历史。可使用 `/memory` 浏览原始文件。

### 直接编辑 (Direct Editing)

你可以直接编辑 `~/.codel/memory/` 目录下的记忆文件。文件监听器会在下一次搜索记忆时自动将你的更改重新索引。使用 `/flush` 来立即保存当前会话，使用 `/dream` 将会话日志整合到有序的主题中。

## 使用 /memory 浏览长期记忆 (Browsing Memory with /memory)

`/memory` 命令会打开一个展示所有记忆文件的模态窗口：

```
/memory
```

文件按作用域分组：
- **全局 (Global)** —— 跨项目的长期记忆 (`MEMORY.md`)。
- **工作区 (Workspace)** —— 项目特定的长期记忆 (`MEMORY.md`)。
- **会话 (Sessions)** —— 会话摘要，按时间倒序排列。

该模态框采用分栏布局：左侧为文件列表，右侧为只读的内容预览。预览会随着你在列表中的移动而实时更新。

### 键盘快捷键 (Keyboard Shortcuts)

| 按键 | 动作 |
|-----|--------|
| `↑`/`↓` 或 `j`/`k` | 在文件列表中上下移动 |
| `PgUp`/`PgDn` | 跳过 10 个条目 |
| `/` | 过滤文件列表 |
| `y` | 将选定文件的路径复制到剪贴板 |
| `x` | 删除选定的会话文件（再次按 `x` 确认） |
| `t` | 开启或关闭长期记忆 |
| `Ctrl+F` | 切换全屏 |
| `Esc` | 关闭模态窗口，或退出过滤模式 |

预览窗格是只读的。你可以使用鼠标滚轮或拖动其滚动条来滚动。你只能删除会话文件，不能删除全局或工作区的 `MEMORY.md`。

当记忆模态窗口的内容区域小于 80 列宽时，它将隐藏预览窗格并仅显示文件列表。

你也可以从命令面板打开 `/memory`。

## 记忆通知 (Memory Notifications)

当你使用 `/remember` 保存笔记时，Codel 会在回滚区（scrollback）中确认：

```
Memory saved to ~/.codel/memory/MEMORY.md
```

后台保存操作（flush、dream，以及会话结束）在后台静默运行，不会发送回滚消息。随时使用 `/memory` 浏览 Codel 已存储的内容。

## 使用 /dream 进行知识整合 (Dream Consolidation with /dream)

`/dream` 命令将散落的记忆碎片整合到有组织的主题中：

```
/dream
```

Dream 会将个别的会话日志和记忆条目重组为一个连贯、去重的知识库，随着时间推移，这可以减少噪音并提高搜索质量。`/dream` 要求开启长期记忆功能。

### 自动整合 (Auto-Dream)

Dream 也能自动运行。默认情况下，当会话结束时，Codel 会检查整合条件，只要经过了足够的时间并且积累了足够的会话，它就会运行 Dream：

```toml
[memory.dream]
enabled = true     # 运行自动整合（默认值：true）
min_hours = 4      # 两次整合之间的最短小时数
min_sessions = 3   # 自上次整合以来的最少会话数
# check_interval_secs 默认未设置，因此 Dream 仅在会话结束时运行。
# 将其设置为正整数秒数，可定期进行检查。
```

## 长期记忆对提示的影响 (How Memory Affects Prompts)

### 首次轮次注入 (First-Turn Injection)

在每个会话的首个对话轮次中，Codel 会自动在长期记忆中搜索与当前项目相关的内容，并将其作为上下文注入。这意味着 Codel 即使没有被提醒，在开始时也已经带有了先前会话的知识。

首次注入行为可以配置：

```toml
[memory.initial_injection]
enabled = true     # 启用或禁用首轮记忆注入
min_score = 0.0    # 可选的分数阈值；默认未设置，表示不应用任何过滤
```

### 压缩后 (After Compaction)

在自动压缩后，同样会搜索长期记忆以恢复可能被丢弃的相关上下文。

## 记忆搜索 (Memory Search)

Codel 会自动搜索长期记忆，但在对话中你也可以手动触发搜索：

```
Search memory for "auth middleware patterns"
Read my workspace MEMORY.md
```

模型拥有两个记忆工具的使用权限：
- `memory_search` —— 在所有记忆中进行混合搜索（向量 + 全文）
- `memory_get` —— 按路径读取特定的记忆文件

### 混合打分 (Hybrid Scoring)

记忆搜索使用加权组合机制：
- **向量相似度** (语义) —— 权重：0.7
- **BM25 文本相似度** (关键字) —— 权重：0.3

结果通过最低分数阈值（默认：0.35）进行过滤。

### 来源权重 (Source Weights)

每种记忆来源都有一个权重乘数应用于其分数。所有来源默认权重均为 `1.0`，你可以在 `[memory.search.source_weights]` 下调整其中任何一项：

| 来源 (Source) | 权重 | 描述 |
|--------|--------|-------------|
| `workspace` | 1.0 | 项目特定的长期记忆 |
| `session` | 1.0 | 会话日志 |
| `global` | 1.0 | 跨项目的长期记忆 |

### 时间衰减 (Temporal Decay)

会话记忆会随时间衰减，以便优先考虑较近的会话：

```toml
[memory.search.temporal_decay]
enabled = true           # 启用基于时间的衰减
half_life_days = 7.0     # 在这么多天后分数减半
```

只有会话切片会衰减。全局和工作区记忆会被豁免，因为它们包含的是经过提炼的长期知识。

### 最大边际相关性 (MMR (Maximal Marginal Relevance))

MMR 重新排序会惩罚多余的结果以提高多样性：

```toml
[memory.search.mmr]
enabled = false          # 选择加入的多样性重新排序
lambda = 0.7             # 0.0 = 最大多样性，1.0 = 纯相关性
```

## 命令行工具 (CLI Commands)

`codel memory` 命令用于在终端中管理长期记忆。它有一个子命令 `clear`：

```bash
# 清除工作区长期记忆 (MEMORY.md、sessions/ 以及 index.sqlite)。这是默认作用域。
codel memory clear

# 明确指明相同的作用域
codel memory clear --workspace

# 清除全局 MEMORY.md
codel memory clear --global

# 同时清除工作区和全局的长期记忆
codel memory clear --all

# 跳过确认提示 (-y 是缩写形式)
codel memory clear --yes
```

要在终端中编辑记忆文件，可以直接在你的编辑器中打开它们——例如，`$EDITOR ~/.codel/memory/MEMORY.md`。

## 配置参考 (Configuration Reference)

### 核心设置 (`[memory]`)

| 键名 | 默认值 | 描述 |
|-----|---------|-------------|
| `enabled` | `false` | 启用长期记忆 |
| `session.save_on_end` | `true` | 在会话结束时写入元数据摘要 |
| `watcher.enabled` | `true` | 监听 `~/.codel/memory/` 中的外部修改并重新索引 |

### 索引设置 (`[memory.index]`)

| 键名 | 默认值 | 描述 |
|-----|---------|-------------|
| `max_chunk_chars` | `1600` | 最大切片大小（字符数） |
| `chunk_overlap_chars` | `320` | 切片间重叠字符数 |

### 嵌入设置 (`[memory.embedding]`)

| 键名 | 默认值 | 描述 |
|-----|---------|-------------|
| `provider` | `"api"` | 嵌入提供商 (目前为 `"api"`) |
| `model` | *(提供商默认)* | 嵌入模型名称 |
| `dimensions` | `1024` | 嵌入向量维度 |

### 搜索设置 (`[memory.search]`)

| 键名 | 默认值 | 描述 |
|-----|---------|-------------|
| `max_results` | `6` | 最大搜索结果数 |
| `min_score` | `0.35` | 最低相关性分数 |
| `vector_weight` | `0.7` | 向量相似度权重 |
| `text_weight` | `0.3` | BM25 文本相似度权重 |

### 首次注入设置 (`[memory.initial_injection]`)

| 键名 | 默认值 | 描述 |
|-----|---------|-------------|
| `enabled` | `true` | 启用首轮记忆注入 |
| `min_score` | unset | 首次结果的分数阈值。当未设置时，Codel 不应用任何阈值，等同于 `0.0`。 |

### Dream 设置 (`[memory.dream]`)

| 键名 | 默认值 | 描述 |
|-----|---------|-------------|
| `enabled` | `true` | 启用自动 Dream 整合 |
| `min_hours` | `4` | 两次整合间的最短时间（小时） |
| `min_sessions` | `3` | 自上次整合以来的最少会话数 |
| `stale_lock_secs` | `3600` | 回收过期整合锁之前的等待秒数 |
| `check_interval_secs` | unset | 定期检查时间间隔（秒）。如果未设置，Dream 仅在会话结束时运行。 |

### Flush 设置 (`[compaction.memory_flush]`)

有关 flush 的配置，是在 `[compaction]` 而不是 `[memory]` 下，因为这是与压缩相关的行为。

| 键名 | 默认值 | 描述 |
|-----|---------|-------------|
| `enabled` | `true` | 启用压缩前的记忆 flush 操作 |
| `soft_threshold_tokens` | `4000` | 触发 flush 操作的压缩阈值前预留 Token 数 |
| `max_flush_write_chars` | `8000` | flush 可写入记忆文件的最大字符数 |
| `flush_model` | unset | 用于执行 flush 的模型。如果未设置，Codel 默认使用会话的主模型。 |
| `idle_timeout_secs` | unset | 启动后台 flush 之前的空闲时间（秒）。如果未设置，则只在压缩前触发 flush。 |
| `semantic_dedup_threshold` | unset | 对 flush 产生的内容去重使用的余弦相似度阈值。如果未设置，默认值为 `0.92`。 |

### 修剪设置 (`[compaction.pruning]`)

修剪的配置也在 `[compaction]` 而非 `[memory]` 下。

| 键名 | 默认值 | 描述 |
|-----|---------|-------------|
| `enabled` | `true` | 启用工具运行结果修剪功能 |
| `keep_last_n_turns` | `3` | 从不被修剪的最近回合的数量 |
| `soft_trim_threshold` | `4000` | 字符数超过该阈值时会对过往工具结果进行软裁剪 |
| `soft_trim_head` | `1500` | 在软裁剪结果的开头保留的字符数 |
| `soft_trim_tail` | `1500` | 在软裁剪结果的末尾保留的字符数 |
| `hard_clear_age_turns` | `10` | 超过此回合数年龄的工具运行结果将被替换为占位符 |

## 记忆陈旧性 (Memory Staleness)

当某个会话记录较旧时，Codel 会在搜索结果中附上“过时”提示。较旧的记录会得到较强的提示，以提醒你在依赖它们之前确认当前状态。这有助于你在存储内容可能已不准确时引起注意。全局和工作区记忆从不接收这种过时提示，因为它们包含的是人工梳理的长期知识。

---

## 文件监听器 (File Watcher)

默认情况下，Codel 监听 `~/.codel/memory/` 目录中的外部文件更改。如果你直接编辑了记忆文件（例如在代码编辑器中），所做的更改会在下次进行记忆搜索时自动应用：

- 新建或修改的文件将被重新索引。
- 删除的文件的旧条目将从索引中移除。

```toml
[memory.watcher]
enabled = true    # 默认值
```

## 故障排除 (Troubleshooting)

### 长期记忆失效

1. 确认记忆已开启：检查 `codel inspect` 的输出。
2. 检查启动标志：`codel --experimental-memory` 或 `CODEL_MEMORY=1`。
3. 检查是否有 `--no-memory` 或 `CODEL_MEMORY=0` 覆盖了你的配置文件。

### 记忆没有出现在会话中

长期记忆是在第一轮回合注入的。如果你是在开启记忆功能之前开启的会话，请使用 `/new` 开始一个新会话。

### 查看长期记忆文件

在 TUI 中使用 `/memory` 来预览所有记忆文件。你也可以直接读取：

```bash
ls ~/.codel/memory/
cat ~/.codel/memory/MEMORY.md
$EDITOR ~/.codel/memory/MEMORY.md
```

### 调试日志 (Debug Logging)

```bash
RUST_LOG=debug CODEL_LOG_FILE=/tmp/codel.log codel
grep "memory" /tmp/codel.log
```
