# 沙盒安全环境

沙盒安全环境 (Sandbox mode) 使用操作系统级的内核原语 (Linux 上的 Landlock，macOS 上的 Seatbelt) 限制智使进程及其生成的命令在文件系统和网络上的访问权限。内核在进程生命周期内执行这些限制。

沙盒安全环境默认处于关闭状态。

---

## 快速入门

```bash
# 在 workspace 沙盒模式下运行 (任何地方可读，仅对 CWD + 临时目录 + ~/.codel/ 可写)
codel --sandbox workspace

# 只读模式 (任何地方可读，仅对 ~/.codel/ + 临时目录可写)
codel --sandbox read-only

# 最严格的配置文件 (读取 CWD + 系统路径，写入 CWD + 临时目录 + ~/.codel/，无子进程网络)
codel --sandbox strict
```

## 内置配置文件

| 配置文件              | 文件系统读取       | 文件系统写入                                   | 子进程网络 | 用例                              |
| --------------------- | ------------------ | ---------------------------------------------- | ---------- | --------------------------------- |
| `off` (默认)          | 无限制             | 无限制                                         | 无限制     | 不使用沙盒                        |
| `workspace`           | 任何地方           | CWD + `~/.codel/` + `/tmp` + `/var/tmp`        | 允许       | 正常开发                          |
| `devbox`              | 任何地方           | 所有顶层目录（`/data` 除外）                   | 允许       | 抛弃型开发虚拟机                  |
| `read-only`           | 任何地方           | `~/.codel/` + `/tmp` + `/var/tmp`              | 阻止¹      | 探索、代码审查                    |
| `strict`              | CWD + 系统路径     | CWD + `~/.codel/` + `/tmp` + `/var/tmp`        | 阻止¹      | 不受信任的代码                    |

¹ 子进程网络阻止**仅在 Linux 上**执行 (通过 seccomp)。在 macOS 上它是一个空操作 (no-op) — 这些配置文件不会限制 macOS 上的子进程网络。

若要在某配置文件的基础上阻止特定文件 (如 `.env` 或凭证路径)，请定义一个包含 `deny` 列表的[自定义配置文件](#自定义配置文件) — 它是内核执行的 (读取 + 写入/重命名) 并且支持像 `**/*.pem` 这样的通配符模式。

### 配置文件详情

**workspace** -- 推荐日常开发使用的配置文件。智使可以读取系统上的任何文件 (用于了解依赖项、系统库等) 但只能对当前工作目录 (CWD)、`~/.codel/` 以及临时目录 (`/tmp`, `/var/tmp` 和 macOS 临时目录) 进行写入。允许网络访问以使用诸如 `web_search` 这样的工具和 MCP 服务器。

**devbox** -- 专为抛弃型开发虚拟机预留的内置配置文件。智使可以随处读取并向除 `/data` 及其虚拟文件系统 (`/proc`, `/sys`, `/dev`) 以外的每一个顶层目录 (包括 home 目录) 进行写入。允许网络访问。`--sandbox devbox` 运行内置的配置文件，它将覆盖您在 `sandbox.toml` 中定义的任何 `[profiles.devbox]`。

**read-only** -- 当您想要智使在不修改您的项目文件的情况下分析代码时使用。智使可以读取一切，但只能写入 `~/.codel/` (保留会话所需) 和临时目录。在 Linux 上会阻止子进程的网络访问 (在 macOS 上为空操作)。

**strict** -- 最受限的配置文件，用于审查不受信任的代码。智使只能读取当前工作目录和必要的系统路径内的文件。写入权限被限制在 CWD、`~/.codel/` 和临时目录内。在 Linux 上会阻止子进程的网络访问 (在 macOS 上为空操作)。

### 针对全局钩子的直接写入保护

在 `workspace`, `read-only`, 和 `strict` 下 (以及继承了这些基础的自定义配置文件)，Codel 的状态目录对于会话/运行时文件保持可写，但内核会**写入拒绝 (write-denies)** 用作用户级全局钩子来源的属于 Codel 的直接磁盘路径 (它们保持可读)：

- `~/.codel/hooks/` (钩子目录)
- `~/.codel/hooks-paths` (注册表文件；它不被当作钩子 JSON 进行加载 — 仅加载它的绝对目标路径)
- 在 `hooks-paths` 中列出的绝对目标 (相对路径被忽略；缺失目标将拒绝沙盒启动)

在这些配置文件下首次启动时，当缺少 `hooks/` 目录和 `hooks-paths` 文件时，Codel 会创建真实的空目录及空文件 (绝不创建符号链接或错误的类型)。Claude/Cursor 全局设置**不**受此写入拒绝保护的限制；这些供应商设置的发现单独受限于兼容性设置。

在沙盒启动时，对于符号链接指向 `$CODEL_HOME`，或包含符号链接组件的 `hooks-paths` 条目将被拒绝 (防止重定向)。对于受保护路径的现有父目录，将固定其名称，以免由于重命名其父级而被绕过拒绝策略 (兄弟目录保持可写)。在 Linux 上，在 bubblewrap 内部禁用嵌套的用户命名空间，因此无法重新排列 mount bind。项目的钩子依然受文件夹信任的管控。`devbox` 配置文件不应用此项保护 (因其为抛弃型虚拟机)。需要应用该保护的配置文件在内核策略无法实施时（包括没有经验证的可读 mounts 的 Linux）将拒绝启动。

## 自定义配置文件

可以在 `~/.codel/sandbox.toml` (全局) 或 `.codel/sandbox.toml` (按项目) 中创建自定义沙盒安全环境配置文件：

```toml
[profiles.project]
# 从内置配置文件启动，然后添加覆盖选项
extends = "workspace"
restrict_network = true

# 智使可以读取，但不能写入/删除的路径
read_only = ["/data"]

# 附加的可读写路径
read_write = ["/tmp/scratch"]

# 将被内核拒绝访问的路径或通配符 (读取 + 写入/重命名，强制执行；参见下文说明)
deny = ["/data/shared-secrets", "**/.env", "**/*.pem"]
```

使用自定义配置文件：

```bash
codel --sandbox project
```

自定义配置文件不能重用内置名称。`--sandbox devbox` 始终运行内置的 `devbox` 配置文件，从而屏蔽您定义的任何 `[profiles.devbox]`。

如果用户和项目文件以不同的方式定义了相同的自定义配置文件，Codel 将使用用户配置文件并显示启动警告。运行 `/doctor` 以查看两个文件的位置以及如何解决冲突。如果定义完全一致则不会产生警告。

### 自定义配置文件字段

| 字段               | 类型     | 描述                                                 |
| ------------------ | -------- | ---------------------------------------------------- |
| `extends`          | String   | 要继承的基础内置配置文件 (`workspace`, `devbox`, `read-only`, `strict`)。省略时默认为 `workspace` |
| `restrict_network` | Boolean  | 是否阻止子进程的网络访问                               |
| `read_only`        | String[] | 附加的只读路径                                       |
| `read_write`       | String[] | 附加的读写路径                                       |
| `deny`             | String[] | 将被内核拒绝访问的路径或通配符 (读取 + 写入/重命名；参见说明)。带有 `*`, `?`, 或 `[` 的条目将作为通配符处理 |

> **关于 `deny` 的注意事项：** 非空的 `deny` 列表由**内核强制执行**。被拒绝的路径在 macOS 上通过 Seatbelt，而在 Linux 上通过 bwrap bind-over 遭受**读取拒绝和写入/重命名拒绝**，因此一个被拒绝的路径既不能被读取 (通过 `bash`，`grep`，或分身智使) 也不能被移出拒绝集合后在其他地方被读取 (堵塞了 `mv secret x && cat x` 这样的绕过漏洞)。在 **Linux** 上，读取拒绝需要依赖 `bubblewrap`：如果它缺失 (或任何一条拒绝路径无法进行绑定)，Codel 将宁可拒绝启动，也不会在拒绝访问路径暴露的情况下运行 (仅对其写入拒绝了 `/data` 的 `devbox`，将仍然回退至使用 Landlock)。对于**不在** `deny` 中的路径，其写入操作受限于您在 `read_write` 中的授权。

> **关于 `deny` 中的通配符 (Globs)：** 如果一个条目包含 `*`，`?`，或 `[`，它便是一个**通配符**。这些字符**总是**表示通配符 — 如果想要拒绝名称包含它们的一个文字文件，请命名其父目录。我们支持 gitignore 风格的通配符子集：
>
> - `*` — 一个路径段内的任意字符运行 (在 `/` 处停止)
> - `?` — 一个段内的确切单个字符
> - `**` — 跨目录匹配 (作为一个完整的路径段，例如 `**/`, `a/**`)；`**/` 也匹配零个目录，因此 `**/.env` 可匹配 `.env` 以及 `sub/.env`
> - `[abc]` / `[a-z]` — 字符类；前导的 `!` **或** `^` 表示取反 (`[!a]` 和 `[^a]` 均表示 "非 `a`")
>
> **不**支持大括号交替 (`{a,b}`)、反斜杠转义，以及不同寻常的字符类格式 `[]…]` (将字面量的 `]` 放首位) 和 POSIX `[[:…:]]`，因此，这两个平台绝对不会以不同的方式解释某通配符。使用不支持元字符的，或者是格式错误的通配符，将使得 Codel **在这两个平台上都会拒绝启动** (安全失败策略) — 请将 `*.pem` 和 `*.key` 作为独立条目编写，而不要写成 `*.{pem,key}`。
>
> 相对通配符将被锚定在工作区；绝对通配符 (如 `/home/**/.ssh`) 将被锚定在其文字前缀上。非通配符的条目保持精确路径匹配。强制执行方面，两大平台有所不同：
>
> - **macOS 密不透风：** 每一个通配符都会在运行时变为一条 Seatbelt 正则表达式予以应用，因此那些匹配的文件**即使是在 Codel 启动后才创建的也会被拒绝**。
> - **Linux 尽力而为：** 挂载命名空间 (mount namespace) 无法在运行时解析通配符，所以，每个通配符将会被展开为**在启动时便已存在**的文件且这些文件将被绑定覆盖。**之后**创建并匹配某通配符的文件将**不会**被覆盖 — 在 Linux 系统下，对于任何必须确保密不透风的内容，请指定其确切的路径。如果通配符匹配了太多文件，或是它所在目录树太深或太广导致无法遍历，Codel **将拒绝启动**以避免安全执行上的疏忽。

## 它是如何工作的

沙盒在启动时通过内核原语被应用在**整个 codel 进程上** —— 而不是通过每个命令的包装。这意味着所有的工具操作都被覆盖了：

- `read_file`, `search_replace`, `list_dir` -- 受进程内 Landlock/Seatbelt 限制
- `bash` 命令，`grep` (rg) -- 子进程会自动继承文件系统限制
- 网络 -- 在 Linux 上，可以通过 seccomp 阻止子进程；在 macOS 上这是一个空操作

一旦沙盒被应用，它是**不可逆**的。智使不能在运行时放松限制。

## 恢复会话

开始会话时所使用的配置文件随同会话一同保存，并且**在该会话生命周期内是固定的**。当您恢复它 (`codel --resume <id>`, `codel --continue`, 或 `codel -r`) 时，Codel 将自动恢复同一配置文件 — 所以，如果您在以 `--sandbox workspace` 开始的会话后来在一个具有更严默认限制的环境下重启时，它不会默默地崩溃，那些以前可执行的命令也依然可用。

恢复**不会**改变会话的沙盒安全环境：

- 在恢复时忽略 `--sandbox` 会使用随该会话保存的配置文件。
- 允许传递一个与已保存配置文件**相匹配**的 `--sandbox <profile>` 标志。
- 传递一个与已保存配置文件**不同**的 `--sandbox <profile>` 标志将**因为错误被拒绝** — 改变恢复会话的沙盒是一个具有安全风险的操作 (它可能会放宽原被限制的访问权限，或导致依赖于更广泛访问权限的会话中断)。要想使用不同的配置文件，请开启一个新的会话。

配置文件的加载优先级 (针对**新**会话)：

1. 明确的 `--sandbox <profile>` 标志或 `CODEL_SANDBOX` 环境变量
2. 配置中的 `[sandbox] profile`
3. `off` (无沙盒)

## 平台支持

| 平台  | 机制     | 最低版本             |
| ----- | -------- | -------------------- |
| Linux | Landlock | 内核版本 5.13 或以上 |
| macOS | Seatbelt | macOS (所有版本)     |

如果无法应用沙盒安全环境 (例如，内核不受支持、缺少权限)，Codel 会记录一个警告并在未强制执行的情况下继续运行。一个例外是显式请求的**自定义配置文件**：在 **macOS 和 Linux** 两个平台上，如果无法对其应用配置 (未知的配置文件，格式不正确的 `sandbox.toml`，或者 ——在 Linux 上 —— `bubblewrap` 对于非空 `deny` 列表不可用)，Codel 会拒绝启动，以避免在暴露所拒绝访问的路径的情况下运行。

## 网络限制

在 Linux 上，开启了 `restrict_network` 的配置文件通过 seccomp 阻止**子进程** (bash 命令、脚本) 中的网络访问。在 macOS 上，阻止网络是一个空操作。在进程内发出 HTTP 请求的内置工具 (网络搜索，LLM API 调用) 永远不会受到影响 —— 智使需要网络访问才能运行。

在实践中，这意味着在 Linux 上：

- `web_search`, `web_fetch`, 以及 LLM API 总是拥有网络访问权限
- 在启用了 `restrict_network` 的情况下，类似 `curl`, `wget` 和 `npm install` 等 `bash` 命令将被拦截

## Shell 环境变量策略

沙盒控制子进程可以访问哪些文件和网络。顶层的 `[shell_environment_policy]` 表控制了其继承的环境变量，所以，模型运行的工具命令不能读取正好保存在你 shell 环境里的密钥。

```toml
[shell_environment_policy]
inherit = "core"                 # all (默认) | core | none
ignore_default_excludes = false  # 还要舍弃包含 *KEY* / *SECRET* / *TOKEN* 字段
exclude = ["ACME_*", "CI_*"]     # 舍弃这些名称
include_only = ["PATH", "HOME"]  # 如果设置了此项，仅保留这些名称
set = { MY_FLAG = "1" }          # 强制这些值
```

Codel 按照顺序构建子环境：它从 `inherit` 开始 (`all` 保留所有，`core` 保留一小部分平台设定的变量例如 `PATH` 和 `HOME`，`none` 代表从空开始)；接着舍弃内置机密匹配模式 `*KEY*`, `*SECRET*` 和 `*TOKEN*`，除非设置了 `ignore_default_excludes = true`；随后舍弃所有的 `exclude` 匹配；应用 `set` 中的设定；当 `include_only` 不为空时，将只保留那些匹配的名称。匹配模式属于大小写不敏感的通配符 (`*`, `?`)。

默认情况 (`inherit = "all"`, `ignore_default_excludes = true`) 保持其环境变量未动，因此直到配置策略以前任何东西都不会改变。在非持久性后端上，策略也会过滤自你登录 shell 所捕捉到的那些变量，这样以来通过 `.rc` 文件导出的变量也不可能带着机密逃出 `exclude` 或 `include_only`。例外的是那个持久性的 shell：它也会在基环境中应用策略，但是 `.rc` 文件在登陆期间导出的变量会重播于快照因此未受二次过滤。因此，需把你的机密剔除于 shell 的启动文件以外。此项执行覆盖于 macOS，Linux，和 Windows 上的 bash 工具及终端上。

## 事件日志记录

沙盒事件会被记录到 `~/.codel/sandbox-events.jsonl` 以用于调试。事件包括：

- 配置文件已应用 (哪个配置文件、时间戳)
- 违规 (试图访问被拒绝的路径)

## 何时使用沙盒安全环境

**在以下情况使用 `workspace`：**

- 开发您自己的项目并需要基础的写操作防护时
- 运行于共享环境且需要限定修改的影响范围时

**在以下情况通过 `deny` 列表定义自定义配置文件：**

- 在某一基础配置之上需针对特定的文件 (例如 `.env` 或是凭证路径) 加以防护
- 你不仅需要拦截 `read_file`，还需要内核管控覆盖于 `bash`, `grep`, 和分身智使

**在以下情况使用 `read-only`：**

- 在审查你不信任的代码时
- 探索某代码库又不愿意面临修改它们的危险时
- 在运行代码扫描与检查时

**在以下情况使用 `strict`：**

- 在解析你不受信任的代码和第三方代码时
- 在高度敏于安全的环境下运行时
- 需要隔离性的最大化时

**在以下情况绕过沙盒：**

- 当智使需要去安装一些依赖时 (`npm install`, `pip install`)
- 当智使需要去更改当前工作目录以外的一些文件时
- 若你在受信任的环境当中并想要最大程度上的灵活性

## 权衡考量

| 考量面 | 未使用沙盒               | 使用沙盒                           |
| ------ | ------------------------ | ---------------------------------- |
| 安全性 | 智使拥有对系统的完全访问权 | 智使的访问权受限于配置文件规则 |
| 能力   | 无所不能                 | 受限于配置文件                     |
| 性能   | 几乎没有开销             | 可以忽略的极少开销                 |
| 恢复   | 你必须去信任你的智使     | 取决于操作系统内核设下的边界       |

沙盒是通过对系统原语——通过在 Linux 的 Landlock 或者其命名挂载，以及 macOS 上的 Seatbelt——在操作系统级别进行限制，而非利用了独立的虚拟机去完成限制。
