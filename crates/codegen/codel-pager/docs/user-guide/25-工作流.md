# 工作流 (Workflows)

工作流是 Codel 内置的 Rhai 脚本化动态编排引擎，允许您通过脚本协调多个 Agent 并行或串行执行复杂任务。工作流默认开启，无需额外配置即可使用。

---

## 快速开始

在项目的 `.codel/workflows/` 目录下创建一个 `.rhai` 脚本文件，即可注册为可用工作流：

```bash
mkdir -p .codel/workflows
```

创建一个名为 `review-changes.rhai` 的脚本：

```rhai
let meta = #{
    name: "review-changes",
    description: "审查当前分支的代码变更",
};

phase("分析变更");
let diff = git_diff_since("origin/main");
let analysis = agent("请审查以下代码变更，指出潜在问题：\n" + diff);

phase("生成报告");
let report = agent("基于以下分析结果，生成一份简洁的代码审查报告：\n" + analysis);

complete(report);
```

在 TUI 中启动：

```
/workflow review-changes
```

---

## 启用与配置

工作流默认开启。可通过以下方式控制：

| 方式 | 示例 |
|------|------|
| 环境变量 | `CODEL_WORKFLOWS=0` 禁用 |
| 配置文件 | `~/.codel/config.toml` 中 `[workflows] enabled = false` |

配置优先级（从高到低）：

```
requirement > cli > env > config > managed > feature flag > default(true)
```

此外，远程设置 `workflows_enabled = false` 作为最高优先的熔断开关，会直接关闭工作流。

---

## 脚本存放与发现

引擎按以下顺序扫描工作流脚本：

| 范围 | 路径 | 说明 |
|------|------|------|
| 内置 | 编译时嵌入 | 系统预置工作流 |
| 项目 | `<git-root>/.codel/workflows/` | 仅在项目目录受信任时扫描 |
| 用户 | `~/.codel/workflows/` | 全局个人工作流 |

规则：

- 仅读取非符号链接的 `*.rhai` 常规文件
- 同名时优先级为：内置 > 项目 > 用户（先出现者胜出）
- 同一范围内重名会报 `DuplicateName` 错误
- 文件主文件名必须与 `meta.name` 一致，否则报 `FilenameMismatch`

## 编写工作流脚本

### 元数据声明

脚本的**第一条语句**必须是纯字面量元数据映射：

```rhai
let meta = #{
    name: "my-workflow",        // 必填，kebab-case
    description: "工作流描述",   // 必填
    when_to_use: "适用场景说明", // 可选
    phases: [                    // 可选
        #{ title: "阶段一", detail: "详细说明" },
        #{ title: "阶段二" },
    ],
};
```

`name` 的命名规则：

- 仅含小写 ASCII 字母或数字
- 以字母/数字开头和结尾
- 只允许单个连字符（不能以连字符开头或结尾、不允许 `--`）
- 长度上限 64 字符

### 可用的宿主调用

| 函数 | 说明 |
|------|------|
| `agent(prompt)` | 启动一个子 Agent 执行任务，返回结果 |
| `agent(prompt, opts)` | 带选项启动子 Agent（如指定模型） |
| `parallel(items)` | 并行执行多个 Agent 任务 |
| `phase(title)` | 标记当前阶段（用于进度展示） |
| `log(msg)` | 输出日志信息 |
| `complete(value)` / `complete()` | 标记工作流完成并返回结果 |
| `pause(kind, msg)` | 暂停工作流等待外部操作 |
| `await_user(kind, msg)` | 等待用户输入 |
| `budget()` | 查询当前 Agent 预算使用情况 |
| `render_template(name, vars)` | 渲染模板 |
| `write_scratch_file(name, content)` | 写入临时文件 |
| `read_scratch_file(name)` | 读取临时文件 |
| `git_diff_since(commit)` | 获取自指定提交以来的 diff |
| `fingerprint(text)` | 计算文本指纹 |
| `json_encode(value)` | 将值编码为 JSON 字符串 |

以下函数被**显式禁用**（调用会返回错误）：`timestamp()`、`sleep()`、`exit()`。

### Agent 预算

`agent_budget` 是对逻辑子 Agent 调用的绝对累计上限：

- 每次 `agent()` 调用消耗 1 个名额
- `parallel()` 面板中的每个项目各消耗 1 个名额
- Schema 纠错重试**不消耗**名额
- 超出剩余预算的面板会在任何子任务启动前被拒绝
- 默认值：128，可调范围：1 ~ 1024

### 脚本示例：并行代码审查

```rhai
let meta = #{
    name: "parallel-review",
    description: "并行审查多个模块的代码变更",
};

let args = args; // 外部传入的参数
let modules = args["modules"];

phase("并行审查");
let results = parallel(modules.map(|m| #{
    prompt: "审查模块 " + m + " 的最近变更，关注安全性和性能问题",
}));

phase("汇总");
let summary = agent("汇总以下审查结果，生成统一报告：\n" + json_encode(results));

complete(summary);
```

启动时传入参数：

```
/workflow parallel-review {"modules": ["auth", "api", "database"]}
```

## 启动与管理工作流

### `/workflow` 命令

```
/workflow <名称>                    # 启动工作流
/workflow <名称> {"key": "value"}   # 带参数启动
/workflow pause <名称>              # 暂停
/workflow resume <名称>             # 恢复
/workflow stop <名称>               # 停止
/workflow save <名称>               # 保存脚本
```

多次启动同一工作流会自动追加编号（如 `review-changes`、`review-changes-2`）。

### `/workflows` 仪表板

`/workflows` 打开实时运行仪表板，展示所有活动与保留的运行：

- 每行显示：显示名称、阶段、Agent 列表、进度和结果
- 详情视图中的快捷键：

| 按键 | 操作 |
|------|------|
| `p` | 暂停 |
| `r` | 恢复 |
| `x` | 停止 |
| `s` | 保存脚本 |

---

## 暂停、恢复与预算

- 同进程下的暂停/恢复会基于已提交的宿主调用结果，继续运行原始不可变的脚本
- 如需迭代更新，应编辑返回的脚本副本并作为新运行启动
- 预算受限的运行只能通过提供更高 `agent_budget` 的恢复请求来恢复
- 单纯的 `/workflow resume <name>` 无法提高预算上限
- 因进程重启中断的运行**无法恢复**

## 引擎限额

| 常量 | 值 |
|------|------|
| 工作流名称最大长度 | 64 |
| 描述最大长度 | 1024 |
| 适用场景最大长度 | 2048 |
| 最大阶段数 | 64 |
| 阶段标题最大长度 | 128 |
| 阶段详情最大长度 | 1024 |
| 最大并行数 | 1024 |
| 默认 Agent 预算 | 128 |
| 最大 Agent 预算 | 1024 |
| 最大宿主调用次数 | 10000 |

---

## 脚本校验

引擎提供 `validate_script` API 用于校验脚本：

- 先提取元数据，再以默认预算进行桩宿主空跑
- `Completed` 与 `Paused` 结果视为有效
- `Failed` 则作为校验错误返回
- 引擎限额（如 `MAX_PARALLEL`、Agent 预算）会以空跑失败的形式暴露

---

## 故障排查

| 问题 | 解决方案 |
|------|----------|
| `DuplicateName` 错误 | 同一范围内存在同名脚本，请重命名 |
| `FilenameMismatch` 错误 | 文件名必须与 `meta.name` 一致 |
| 工作流未出现在列表中 | 检查文件是否为 `.rhai` 后缀、是否为符号链接、项目是否受信任 |
| 预算受限无法恢复 | 启动新运行并指定更高的 `agent_budget` |
| 进程重启后运行丢失 | 跨进程中断的运行无法恢复，需重新启动 |
