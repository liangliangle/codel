# 智使模式 (ACP) 与 IDE 集成 (Agent Mode (ACP) and IDE Integration)

智使模式（Agent Mode）作为 ACP（Agent Client Protocol，智能体客户端协议）服务端运行 Codel，以实现与各类 IDE、代码编辑器以及定制工具的集成。与仅发送一次提示后打印响应并退出的单提示模式（`codel -p`）不同，智使模式保持后台常驻进程，并通过结构化的 JSON-RPC 消息进行通信。

---

## 什么是 ACP？ (What is ACP?)

[智能体客户端协议 (ACP, Agent Client Protocol)](https://agentclientprotocol.com) 是一套关于 AI 智能体通信的标准规范。它定义了客户端（IDE、代码编辑器、定制应用程序）应当如何通过结构化的 JSON-RPC 协议与 AI 智能体进行通信。ACP 提供了：

- **会话管理** —— 创建、加载并恢复会话
- **发送提示** —— 发送用户消息并接收流式响应
- **工具调用可见性** —— 实时查看智使正在使用的工具
- **思维流显示** —— 观察智使内部的推理过程
- **权限处理** —— 以交互方式批准或拒绝工具执行操作

---

## stdio 传输机制 (stdio transport)

stdio（标准输入输出）是首要的集成模式。智使进程通过 stdin 和 stdout 交换 JSON-RPC 消息：

```bash
codel agent stdio
```

使用这种模式的客户端包括：

- IDE 扩展（例如 Zed、Neovim 和 Emacs）
- 自定义自动化工具
- ACP 客户端库

### 选项设置 (Options)

这些选项属于 `codel agent` 命令，适用于每种模式。请将它们放在模式名称之前传入，例如 `codel agent --model codel-build stdio`。`stdio` 子命令本身不带任何选项参数。

| 标志                       | 描述                                                       |
| -------------------------- | ---------------------------------------------------------------- |
| `-m, --model <MODEL>`      | 设定所用的大模型 ID (例如 `codel-build`)。                    |
| `--always-approve`         | 自动核准所有的工具调用操作。（同义选项：`--yolo`。）            |
| `--reauth`                 | 在启动智使进程之前重新执行账号认证。                    |
| `--agent-profile <PATH>`   | 从指定文件中加载智使偏好配置文件。                               |

## Server 服务器模式 (Server mode)

将智使作为 WebSocket 服务器运行，以便服务于远程连接过来的客户端：

```bash
codel agent serve --bind 127.0.0.1:2419 --secret <token>
```

客户端通过 WebSocket 发起连接，并使用预设的安全令牌验证身份。如果您未提供 `--secret`，智使端会在启动时生成一个安全令牌并将其打印在终端上；您也可以通过配置环境变量 `CODEL_AGENT_SECRET` 来提供它。智使可以在多次重连中保持活性，因此客户端可以在随时断开后找回正在执行的任务。

---

## WebSocket 中继传输 (WebSocket relay)

如果您不满足于在局域网络环境内使用，并希望通过广域网进行通信访问智使，可以运行 WebSocket 中继服务器（relay server）并让智使主动连接到它：

```bash
codel agent headless --codel-ws-url wss://your-relay.example.com/ws
```

智使进程连接到您专属的中继服务节点，随后您的各类 Web 客户端也能访问同一个中继服务器进行数据传递。这种用法特别适合浏览器无法在本地生成智使进程的各类 Web UI 产品构筑之中。

## ACP 协议基础原理 (ACP protocol basics)

通信体系全盘遵循 JSON-RPC 2.0 数据结构格式。一次典型的会话生命周期包含：

1. **初始化 (Initialize)** —— 客户端发送携带能力清单（capabilities）的 `initialize` 信息
2. **构建会话 (Create session)** —— 客户端发送 `session/new` 及其相应的工作区目录信息
3. **分发提示 (Send prompts)** —— 客户端利用 `session/prompt` 将用户输入的任务交予对方
4. **接收同步状态 (Receive updates)** —— 智使利用 `session/update` 以流形式返回各种更新通知
5. **处理权限管控 (Handle permissions)** —— 智使或许会向你发来执行相关工具操作的确认请求

### 架构示意 (Architecture)

```
+------------------------------------------+
|           ACP Client 客户端               |
|  (IDE、代码编辑器、自定义应用等等)        |
+-------------------+----------------------+
                    | JSON-RPC 基于 stdio 传输
+-------------------v----------------------+
|           codel agent stdio 智使          |
|                                          |
|  +---------+  +---------+  +---------+   |
|  | 会话管理|  | 工具库池|  | MCP 节点|   |
|  | Session |  | Registry|  | Servers |   |
|  +---------+  +---------+  +---------+   |
+------------------------------------------+
```

## 流式更新状态 (Streaming updates)

ACP 返回结构化的流事件状态。每一次下发的 `session/update` 通知都会包含在 `sessionUpdate` 字段中用于标识出该操作涉及的具体操作种类：

| `sessionUpdate` 取值 | 描述                                            |
| --------------------- | ----------------------------------------------------- |
| `agent_message_chunk` | 智使文字内容回应的一处分片块。                 |
| `agent_thought_chunk` | 智使内部思维逻辑流的推理信息分片块。            |
| `tool_call`           | 新发起的一次工具调用申请记录 (包含功能名称，种类，目前状态及参数信息等)。   |
| `tool_call_update`    | 在运行之中的某个工具执行进度状态或最终反馈结果变更消息。 |
| `plan`                | 智使所制定的行事任务计划图。                           |

每一种更新通知事件都明确标记了其属性类别，所以客户端可以清晰划分地渲染相应的不同 UI 面板进行显示操作交互信息，包括推理思绪，工具状态与交互过程的内容反馈。

## 扩展协议方法 (Extension methods)

在基础架构 ACP 协议本身之外，Codel 还在 `codel.dev/` 为前缀名的情况下自定义增设了专门对标专属产品功能层的一些扩充协议。此类扩充具体涵盖：

| 方法大类                   | 前缀名标识               | 具体方法案例                                         |
| -------------------------- | -------------------- | ------------------------------------------------ |
| **文件系统 (Filesystem)**             | `codel.dev/fs/*`          | `list`, `exists`, `read_file`, `write_file`      |
| **Git 功能 (Git)**                    | `codel.dev/git/*`         | `status`, `stage`, `commit`, `diffs`, `discard`  |
| **工作树管理 (Git Worktree)**           | `codel.dev/git/worktree/*`| `create`, `remove`, `apply`, `list`, `gc`        |
| **检索查询 (Search)**                 | `codel.dev/search/*`      | `fuzzy/open`, `fuzzy/change`, `content`          |
| **终端操作 (Terminal)**               | `codel.dev/terminal/*`    | `create`, `kill`, `output`, `wait_for_exit`      |
| **会话状态管理 (Session Management)**     | `codel.dev/session/*`     | `fork`, `resolve_local_for_worktree_resume`      |
| **历史追溯 (Conversation & History)** | `codel.dev/*`             | `prompt_history`, `rewind/*`, `compact_conversation` |
| **认证管理 (Authentication)**         | `codel.dev/auth/*`        | `get_url`, `submit_code`                         |

表单仅仅展示了目前涉及大类的几个具有代表性质的具体案例调用名称。归于 `codel.dev/*` 之中的所有特定接口都会根据后续产品推演继续升级变更多种能力拓展，在使用之中应以其 `initialize` 中接收反馈下发到的当前具体开放函数为主以获取详细列表。

### 通知 (智使到客户端的消息推送) (Notifications: agent to client)

智使向客户端发送实时状态更新推送：

| 通知名称 (Notification)               | 描述说明                          |
| -------------------------- | ------------------------------------ |
| `codel.dev/search/fuzzy/status` | 模糊搜索运行过程结果更新          |
| `codel.dev/git/worktree/status` | 工作区创建加载状态与结果           |
| `codel.dev/fs_notify`           | 文件系统变更状态感知更新       |
| `codel.dev/fs/index`            | 全盘文件的完整索引数据树       |
| `codel.dev/fs/index/delta`      | 带有部分更新状态的增量索引数据       |
| `codel.dev/session_notification`| 一部分属于会话自身特供的信息 (比对分析反馈、回退数据信息、重连保存与自优化状态) |
| `codel.dev/session/update`      | 传统会话更新消息 (工具呼叫进展状态，交流语篇文本) |

## 设立 `_meta` 高阶配置对象参数 (Session `_meta` options)

发送建立请求的 `session/new` 对象内部也包含下面这几个可选加入的 `_meta` 关键性拓展功能点：

| 内部字段 (Field)                  | 描述说明                                    |
| ---------------------- | ---------------------------------------------- |
| `rules`                | 后插于基本系统设定之后加入额外的自定义限制守则等。     |
| `systemPromptOverride` | 全面强行替换的系统核心层角色定制提示语。                   |
| `agentProfile`         | 某一类配置文件对象的字符串描述名字或者整个定制功能的 JSON 数据对象等形式。  |

## 集成实践：使用 TypeScript 建立 ACP 客户端 (Integration example: a TypeScript ACP client)

```typescript
import { spawn, ChildProcess } from "child_process";
import * as readline from "readline";

class CodelACPChat {
  private proc!: ChildProcess;
  private sessionId!: string;
  private rl!: readline.Interface;

  constructor(private cwd = ".") {}

  async init() {
    this.proc = spawn("codel", ["agent", "stdio"]);
    this.rl = readline.createInterface({ input: this.proc.stdout! });

    // Initialize
    await this.request("initialize", {
      protocolVersion: 1,
      clientCapabilities: {
        fs: { readTextFile: true, writeTextFile: true },
        terminal: true,
      },
    });

    // Create session
    const { sessionId } = await this.request("session/new", {
      cwd: this.cwd,
      mcpServers: [],
    });
    this.sessionId = sessionId;
    return this;
  }

  private async request(method: string, params: any): Promise<any> {
    return new Promise((resolve) => {
      const msg = JSON.stringify({ jsonrpc: "2.0", id: 1, method, params });
      this.proc.stdin!.write(msg + "\n");

      this.rl.once("line", (line) => {
        resolve(JSON.parse(line).result || {});
      });
    });
  }

  async *streamPrompt(text: string) {
    const msg = JSON.stringify({
      jsonrpc: "2.0",
      id: 1,
      method: "session/prompt",
      params: {
        sessionId: this.sessionId,
        prompt: [{ type: "text", text }],
      },
    });
    this.proc.stdin!.write(msg + "\n");

    for await (const line of this.rl) {
      const data = JSON.parse(line);

      if (data.method === "session/update") {
        const update = data.params.update;
        yield update; // { sessionUpdate, content, title, ... }
      } else if (data.result) {
        break; // Final response
      }
    }
  }
}

// Usage
const client = await new CodelACPChat(".").init();

for await (const update of client.streamPrompt("List the files in this project")) {
  switch (update.sessionUpdate) {
    case "agent_message_chunk":
      process.stdout.write(update.content?.text || "");
      break;
    case "agent_thought_chunk":
      console.log(`\n[Thinking: ${update.content?.text}]`);
      break;
    case "tool_call":
      console.log(`\n[Tool: ${update.title}]`);
      break;
  }
}
```
