# 插件系统（Plugins）

插件将技能扩展（Skills）、斜杠指令（Slash commands）、Agent 定义、生命周期钩子（Hooks）、MCP 服务器配置和 LSP 服务器配置打包为一个可安装的独立单元。

---

## 插件包含的内容

插件是一个目录，可以包含以下任意组件的组合：

- **技能扩展（Skills）** -- 包含 SKILL.md 文件的 `skills/` 目录
- **斜杠指令（Slash commands）** -- 包含指令文件的 `commands/` 目录
- **Agent 定义** -- 包含 Agent 定义的 `agents/` 目录
- **钩子（Hooks）** -- 包含生命周期钩子的 `hooks/hooks.json` 文件。插件钩子还会接收 `CODEL_PLUGIN_ROOT` 和 `CODEL_PLUGIN_DATA` 环境变量（参阅[钩子机制指南](10-钩子机制.md)获取传递给钩子的完整环境变量列表）。
- **MCP 服务器** -- 包含服务器配置的 `.mcp.json` 文件
- **LSP 服务器** -- 包含语言服务器配置的 `.lsp.json` 文件

如果插件包含 `plugin.json` 清单文件，该清单可以覆盖路径或添加元数据；否则组件将从约定目录加载。清单文件是可选的：即使没有清单文件，Codel 也会从标准目录中发现上述组件。

例如，一个 `team-tools` 插件可能包含部署技能扩展、代码审查 Agent、提交前 Hooks 和 Linear MCP 服务器。你可以通过一个步骤将它们统一安装。

## 插件 Hook 钩子中的环境变量

除了为每个 Hook 钩子设置的标准环境变量外，插件 Hook 还会接收两个额外的环境变量：

| 变量名 | 描述 |
|----------------------|-------------|
| `CODEL_PLUGIN_ROOT` | 插件安装目录的绝对路径。 |
| `CODEL_PLUGIN_DATA` | 插件可写数据目录的绝对路径，用于存储插件状态、缓存和日志。 |

Codel 会自动设置这些值，并覆盖你在 Hook JSON 的 `env` 映射中为相同 key 声明的任何值。（为了实现兼容性，Codel 还会设置 `CLAUDE_PLUGIN_ROOT` 和 `CLAUDE_PLUGIN_DATA` 别名。）参阅[钩子机制指南](10-钩子机制.md)获取传递给钩子的所有环境变量。

## 插件存放位置

Codel 按以下优先级顺序从这些位置发现插件：

| 位置 | 作用域 | 信任机制 |
|----------|-------|----------|
| `_meta.pluginDirs` (`session/new` / `session/load`) | 会话级 -- 仅为该会话加载 | 自动受信任 |
| `--plugin-dir` (CLI 标志, `codel agent`) | 进程级 -- 仅为该 Agent 进程加载 | 自动受信任 |
| `.codel/plugins/` | 项目级 -- 通过版本控制与团队共享 | 需要显示信任 |
| `~/.codel/plugins/` | 用户级 -- 适用于所有项目的个人插件 | 自动受信任 |
| `[plugins].paths` (配置文件) | 在 `config.toml` 中添加的自定义目录 | 取决于具体位置 |

为了兼容性，Codel 也会读取对应的 `.claude/plugins/` 目录。当两个插件重名时，较高优先级的存储位置生效。

Agent SDK 通过 `CodelOptions.plugins` 加载每个会话的插件，在 `session/new` 和 `session/load` 时作为 `_meta.pluginDirs` 送达；由于调用者控制了目录，这些插件始终是自动受信任的 -- 其 Hooks 和 MCP 服务器无需提示即可直接激活，且绝不会在会话结束后继续持久化。`--plugin-dir` 标志是面向直接 CLI 使用的进程级等效项（可多次重复使用：`codel agent --no-leader --plugin-dir A --plugin-dir B stdio`）；它仅适用于专用 Agent 进程，在 Leader 模式下会被忽略（共享的 Leader 会自行发现其插件）。

## 在 TUI 中管理插件

### 打开模态框

| 操作方式 | 打开页面 |
|--------|-------|
| `Ctrl+L`（在任意面板中；**仅限非 VS Code 系列**） | Plugins 标签页 |
| `/plugins`（任意终端；**VS Code 系列必须使用**） | Plugins 标签页 |

该模态框包含五个标签页：**Hooks**、**Plugins**、**Marketplace**、**Skills** 和 **MCP Servers**。使用 `Tab`（向前）或 `Shift+Tab`（向后）切换标签页。`/hooks`、`/marketplace`、`/skills` 和 `/mcps` 指令分别会在对应的标签页上打开该模态框。

### Plugins 标签页

按 `Enter` 展开插件行并显示其详细信息：

- **名称** 与 **版本号**
- **作用域** -- `cli`、`project`、`user`、`custom path` 或插件市场来源名称
- **技能扩展** -- 名称或数量
- **Agent** -- 名称或数量
- **Hooks** -- 数量
- **MCP 服务器** -- 数量（在插件不受信任时显示为 `blocked`）
- **描述** 与 **路径**

在 Plugins 标签页中使用以下快捷键：

| 按键 | 操作 |
|-----|--------|
| `r` | 重新加载所有插件 |
| `a` | 从 `owner/repo`、URL 或本地路径添加插件 |
| `Space` | 启用或禁用选中的插件 |
| `x` | 卸载选中的插件（会要求确认） |
| `f` | 按状态过滤（全部、已启用或已禁用） |
| `Enter` | 展开或折叠插件详情 |
| `/` | 按名称搜索插件 |

卸载操作会要求确认：按小写 `y` 确认，按其他任何键（包括 `Esc`）取消。

### Marketplace 标签页

浏览并安装来自于已配置的插件市场来源中的插件。

在 Marketplace 标签页中使用以下快捷键：

| 按键 | 操作 |
|-----|--------|
| `i` | 安装选中的插件 |
| `d` | 卸载选中的插件（会要求确认） |
| `a` | 添加插件市场来源 |
| `x` | 移除选中的来源及其所有插件（会要求确认） |
| `r` | 刷新插件市场来源 |
| `u` | 更新选中的插件市场插件 |
| `Enter` | 展开或折叠来源或插件 |
| `/` | 按名称搜索插件 |

列表行上的组件摘要以及展开视图中按类别划分的组件详情仅在使用发布了 `plugin-index.json` 目录的插件市场时才会显示。

## CLI 命令行操作

无需启动交互式会话即可管理插件。

### 插件管理指令

```bash
codel plugin list [--json] [--available]   # 列出已安装的插件 (--available 需要配合 --json)
codel plugin install <source> --trust      # Git URL、GitHub 简写 (user/repo) 或本地路径
codel plugin uninstall <name> [--confirm] [--keep-data]   # 别名: rm, remove
codel plugin update [<name>]               # 省略名称将更新所有插件
codel plugin enable <name>
codel plugin disable <name>
codel plugin details <name>                # 展示插件的组件清单
codel plugin validate [<path>]             # 校验 plugin.json (默认: 当前目录)
codel plugin tag [<path>] [--push] [--force] [--dry-run]   # 从清单版本打发布标签
```

运行不带 `--trust` 的 `codel plugin install <source>` 时，Codel 会打印来源并警告安装将激活该插件的 Hooks、MCP 服务器与技能扩展，然后终止且不进行安装。添加 `--trust` 参数以完成安装。

`<source>` 参数接收：

- `user/repo` -- GitHub 简写
- `user/repo@v1.0` -- 锚定到某个 Git Ref
- `user/repo@<commit-sha>` -- 锚定到精准的 Commit SHA（获取后校验）
- `user/repo#subdir` -- 仓库中的子目录
- `https://github.com/user/repo.git` -- 完整 URL
- `git@github.com:user/repo.git` -- SSH
- `./local-dir` 或 `/absolute/path` -- 本地目录

### 要求 Commit SHA 锁定 (`require_sha`)

远程插件未经密码学签名：追溯某个分支或 Tag 的安装意味着明天可能会运行该 Ref 指向的任何内容。运维人员可以要求所有远程安装和更新必须锚定完整的 Commit SHA（40 或 64 位的十六进制，且在获取检出后进行校验）：

```toml
# config.toml
[marketplace]
require_sha = true
```

或设置 `CODEL_MARKETPLACE_REQUIRE_SHA=1`。两者均只能收紧策略：任一方式均可启用该策略，且均无法将其切回关闭状态。在策略开启的情况下，未锚定 SHA 的远程安装、未发布 `sha` 的插件市场安装以及追溯分支的更新均将被拒绝。

作用域：该策略涵盖在安装或更新时从远程 Git URL 获取的所有内容。包含在插件市场来源内部的 Vendor 插件是从该来源已同步的检出中复制的，不在涵盖范围内 -- 请通过在 `plugin-index.json` 中发布 `sha` 条目来锁定你的插件市场来源内容。

### 插件市场指令

```bash
codel plugin marketplace list [--json]
codel plugin marketplace add <url>         # Git URL、GitHub 简写 (user/repo) 或本地路径
codel plugin marketplace remove <url>      # 已配置来源的 Git URL 或本地路径
codel plugin marketplace update [<name>]   # 省略名称将刷新所有来源
```

### 示例：搭建团队插件市场

```bash
codel plugin marketplace add my-org/team-plugins
codel plugin marketplace list
codel plugin install my-org/team-plugins --trust
codel plugin list
codel plugin update
```

## 系统配置

在 `~/.codel/config.toml` 中配置插件目录与单个插件状态：

```toml
[plugins]
paths = ["~/my-plugins/custom-tools"]        # 额外的插件目录
disabled = ["user/a1b2c3d4/noisy-plugin"]    # 跳过加载的插件 ID 或名称
enabled = ["project/9f8e7d6c/team-tools"]    # 强制开启的插件 ID 或名称
```

在 `disabled` 中列出某个插件可以对其进行发现，但跳过加载其组件。在 `enabled` 中列出某个插件可将其激活 -- 插件默认处于禁用状态，除非通过 CLI 覆盖或显式配置路径启用，因此在此处添加可将其开启。每个条目可以是普通插件名称（如 `codel plugin list` 中所示），或者是格式为 `<scope>/<hash>/<name>` 的完整插件 ID。

### 隐藏插件 UI

若要隐藏 Hooks 和 Plugins UI -- 包括 `/hooks` 与 `/plugins` 指令以及滚动历史注解 -- 请在 `~/.codel/pager.toml` 中进行如下设置：

```toml
disable_plugins = true
```

## 插件市场来源

添加 Git 或本地插件市场来源以发现和安装插件。

### 在 config.toml 中

每个来源需要一个 `name` 属性，以及一个 `git` URL（带可选的 `branch`）或本地 `path`：

```toml
[[marketplace.sources]]
name = "My Team Plugins"
git = "https://github.com/my-org/plugins.git"

[[marketplace.sources]]
name = "Local Dev"
path = "~/dev/my-plugins"
```

### 在 settings.json 中

在 `extraKnownMarketplaces` 下添加来源，以名称为 key。每个条目的 `source` 为 `git`（带 `url`）、`github`（带 `repo`）或 `local`（带 `path`）之一：

```json
{
  "extraKnownMarketplaces": {
    "my-marketplace": {
      "source": { "source": "git", "url": "git@github.com:my-org/plugins.git" }
    }
  }
}
```

将此文件放置在 `~/.codel/settings.json` 或 `~/.claude/settings.json`。

## 信任模型（Trust Model）

启用插件会加载其技能扩展、斜杠指令与 Agent 定义。信任机制是相互独立的，负责控制插件的代码是否能够运行：即使对于已启用的插件，在其获得信任之前，其 Hooks、MCP 服务器与 LSP 服务器均保持未激活状态。这可以防止未经信任的仓库在你的机器上运行代码。

Codel 自动信任来自于 `~/.codel/plugins/` 的插件。`.codel/plugins/` 中的项目级插件需要显式授权信任。若要信任某个插件，请使用 `--trust` 参数进行安装：

```bash
codel plugin install <source> --trust
```

## 检查插件状态

运行 `codel inspect` 以查看发现的每个插件及其提供的组件：

```bash
codel inspect          # 显示插件及其技能扩展、Agent、Hooks 和 MCP 服务器
codel inspect --json   # 输出机器可读的 JSON
```

插件提供的组件在其对应的部分（Skills、Agents、MCP Servers 等）中带着 `plugin: <name>` 标签出现，以便你能清晰识别每个组件的来源。

## 通用快捷键说明

这些按键在模态框的所有标签页中均可正常使用：

| 按键 | 操作 |
|-----|--------|
| `Tab` | 下一个标签页 |
| `Shift+Tab` | 上一个标签页 |
