# 主题与外观定制

Codel Build 将所有 TUI 界面颜色统一由中央主题管理。你可以在 Codel 运行时随时切换主题、跟随操作系统的浅色或深色外观，并可通过配置文件调整滚动历史布局、动画及文本块样式。

---

## 可用主题

Codel 内置了 5 款主题，此外还包含一个可随系统外观自动切换的 `auto` 选项：

| 主题 | 配置名称 | 描述 | 是否要求真彩 (Truecolor) |
|-------|-------------|-------------|--------------------|
| **CodelNight** | `codelnight`, `codel-night`, `dark` | 中性深色底色搭配品红（Magenta）强调色。默认主题。在 256 色和 16 色终端上能完美量化渲染。 | 否 |
| **CodelDay** | `codelday`, `codel-day`, `light`, `day` | 适用于明亮终端背景的浅色主题。 | 否 |
| **TokyoNight** | `tokyonight`, `tokyo-night`, `tokyo` | 来自 Tokyo Night 色板的深蓝调背景。量化降级后会失去原有特色。 | 是 |
| **RosePineMoon** | `rosepine`, `rose-pine`, `rosepine-moon`, `rose-pine-moon` | 柔和的深色色板搭配淡紫（Mauve）强调色，源自 Rosé Pine 家族。 | 是 |
| **OscuraMidnight** | `oscura`, `oscura-midnight` | 深邃暗色底色搭配紫色强调色。 | 是 |

主题名称不区分大小写。`auto` 选项（别名 `system`）在[自动主题（系统外观）](#自动主题系统外观)一节中有详细说明。

### 极简模式无主题设定

**极简模式**（`--minimal`）始终使用单一固定的终端原生色板渲染，并完全忽略 `theme` 设置（这些设置仅作用于完整 TUI 界面）。极简模式直接绘制在终端自身的背景上，因此使用你终端的默认前景色/背景色及其 16 色 ANSI 色板 —— 与 `git` 或 `ls` 使用的颜色一致 —— 无需检测或配置即可在任何浅色或深色终端配置文件上保持清晰可读。极简模式下无法使用 `/theme` 命令及 `/settings` 中的主题配置项。

极简模式下的语法高亮**不会**在浅色和深色主题文件之间切换（故意避免极性检测）。接近灰色的 Token 继承终端默认前景色；有颜色的 Token 使用基础 ANSI 强调色（红/绿/黄/蓝/品红/青），使文件读取输出和围栏代码块在浅色和深色配置文件上均保持清晰易读。

## 切换主题

### 在 TUI 界面中

运行 `/theme` 斜杠指令（别名 `/t`）以打开主题选择器。当你在列表中使用方向键移动时，Codel 会实时预览每个主题。按 Enter 确定并保存你的选择，按 Escape 取消并恢复原样。

若无需选择器直接切换，可直接传入主题名称：

```
/theme tokyonight
```

单独提交 `/theme` 指令（不从选择器中挑选）会自动循环切换到下一个主题。

### 通过配置文件

在 `~/.codel/config.toml` 中设置主题：

```toml
[ui]
theme = "tokyonight"
```

## 自动主题（系统外观）

设置 `theme = "auto"` 可使 Codel 遵循操作系统的浅色/深色外观并自动切换主题：

```toml
[ui]
theme = "auto"
```

默认情况下，深色模式映射到 **CodelNight**，浅色模式映射到 **CodelDay**。可以通过 `auto_dark_theme` 与 `auto_light_theme` 覆盖映射：

```toml
[ui]
theme = "auto"
auto_dark_theme = "tokyonight"
auto_light_theme = "codelday"
```

`theme = "system"` 是 `theme = "auto"` 的别名。

### 自动检测工作原理

| 平台 | 方法 |
|----------|--------|
| **macOS** | 读取 `AppleInterfaceStyle` 系统偏好设置 |
| **Linux** | 查询 XDG Desktop Portal (`org.freedesktop.appearance.color-scheme`) |
| **Windows** | 读取系统个性化注册表 |
| **SSH / 无头环境** | 在启动时退回到 OSC 11 终端背景色查询 |

启动后，Codel 每 5 秒轮询一次外观变化。在 OS 中切换浅色与深色模式会在数秒内生效，无需重启。

### 通过设置面板配置

运行 `/settings`（别名 `/config`）并打开 **Appearance** 分类，以交互方式设置 **Auto dark theme** 和 **Auto light theme**。在 `/theme` 选择器中选择 `auto` 会启用基于这些映射的自动模式。

## 颜色支持检测

启动时，Codel 会自动检测你终端的色彩支持级别：

| 级别 | 描述 | 检测依据 |
|-------|-------------|-----------|
| **真彩 (Truecolor)** (24-bit) | 完整 RGB 色彩。所有主题按原设计完美渲染。 | `COLORTERM=truecolor` 或同等终端能力 |
| **256 色** | 索引色板。RGB 值被映射到最接近的色板条目。 | 标准 xterm-256color |
| **16 色** | 仅 ANSI 名称。颜色被映射到最接近的 ANSI 颜色。 | 基础终端支持 |

当设置 `NO_COLOR` 时，Codel 不输出任何颜色，并以单色模式渲染。

运行 `/doctor` 可以查看此终端检测到的色彩级别以及可用主题。如果真彩不可用，Doctor 会展示相关的设置步骤或解释终端限制。

### 自动颜色量化

每个主题都是使用完整的 RGB 值定义的。在启动时，Codel 会量化所有颜色以匹配检测到的能力级别。这意味着：

- 在 **真彩 (Truecolor)** 终端上，颜色保持原样透传。
- 在 **256 色** 终端上，每个 RGB 值都被映射到最接近的索引色板条目。
- 在 **16 色** 终端上，颜色映射到 ANSI 名称。

CodelNight 和 CodelDay 使用中性灰色，可以完美量化。TokyoNight、RosePineMoon 和 OscuraMidnight 使用独特的带色彩倾向的背景，量化后会失去原有特色，这就是为什么主题选择器会在非真彩终端上隐藏它们的原因。

### 运行时生成的颜色

运行时生成的颜色（如语法高亮、背景混合色）也会通过相同的管线进行量化，从而确保在所有终端类型上具有一致的外观展示。

## 光标颜色

Codel 使用 OSC 12 转义序列将你终端的光标颜色设置为当前主题的 `accent_user` 颜色，以指示当前处于活跃的 Codel 会话中。光标颜色：

- 在启动和切换主题时应用。
- 在退出时通过 OSC 112 重置为终端默认颜色。

这在支持 OSC 12 的终端中有效（大多数现代终端均支持）。

## 紧凑模式（Compact Mode）

使用 `/compact-mode` 斜杠指令切换紧凑模式。紧凑模式：

- 移除外部垂直边距（顶部/底部边距变为 0）。
- 将水平边距缩减至最小（1 列）。
- 减少 Prompt 区域和信息块顶部的边距。

该设置持久化在 `~/.codel/config.toml` 的 `[ui].compact_mode` 中，重启后仍然保留。

在小屏幕上使用紧凑模式可以最大化内容显示区域。

---

## 语法高亮

Codel 内置了三个 `.tmTheme` 文件用于代码块语法高亮，并根据当前激活的主题自动挑选：

- `codel-night.tmTheme` -- CodelNight, RosePineMoon, 和 OscuraMidnight
- `codel-day.tmTheme` -- CodelDay
- `tokyo-night.tmTheme` -- TokyoNight

当你切换主题时，Codel 会自动挑选匹配的文件。`.tmTheme` 文件已被内置在二进制文件中，因此无法替换为你自己的文件。

## 使用 pager.toml 进行深度定制

若需对 TUI 外观进行精细控制，可创建 `~/.codel/pager.toml`。该文件控制滚动历史布局、区块样式、动画等。所有设置均有默认值；仅需指定你要覆盖的值。（Dev 构建版本会将此文件作为模板生成，其中每个默认值均被注释 —— 取消注释某行即可覆盖它；被注释的值将继续跟随未来的默认值。）

### 布局配置

控制视口边距和区块间距：

```toml
[scrollback.layout]
outer_vpad = 1          # 视口垂直边距（顶部/底部）
outer_hpad_left = 2     # 左边距（最小：1）
outer_hpad_right = 2    # 右边距（最小：1）
block_pad_left = 2      # 强调线与内容之间的边距
block_pad_right = 2     # 右侧边缘内容后的边距
```

### 滚动条配置

```toml
[scrollback.scrollbar]
enabled = true          # 显示/隐藏滚动条
gap_left = 0            # 内容与滚动条之间的间隙（0 = 紧邻）
gap_right = 0           # 滚动条与屏幕边缘之间的间隙（0 = 贴边）
# scrollbar_bg = "none" # 覆盖背景颜色（或 "none" 使用主题默认）
# scrollbar_fg = "none" # 覆盖滑块颜色（或 "none" 使用主题默认）
```

### 滚动行为

```toml
[scrollback.scroll]
margin = 0                  # 选中项上方/下方的上下文行数（0 = 贴边）
min_page_fraction = 0       # 最小滚动占视口的百分比 (0-100)
follow_indicator = "center" # "center" = 显示向下箭头，"none" = 隐藏
follow_auto_select = true   # 跟随模式下自动选择最新的条目
follow_by_overscroll = true # 滚动超过底部时自动进入跟随模式
anchor_on_fold = true       # 折叠时将区块标头保持在屏幕相同位置
```

### 显示选项

```toml
[scrollback.display]
sticky_headers = true              # 向上滚动时将用户 Prompt 作为标头固定在顶部
tab_width = 4                      # 每个 Tab 字符占用的空格数 (0 = 原样透传)
expandable_indicator = true        # 在可折叠已收起的条目上显示 "›"
expandable_indicator_char = "›"    # 使用的指示符字符 (默认: "›")
collapsed_accent_char = "❙"        # 已折叠的分组区块的强调字符 (在旧版 Windows 控制台上退回到 "|")
dim_accent = 0.5                   # 暗淡强调色的混合因子 (0.0-1.0)
line_under_last_entry = false      # 最后一条记录下方的水平线
selection_buttons = false          # 在选择框上显示复制/查看按钮
```

### 动画配置

```toml
[animation]
fps = 30           # 帧率 (1-60)。更高 = 更流畅，但消耗更多 CPU
wave_rows = 32     # 强调动画每个波浪周期的行数
```

### 区块样式：编辑 Diff 块

```toml
[scrollback.blocks.edit]
indent = true                   # 缩进 diff 内容
vpad = false                    # diff 周围的垂直边距
# expanded_by_default = true    # 未设置：继承 config.toml 中的 [ui] collapsed_edit_blocks
                                # (标志开启 = 折叠为单行); 取消注释以固定任意一种形态
hunk_separator = "…"            # diff 块之间的分隔符 ("…", "───", "⋯", 或 "" 表示无分隔)
dual_line_numbers = false       # 双列行号 (旧 + 新，类似 GitHub)
# line_summary = false          # 在折叠标头中显示 +N/-M；未设置时继承相同标志
# bg = "none"                   # 区块背景 ("none", "light", "dark")
```

### 区块样式：思考与推理过程

```toml
[scrollback.blocks.thinking]
accent_enabled = true       # 为思考块显示强调线
animate = true              # 思考时动态显示强调线
truncated_lines = 3         # 截断模式下显示的行数
bg_blend = 70               # Markdown 颜色与背景的混合比例 (0-100)
header = true               # 显示 "Thinking..." 标头
header_bright = false       # 亮色标头样式 (对比暗淡/柔和样式)
```

### 区块样式：工具调用

```toml
[scrollback.blocks.tool]
muted_collapsed = true     # 将折叠的工具调用变灰
dim_details = true          # 暗淡显示括号内的详细信息 (行数、匹配数)
bullet = "diamond"          # 工具标头前的项目符号样式
```

可选的项目符号样式：

| 配置值 | 字符 | 描述 |
|-------------|-----------|-------------|
| `none` | (无) | 无项目符号 |
| `dot` | `·` | 中点 (最小) |
| `small-circle` | `•` | 实心圆点 |
| `circle` | `●` | 大实心圆 |
| `small-triangle` | `▸` | 右向小三角 |
| `triangle` | `▶` | 右向三角 |
| `diamond` | `◆` | 实心菱形 (默认) |

### 区块样式：Execute（Shell 命令）

```toml
[scrollback.blocks.execute]
first_lines = 2                   # 截断模式下开头显示的输出行数
last_lines = 3                    # 截断模式下结尾显示的输出行数
accent_enabled = true             # 显示强调线 (运行时带动态效果)
header_style = "label"            # "shell" ($ 前缀) 或 "label" (Run 前缀)
muted_command_collapsed = true    # 折叠时淡化命令文本
```

### 区块样式：用户 Prompt（滚动历史中）

```toml
[scrollback.blocks.prompt]
vpad = true            # 垂直边距
bg = "light"           # 背景 ("none", "light", "dark")
show_prefix = true     # 显示 Prompt 前缀字符
min_lines = 2          # 截断/固定模式下的最小内容行数
```

### Prompt 输入组件

```toml
[prompt]
collapse_unfocused = true    # 当焦点在滚动历史时折叠 Prompt
mouse_hover = true           # 鼠标悬停时显示高亮
show_prefix = true           # 显示 Prompt 前缀字符
```

### Todo 待办事项徽章

```toml
[todo]
badge_format = "default"   # "default" = 2/5 (已完成/总数), "colon" = [▶:1 □:4 ✓:3 ✗:2], "comma" = [1 ▶, 4 □, 3 ✓, 2 ✗]
```

### 终端行为

```toml
[terminal]
alt_screen = "auto"    # "auto", "always" 或 "never"
```

切屏策略说明：
- `auto` -- 在普通终端和标准 tmux 中全屏；在 tmux 控制模式和 Zellij 中内联。
- `always` -- 始终进入全屏。
- `never` -- 绝不进入全屏；在主滚动历史中内联运行。

### 插件 UI

```toml
disable_plugins = false   # 设置为 true 以隐藏 /hooks、/plugins 命令和注解
```

## 主题颜色槽位（Color Slots）

每个主题都定义了以下在整个 TUI 中使用的颜色槽位：

**背景色：** `bg_base`, `bg_light`, `bg_dark`, `bg_highlight`, `bg_hover`, `bg_terminal`, `bg_visual`

**强调色：** `accent_user`, `accent_assistant`, `accent_thinking`, `accent_tool`, `accent_system`, `accent_error`, `accent_success`, `accent_running`, `accent_skill`, `accent_plan`, `accent_verify`, `accent_feedback`, `accent_remember`, `accent_model`

**文本色：** `text_primary`, `text_secondary`

**灰色调：** `gray_dim`, `gray`, `gray_bright`

**语义色：** `command`, `path`, `running`, `warning`, `fuzzy_accent`

**边框与滚动条：** `selection_border`, `hover_border`, `prompt_border`, `prompt_border_active`, `scrollbar_bg`, `scrollbar_fg`

**粘贴内容：** `paste_bg`, `paste_fg`, `paste_dim`

**Diff 对比：** `diff_delete_bg`, `diff_delete_fg`, `diff_insert_bg`, `diff_insert_fg`, `diff_equal_fg`, `diff_gutter_fg`

**Markdown：** 标题颜色 (`md_heading_h1`-`md_heading_h6`), `md_code`, `md_code_bg`, `md_text`, `md_muted`, `md_task_checked`, `md_task_unchecked`, `link_fg`

主题系统在内部管理这些槽位，并为你使用的终端自动进行色彩量化。
