# 系统配置

Codel 从配置文件、环境变量和 CLI 命令行标志中读取设置。本页面涵盖常见配置选项。

---

## 优先级

配置设置按以下优先级解析（从高到低）：

1. **CLI 命令行标志**（例如 `--yolo`、`--model`、`--sandbox`）
2. **环境变量**（例如 `CODEL_API_KEY`、`CODEL_MEMORY`）
3. **config.toml** (`~/.codel/config.toml`)
4. **托管/要求配置**（你的组织部署的文件，例如 `managed_config.toml` / `requirements.toml`）
5. **内置默认值**

---

## config.toml（主配置文件）

位置：`~/.codel/config.toml`。若该文件不存在，Codel 将使用其内置默认值，因此你只需要设置想要覆盖的值。

### 通用配置

```toml
[cli]
auto_update = true                     # 启动时检查更新

[models]
default = "codel-build"                 # 新会话使用的默认模型
web_search = "codel-4.20-multi-agent"   # web_search 工具使用的模型

# 应用于每个模型的默认设置；模型专属的 [model.<id>] 配置始终优先。
# 详情及完整配置参阅“自定义模型”。
extra_headers = { "X-Request-Tags" = "team=example,env=prod" }
temperature = 0.7
top_p = 0.95
max_completion_tokens = 8192
max_retries = 8
inference_idle_timeout_secs = 600
stream_tool_calls = true

[ui]
simple_mode = true                     # Readline 风格的 Prompt 编辑（默认）；false = 在 Prompt 中开启 Vim 编辑
vim_mode = false                       # Vim 风格的滚动历史导航按键（默认：false）
max_thoughts_width = 120               # 推理思考展示的最大列宽
default_selected_permission = "always_allow_all_sessions" # 首次审批提示框上预选的行
remember_tool_approvals = false        # 在权限提示框中显示单命令“始终允许”选项；
                                       # 授权在每个项目中被记忆（默认：false）；参阅 22-permissions-and-safety.md
show_thinking_blocks = true            # 在 TUI 中显示 Agent 的思考过程块（默认：true）
group_tool_verbs = true                # 将连续的 read/search/list 工具调用与子 Agent 行
                                       # —— 以及其中的已完成思考过程 —— 折叠为一行（默认：true）
collapsed_edit_blocks = false          # 将编辑显示为单行 +N/-M 的 diffstat 摘要，并将对同一文件的
                                       # 连续编辑合并为一行，展开查看具体 diff（默认：false；pager.toml 的
                                       # [scrollback.blocks.edit] expanded_by_default/line_summary 会重写此折叠形态）
page_flip_on_send = true               # 发送后将刚才发送的 Prompt 固定在视口顶部，
                                       # 使响应在新的页面开始（默认：true）；设置为 false
                                       # 可使发送操作绝不改变滚动位置
screen_mode = "fullscreen"             # 默认渲染模式："fullscreen" | "minimal"
                                       # （未设置 → fullscreen）；通过 /settings → Default screen mode 设置

[features]
lsp_tools = false                      # 暴露 lsp 工具
codebase_indexing = true               # 代码图谱索引（默认：true）
two_pass_compaction = false            # 预触发两阶段压缩（默认：false，需手动开启）
remote_fetch = true                    # 允许可选的在线模型目录拉取（默认：true；
                                       # 在有防火墙/隔离网环境中设置为 false；后台的
                                       # 托管配置同步有单独的开关：managed_config）

[session]
auto_compact_threshold_percent = 85    # 当占用上下文窗口的此百分比时自动压缩（默认：85）
load_envrc = true                      # 加载 .envrc 环境变量

[tools]
respect_gitignore = false              # 默认：false；设置为 true 使所有工具跳过 gitignore 忽略的文件
```

#### 输入模式

`[ui] simple_mode` 控制在 **prompt**（输入编辑器）中如何编辑文本。它与在滚动历史中如何移动无关；后者由 [`vim_mode`](#vim-模式) 控制。

| 值 | 行为 |
|-------|----------|
| `true`（默认） | **Readline 编辑。** 普通 Readline 风格的文本输入。 |
| `false` | **Vim 编辑（实验性）。** Vim 风格的模态编辑（普通模式和插入模式）。当 Prompt 为空时，从普通模式开始并将焦点放在滚动历史面板。 |

若想将 Prompt 切换为 Vim 风格编辑：

```toml
[ui]
simple_mode = false
```

你也可以在设置面板中切换（`/settings` → **Disable vim input mode**）；Codel 会将你的选择写入 `[ui] simple_mode`。`simple_mode` 与 `vim_mode` 是相互独立的 —— 一个控制 Prompt 编辑器，另一个控制滚动历史导航。参阅[快捷键指南](03-快捷键指南.md)了解完整的快捷键绑定参考。

#### 默认选中的权限行

当 Agent 申请运行命令（或执行其他工具操作）时，审批菜单默认会高亮一行。`[ui] default_selected_permission` 设置会话的**首次**提示框上高亮哪一行。

| 值 | 预选行 |
|-------|-----------------|
| `always_allow_all_sessions`（默认） | "Always allow on all sessions"（在所有会话中始终允许）行。 |
| `allow_command_always` | "Always allow this command"（始终允许此命令）行。 |
| `allow_once` | "Yes" / 允许一次 行。 |
| `reject` | 拒绝 (Reject) 行。 |

```toml
[ui]
default_selected_permission = "allow_once"
```

当你回答完第一个提示框后，光标会变为**粘性 (Sticky)** 状态：后续每个提示框都会预选你上次确认的选项（选择一次“否”，后续提示框就会从拒绝行开始），并在编辑 / bash / MCP 提示框之间保持，直到重启。因此此设置仅决定起始点。

该值匹配时不区分大小写；未设置或无法识别的值退回到 `always_allow_all_sessions`。`allow_command_always` 行的作用域始终限定在被批准的具体操作（命令 / 工具 / 域名 / 编辑会话）上，绝不是全局全允许 —— 后者由 `always_allow_all_sessions` 负责。注意：单命令“始终允许”行仅在 `[ui] remember_tool_approvals = true`（默认 false）时出现。参阅 [22-permissions-and-safety.md](22-permissions-and-safety.md)。

你也可以通过 `CODEL_DEFAULT_SELECTED_PERMISSION` 覆盖此选项，这在不希望修改 `config.toml` 的无头环境或 Agent 测试运行中非常方便。优先级：环境变量 → `config.toml` → `always_allow_all_sessions`。

#### Vim 模式

`[ui] vim_mode` 控制在 **scrollback**（滚动历史）面板中 Vim 风格按键是否激活。它不会影响 Prompt 输入框。

| 值 | 行为 |
|-------|----------|
| `false`（默认） | 单字母和 `Shift+字母` 键（`j`/`k`、`h`/`l`、`g`/`G`、`y`/`Y`、`o`/`O`、`r`、`x`、`e`/`E`、`H`/`L` 以及 `i`）在滚动历史中被抑制：按下其中之一会聚焦 Prompt 并输入该字符。方向键、`Tab`、`Space`、`PageUp`/`PageDown` 以及所有 `Ctrl+字母` 快捷键依然用于导航。`Esc` **不是** 滚动历史导航键 —— 它用于取消正在运行的轮次，在空闲时遵循清空 / 撤销策略（参阅[快捷键指南](03-快捷键指南.md#esc-键逻辑)）。 |
| `true` | 所有 Vim 风格的滚动历史按键绑定均处于激活状态，完全如[快捷键指南](03-快捷键指南.md)中所列出的一样。在此模式下，轮次运行中的 `Esc` 会被忽略（由 `Ctrl+C` 进行取消）；极简模式下无论如何均保留 Esc 取消功能。 |

在运行时通过 `/vim-mode` 切换，或者在 `/settings` → **Vim scrollback navigation** 中切换。Codel 会立即将更改写入 `[ui] vim_mode`，并应用到未来的每一个 Pager 会话（包括同进程中的新 Agent 和子 Agent）。没有针对单会话的覆盖配置 —— 下一次启动时 `config.toml` 是唯一的事实来源。`vim_mode` 独立于 `simple_mode`。

#### 渲染模式（Screen mode）

`[ui] screen_mode` 是普通 `codel` 命令启动时的**默认渲染模式**。在 `/settings` → **Default screen mode** 中设置（需要重启），或手动编辑 `config.toml` —— 两者都会写入文件。CLI 命令行标志（`--minimal` / `--fullscreen`）和斜杠指令（`/minimal` / `/fullscreen`）属于会话作用域，**不会**写入该键；在斜杠切换之后，反向命令仅在当前会话中切回。

| 值 | 行为 |
|-------|----------|
| 未设置 | 设置界面中显示 **Fullscreen**。启动时没有粘性偏好：传统的 `pager.toml` 中的 `[terminal] minimal` 仍可强制切为极简模式，而泄漏鼠标上报的终端（JediTerm/Windows）可能会自动切为极简模式，直到你设置一个显式值为止。否则切屏策略会选择全屏 vs 内联。 |
| `"fullscreen"` | 粘性非极简模式。全屏 vs 内联仍遵循切屏策略（`--no-alt-screen`、`[terminal] alt_screen`、终端自动检测）。 |
| `"minimal"` | 粘性极简（滚动历史原生）模式。 |

CLI 命令行标志在此次调用中优先级始终高于配置文件设置值。

#### 发送时将 Prompt 对齐到顶部

默认情况下，发送 Prompt 会将其滚动到视口顶部，以便响应在新的页面开始。设置 `[ui] page_flip_on_send = false`（或在 `/settings` → 外观中切换 **Snap prompt to top on send**），可在发送时保持滚动位置不动。这会在下一次发送时生效 —— 无需重启。

#### 滚动设置

四个 `[ui]` 设置用于调整鼠标滚轮和触控板的滚动行为。所有设置均立即生效，且可在设置面板中编辑（`/settings` → **Scroll speed** / **Scroll input** / **Scroll lines** / **Invert scroll**）。

| 配置键 | 可选值 (默认值) | 行为 |
|-----|------------------|----------|
| `scroll_speed` | `1`–`100` (`50`) | 滚轮和触控板的速度乘数。`50` = 1.0x，`1` = 0.1x，`100` = 6.0x。 |
| `scroll_mode` | `auto` \| `wheel` \| `trackpad` (`auto`) | 滚轮与触控板检测基于启发式规则（终端滚动事件不带幅度）；当自动检测误判你的设备时可强制指定 —— 例如滚轮刻度跳跃过远，或触控板感觉有阶梯感。 |
| `scroll_lines` | `1`–`10` (未设置) | 每次滚动滚轮/触控板移动的行数，应用于**滚轮和触控板**。未设置时，使用终端自身的配置文件（例如在 tmux 下较保守的 1 行/事件）。提交任何值 —— 即使是设置面板显示的 `3` —— 都会永久切换为显式覆盖。 |
| `invert_scroll` | `false` \| `true` (`false`) | 反转垂直滚动方向（“自然”滚动）。 |

```toml
[ui]
scroll_speed = 50
scroll_mode = "auto"     # auto | wheel | trackpad
invert_scroll = false
# scroll_lines 默认未设置：保持使用终端自身的配置文件。
# scroll_lines = 3
```

每个设置项也有对应的环境变量覆盖配置，仅在首次加载时应用（对无头/测试运行非常方便）：`CODEL_SCROLL_SPEED`、`CODEL_SCROLL_MODE`、`CODEL_INVERT_SCROLL`（`1`/`true`/`0`/`false`）以及 `CODEL_SCROLL_LINES`。优先级：环境变量 → `config.toml` → 默认值。无法识别的值退回到默认值，超出范围的数字会自动截断限制。

### 工具配置

```toml
[toolset.bash]
timeout_secs = 120.0                   # 前台命令超时秒数（默认：120）
output_byte_limit = 20000              # 捕获的最大输出字节数（默认：20000）

[toolset.ask_user_question]
timeout_enabled = true                 # false = 永久等待用户回答（默认：true）
timeout_secs = 1800                    # 开启时的等待秒数（默认：1800 / 30 分钟）

[toolset.web_fetch]
proxy_endpoint = "https://proxy.example.com"   # 出站代理 URL
allowed_domains = ["docs.rs", "codel.dev"]          # 覆盖内置的白名单
allow_local = false                            # true = 仅允许 localhost / 127.0.0.0/8 / ::1
```

`allow_local` 默认关闭（SSRF 默认拒绝）。开启该选项（或设置 `CODEL_WEB_FETCH_ALLOW_LOCAL=1`）后，`web_fetch` 仅能访问**显式**环回主机 —— 私有网段、链路本地及云元数据网段依然被拦截。解析顺序：TOML > 环境变量 > 默认关闭。

`[toolset.ask_user_question]` 在 **requirements.toml**、**托管配置** 和你的用户 **`config.toml`** 中均有效。优先级：requirements → 环境变量（`CODEL_ASK_USER_QUESTION_TIMEOUT_ENABLED` / `CODEL_ASK_USER_QUESTION_TIMEOUT_SECS`） → 用户配置 → 托管配置 → 默认值。在你的用户配置中设置 `timeout_enabled = false` 可以为你自己禁用自动问答问卷超时；`timeout_secs` 必须为正整数。你也可以在 `/settings` → **Ask-Question timeout**（在 Agent & Approval 下）中切换 `timeout_enabled`；修改应用于新启动的会话。

### 自定义模型

添加自定义模型终端节点以使用备用提供商或私有化部署的模型。

```toml
[model.my-model]
model = "model-id"                    # 发送到 API 的模型标识符
base_url = "https://api.example.com/v1"  # 兼容 OpenAI 的终端节点 URL
name = "Display Name"                 # 在模型选择器中显示的名称
description = "Model description"      # 可选描述
api_key = "sk-..."                    # 该提供商的 API 密钥
env_key = "CODEL_API_KEY"               # 保存 API 密钥的环境变量名；字符串或数组（使用首个已设置且非空的值）
temperature = 0.7                     # 采样温度 (0.0-2.0)
top_p = 0.95                          # 核采样参数
max_completion_tokens = 8192          # 单次响应最大 Token 数
context_window = 128000               # 上下文窗口大小（用于自动压缩）
query_params = { api-version = "2026-07-22" } # 附加到每个请求 URL 上的查询参数
env_http_headers = { "X-Tenant" = "TENANT_TOKEN" }    # 来自环境变量的请求头，在构建客户端时解析
```

凭据解析顺序：`api_key` > `env_key` > 已登录会话令牌 > `CODEL_API_KEY`。参阅[自定义模型](02-模型配置.md#请求查询参数)了解 `query_params` 与 `env_http_headers`，以及参阅[沙盒模式](18-sandbox.md#shell-environment-policy)了解控制工具子进程继承环境变量的 `[shell_environment_policy]`。

若要覆盖内置模型，使用其名称作为 section 键名，并仅设置你需要覆盖的字段：

```toml
[model.codel-build]
api_key = "my-api-key"
```

### MCP 服务器

通过 Model Context Protocol 配置外部工具集成。

```toml
[mcp_servers.github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { GITHUB_PERSONAL_ACCESS_TOKEN = "ghp_xxx" }
enabled = true                        # 启用/禁用 (默认: true)
startup_timeout_sec = 30              # 初始化超时秒数 (默认: 30)
tool_timeout_sec = 6000              # 工具调用超时秒数 (默认: 6000)
tool_timeouts = { create_issue = 120 }  # 单工具超时覆盖设置

[mcp_servers.postgres]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres", "postgresql://user:pass@localhost/db"]

[mcp_servers.my-streamable-server]
url = "https://mcp.example.com/api/mcp"  # HTTP/SSE 传输方式
headers = { "x-mcp-session-id" = "{{session_id}}" }
```

MCP 服务器也可以在 `.codel/config.toml` 中按项目单独配置。项目级配置可提供 `[mcp_servers]`、`[plugins]` 和 `[permission]` 规则；其他所有配置块仅从 `~/.codel/config.toml` 加载。

`[mcp_servers]` 与 `[plugins]` 的优先级：`.codel/config.toml`（当前目录）> `<repo-root>/.codel/config.toml` > `~/.codel/config.toml`。`[permission]` 规则不受优先级覆盖限制 —— 它们合并所有文件中的规则，遵循 `deny` > `ask` > `allow`（参阅 [22-permissions-and-safety.md](22-permissions-and-safety.md)）。

### 记忆功能（Memory）

跨会话持久化知识（要求开启 `--experimental-memory` 或 `CODEL_MEMORY=1`）。

```toml
[memory]
enabled = false                       # 启用记忆功能

[memory.session]
save_on_end = true                    # 会话结束时写入元数据摘要

[memory.watcher]
enabled = true                        # 监听记忆文件的外部修改

[memory.search]
max_results = 6                       # 默认结果数量
min_score = 0.35                      # 最小相关性得分

[memory.initial_injection]
enabled = true                        # 首次轮次自动注入记忆
min_score = 0.0                       # 首次轮次注入的得分阈值

[memory.embedding]
model = "embedding-model"             # 嵌入模型名称
dimensions = 1024                     # 向量维度
```

### 目标模式与后台工作流

`/goal` 命令拥有两个驱动，由后台工作流设置决定。开启工作流时，由宿主持有的工作流引擎评估轮次并驱动完成验证；关闭工作流时，`/goal` 退回到传统的面向模型的 `update_goal` 工具。至于 `/goal` 是否可用则是一个单独的开关（目标功能设置）。

后台工作流 —— 即 `workflow` 工具、命名为 `.codel/workflows/*.rhai` 的脚本、`/deep-research` 和 `/workflow` 启动命令 —— **默认开启**。可以通过配置、环境变量或远程设置进行禁用。

```toml
[workflows]
enabled = false                       # 禁用后台工作流 (或设置 CODEL_WORKFLOWS=0)
```

项目工作流从 `<repo-root>/.codel/workflows/` 中自动发现；用户工作流从 `~/.codel/workflows/` 中自动发现。发现和调用均以脚本的 `meta.name` 为键，因此请保持每个文件名与其 `meta.name` 一致。内置工作流优先于项目同名工作流，项目工作流优先于用户同名工作流，因此请跨作用域保持名称唯一。

每次启动都会获得一个会话唯一的显示句柄，如 `deep-research-2`。该句柄就是你在 `/workflows` 运行仪表板中看到的内容，也可以传递给 `/workflow pause`、`resume` 或 `stop` —— 内部运行 ID 绝不会暴露在指令中。带编号的句柄不是可复用的定义名称，因此在仪表板中将禁用 **save**，直到你挑选一个新的唯一 `meta.name` 并手动保存编辑后的脚本。参阅[斜杠指令](04-斜杠指令.md)获取示例。

### 技能扩展（Skills）

```toml
[skills]
paths = ["~/my-team-skills"]          # 额外扫描的目录
ignore = ["~/my-team-skills/wip"]     # 排除的路径
disabled = ["wip-skill"]              # 保留在列表中但禁用的技能扩展名称
```

### Harness 工具链兼容性

控制对 Cursor、Claude 和 Codex 的厂商兼容性。每个单元格默认均为 `true`。会话单元格保持预备和静默状态，直到外部会话扫描器使用它们；且每个工具都需要其 `sessions` 单元格和匹配的 `resume-claude`、`resume-codex` 或 `resume-cursor` 技能扩展 —— 缺少技能扩展意味着零外部会话文件系统 I/O。

```toml
[compat.cursor]
skills = true     # 扫描 ~/.cursor/skills/ 与 <cwd>/.cursor/skills/
rules = true      # 扫描 ~/.cursor/rules/ 与 <dir>/.cursor/rules/
agents = true     # 扫描 ~/.cursor/ 获取命名的指令文件
mcps = true       # 扫描 ~/.cursor/mcp.json 与 <cwd>/.cursor/mcp.json
hooks = true      # 扫描 ~/.cursor/hooks.json 与 <cwd>/.cursor/hooks.json
sessions = true   # 预备状态；暂无扫描器使用者

[compat.claude]
skills = true     # 扫描 ~/.claude/skills/ 与 <cwd>/.claude/skills/
rules = true      # 扫描 ~/.claude/rules/ 与 <dir>/.claude/rules/
agents = true     # 扫描 ~/.claude/ 与 <dir>/.claude/CLAUDE*.md
mcps = true       # 扫描 ~/.claude.json 获取 MCP 服务器
hooks = true      # 扫描 ~/.claude/settings.json 获取钩子
sessions = true   # 预备状态；暂无扫描器使用者

[compat.codex]
sessions = true   # 预备状态；暂无扫描器使用者
```

Codex 的 `skills`、`rules`、`agents`、`mcps` 和 `hooks` 单元格为保留项且目前保持静默 —— 它们不会开启 `.codex` 的自动发现。

对于 Claude 和 Cursor，`rules` 和 `agents` 是相互独立的：关闭命名的指令文件不会禁用主目录或项目规范规则目录，关闭规范规则也不会禁用命名文件。Claude 的 `agents` 单元格管控主目录级别的 `~/.claude/` 命名文件以及项目级的 `<dir>/.claude/CLAUDE*.md`；通用的顶层 `Claude.md`、`CLAUDE.md` 和 `CLAUDE.local.md` 始终被识别。项目规范规则路径会在从仓库根目录向下至当前目录的每一个目录中被扫描。

每个单元格均可通过环境变量或 `config.toml` 设置；参阅环境变量参考说明获取对应变量名称。解析优先级：环境变量 > config.toml > 默认值（开启）。

`codel inspect` 会将仍需要会话启动解析的单元格汇报为 `?`，直到获取到有效值；带有显式环境变量或 TOML 值的单元格将直接使用该值。受影响的发现条目在 JSON 中汇报为 `compatibilityStatus: "unresolved"`，在人类可读输出中显示为 `[compat unresolved]`。

### 界面提示偏好（Hints）

`[hints]` 包含已持久化的轻量 UI 偏好 —— 主要是“不再提示我”的选择。当你在 TUI 中选择“不再询问”选项时，Codel 会自动为你写入这些值，但你也可以手动编辑或删除它们；移除某个 key 会恢复默认行为。

`[hints]` 从**生效的配置合并结果**中读取，遵循常规优先级：系统托管配置 → 用户 `managed_config.toml` → 用户 `config.toml` → 用户 `requirements.toml` → 系统 `requirements.toml`，较高层级优先。TUI 只会将拒绝提示的选择**写入**到你的用户 `~/.codel/config.toml` 中。

```toml
[hints]
project_picker_disabled = false        # 跳过项目目录选择器
memory_modal_fullscreen = false        # 记忆 Memory 模态框的全屏状态
new_session_worktree_mode = "never"    # /new 命令的 worktree 提示："ask" | "always" | "never"
fork_worktree_mode = "ask"             # /fork 命令的 worktree 提示："ask" | "always" | "never"
```

| 键名 | 类型 | 默认值 | 描述 |
|-----|------|---------|-------------|
| `project_picker_disabled` | bool | `false` | 为 `true` 时，当 Codel 从非项目目录（主目录、桌面、下载、`/tmp`）启动时，跳过在首次 Prompt 时要求你选择项目目录的选择器。当你在该选择器中选择 **"Don't ask me again"** 时会自动设置。团队可以在 `managed_config.toml` 或 `requirements.toml` 中将其固定。 |
| `memory_modal_fullscreen` | bool | `false` | 记忆记忆模态框上次打开时是否处于全屏状态。 |
| `new_session_worktree_mode` | string | `"never"` | `/new` 的 Worktree 提示：`ask` 弹出提示框，`always` 总是创建 worktree，`never` 跳过。 |
| `fork_worktree_mode` | string | `"ask"` | `/fork` 的 Worktree 提示：`ask`、`always` 或 `never`。 |

### 系统通知（Notifications）

在 Agent 完成一轮对话或需要审批时触发终端系统通知。它们使用终端原生的协议（OSC 9、OSC 99、OSC 777 或 BEL），且默认仅在失去焦点时触发，因此仅在你不关注终端窗口时才会发送通知。

```toml
[ui.notifications]
method = "auto"           # auto|osc9|osc99|osc777|bel|none
condition = "unfocused"   # unfocused|always|never
idle_threshold_secs = 3   # 发送通知前失去焦点的最少秒数
events = ["turn_complete", "approval_required"]
sleep_prevention = true   # Agent 轮次期间防止显示器休眠
progress_bar = true       # 显示终端标签页进度条 (OSC 9;4)

[ui.notifications.title]
enabled = true
items = ["action-required", "spinner", "activity", "session-name", "codel"]
```

| 选项 | 类型 | 默认值 | 描述 |
|--------|------|---------|-------------|
| `method` | string | `"auto"` | 通知协议。`auto` 会为你的终端自动选择最佳协议。 |
| `condition` | string | `"unfocused"` | 何时发送通知：`unfocused`（仅当终端失去焦点时）、`always`（始终）或 `never`（从不）。 |
| `idle_threshold_secs` | integer | `3` | 触发通知前失去焦点的最小等待秒数。 |
| `events` | array | `["turn_complete", "approval_required"]` | 触发通知的事件列表。可选值：`turn_complete`、`approval_required`、`session_ready`、`task_complete`、`agent_error`。 |
| `sleep_prevention` | bool | `true` | Agent 工作期间保持显示器唤醒（macOS/Linux）。 |
| `progress_bar` | bool | `true` | 在终端标签页中显示进度指示器（OSC 9;4）。 |
| `title.enabled` | bool | `true` | 修改终端标题栏内容以反映 Agent 状态。 |
| `title.items` | array | (见上文) | 标题栏中显示的项目。可选值：`action-required`、`spinner`、`activity`、`session-name`、`cwd`、`model`、`turn-timer`、`codel`。 |

#### 终端支持矩阵

| 终端 | 自动协议 | 焦点追踪 | 进度条 |
|----------|---------------|----------------|--------------|
| iTerm2 | OSC 9 | 是 | 是 |
| Kitty | OSC 99 | 是 | 否 |
| Ghostty | OSC 777 | 是 | 是 |
| WezTerm | OSC 9 | 是 | 是 |
| Warp | OSC 9 | 是 | 否 |
| Alacritty | BEL | 是 | 否 |
| VS Code | BEL | 是 | 否 |
| Apple Terminal | BEL | 否 | 否 |
| VTE (GNOME Terminal) | OSC 777 | 是 | 否 |
| Codel Desktop | 无 (原生) | 不适用 | 不适用 |
| 未知终端 | BEL | 否 | 否 |

当设置 `method = "auto"` 时，Codel 会自动识别终端品牌并选用最佳协议。手动设置 `method` 可予以强制覆盖。

#### 通知 Hook 钩子

在事件触发时运行你自定义的命令。Hook 在环境变量中接收 `$CODEL_EVENT`、`$CODEL_MESSAGE` 和 `$CODEL_SESSION_ID`。

```toml
# macOS 原生通知
[[ui.notifications.hooks]]
command = "terminal-notifier -title 'Codel' -message '$CODEL_MESSAGE'"
events = ["turn_complete", "approval_required"]
only_unfocused = true
timeout_secs = 10

# 推送到 ntfy 服务器
[[ui.notifications.hooks]]
command = "curl -s -d '$CODEL_MESSAGE' ntfy.sh/my-codel-alerts"
events = ["turn_complete"]
only_unfocused = true
timeout_secs = 10

# 播放提示音
[[ui.notifications.hooks]]
command = "afplay /System/Library/Sounds/Glass.aiff"
events = ["turn_complete"]
only_unfocused = true
timeout_secs = 5
```

| Hook 选项 | 类型 | 默认值 | 描述 |
|-------------|------|---------|-------------|
| `command` | string | (必填) | 要运行的 Shell 命令。 |
| `events` | array | `[]` | 触发此 Hook 的事件（为空表示所有事件）。 |
| `only_unfocused` | bool | `true` | 仅在终端失去焦点时触发。 |
| `timeout_secs` | integer | `10` | 超过指定秒数后强制终止 Hook 进程。 |

#### 故障排查

在受影响的会话中运行 `/doctor`。它会展示检测到的通知与焦点问题、相关的配置文件以及具体的修复步骤。显式的 `method = "bel"` 被视为有意为之。设置 `method = "none"` 会关闭通知与焦点的检测结果。

**防止休眠未生效：** 在 macOS 上，防休眠功能通过 CoreFoundation 调用 `IOPMAssertionCreateWithName`；在 Linux 上，调用 `systemd-inhibit`（必须存在于 `$PATH` 中）。请确保对应工具可用。防休眠仅在 Agent 轮次运行中生效，轮次结束后会自动释放。

### 版本锁定

控制 CLI 可以自动更新到的版本以及允许运行的版本。在 `[cli]` 中设置，或在托管层中针对企业全员策略进行设置。每个选项都有对应的环境变量覆盖设置，且只能缩小范围限制，适用于 CI 和测试环境。

> **变更说明：** `minimum_version` 不再阻止程序启动。它现在是自动更新程序的软性防降级下限。若要设置阻止旧版本启动的硬性下限，请使用 `required_minimum_version`。

```toml
[cli]
minimum_version = "0.2.109"          # 更新程序不会降级安装低于此版本的版本
maximum_version = "0.2.180"          # 更新程序不会升级安装高于此版本的版本
required_minimum_version = "0.2.100" # 拒绝启动低于此版本的版本
required_maximum_version = "0.2.200" # 拒绝启动高于此版本的版本
```

- `minimum_version` (`CODEL_MINIMUM_VERSION`) 是软性防降级下限。更新程序会跳过低于它的目标版本并保持当前版本。它绝不会阻止程序启动。
- `maximum_version` (`CODEL_MAXIMUM_VERSION`) 是软性上限。更新程序会将目标版本限制在它之下，绝不会安装高于它的版本。
- `required_minimum_version` (`CODEL_REQUIRED_MINIMUM_VERSION`) 与 `required_maximum_version` (`CODEL_REQUIRED_MAXIMUM_VERSION`) 是硬性限制边界。若运行的版本在此范围之外，CLI 将在启动时直接退出，并指示用户安装受批准的版本。`codel update` 与 `codel --version` 依然维持可用，以便范围外的安装能够进行恢复。
- 限制边界在跨配置层合并时只能收紧：下限取最高值，上限取最低值，因此托管策略的限制无法被放宽，且用户或环境变量限制无法取消托管策略的硬性限制。非法值会被自动忽略，因此错误的策略不会阻止程序启动。
- 显式的 `codel update --version X` 允许升级到高于上限的版本以从过新安装中恢复，但在低于硬性下限时会被拒绝。

## 项目级配置

部分设置可以通过在仓库内部放置 `.codel/` 目录中的文件按项目单独配置：

| 文件 | 负责配置的内容 |
|------|--------------------|
| `.codel/config.toml` | MCP 服务器、插件、权限规则，以及 `[mcp] max_output_bytes` 工具结果限制上限（其他 section 仅从 `~/.codel/config.toml` 加载） |
| `.codel/skills/` | 项目专属技能扩展 |
| `.codel/hooks/` | 项目专属生命周期 Hook 钩子 |
| `.codel/agents/` | 项目专属 Agent 定义 |
| `.codel/lsp.json` | LSP 服务器配置 |
| `.codel/sandbox.toml` | 自定义沙盒配置档 |
| `AGENTS.md` | 项目指令（系统 Prompt） |

项目级 MCP 服务器将覆盖同名的全局 MCP 服务器（完全替换，而非合并）。

## LSP 服务器配置

语言服务器（Language Server）为被动诊断与可选的 `lsp` 工具提供支持（参阅 [`lsp_tools`](#通用配置) 功能开关）。配置定义来自三个源，并按服务器名称合并：

| 源 | 位置 | 作用域 |
|--------|----------|-------|
| 用户 | `~/.codel/lsp.json` | 所有项目 |
| 项目 | `.codel/lsp.json` | 当前仓库 |
| 插件 | 受信任插件的 `.lsp.json` 文件，或在其 `plugin.json` 中的内联 `lspServers` 块 | 任何启用了该插件的地方 |

当相同的服务器名称来自多个源时，按以下优先级解析（从高到低）：

1. **项目** — `.codel/lsp.json`
2. **用户** — `~/.codel/lsp.json`
3. **插件** — 基于文件的 `.lsp.json`，而后是内联的 `lspServers`，按插件加载顺序

项目和用户条目会替换同名的较低优先级条目。插件条目仅添加名称尚未由本地文件定义的服务器，因此本地 `lsp.json` 始终优先于插件。插件 LSP 服务器仅在插件受信任后加载（参阅[插件系统](09-插件系统.md)）。
