# 智使控制面板

智使控制面板（Agent Dashboard）是一个汇聚一处、对智使原生的视图，旨在概览您正在进行的每一个顶层会话——涵盖本地的各类会话及分支——并通过状态对其予以分组，实现了在同一界面中进行概览、附着（attach）与分发的功能。分身智使并不会被罗列于此：因为它们是在父会话之下运作的，而当工作正在执行时，父会话自身便已然能够体现。

---

## 打开控制面板

包含三种切入点，它们皆可打开相同的视图：

- **`codel dashboard`** — 直接将 TUI 启动进入到控制面板。
- **`/dashboard`** (别名 **`/agents-dashboard`**, **`/sessions`**) — 从某处于激活状态下的会话内将其唤起。
- **Ctrl+\\** — 与斜杠命令功效一致，仅需两次按键敲击。该快捷键与其他任何快捷键相仿，均可在 `~/.codel/config.toml` 里的 `[keybindings]` 处进行定制化配置。

## 所见即所得

```
 Codel Build · Dashboard — 4 agents · 2 awaiting
▌● reviewer · audit token flow    Awaiting your input            2m
 ● implementer · fix login bug    Running: cargo test           12m
 ⋅ refactor · feat/login          Responding…                   24m
 ○ housekeeping                   idle                           1h
 ● implementer · add login tests  8 tools · 1.2k tok            14m
╭─────────────────────────────────────────────────────────────────╮
│ ❯ Dispatch a new agent                                          │
╰─ dispatch ──────────────────────────────────────────────────────╯
 ↑/↓ select (peek) · Enter open · Ctrl+R rename · Ctrl+T pin · Ctrl+X stop · ? help · Esc new
```

每一行表征着一个顶层的智使（分身智使不会在此显现——它们运作在父级之下）。行是以状态为依据进行排布的（需要输入 → 正在运作 → 空闲 → 沉寂 → 已经圆满 → 已遭折戟），从而保证处于相同状态的行能够挨在一起，或是依照工作目录进行排序（运用 `Ctrl+G` 切换）。**沉寂**状态（Inactive）容纳那些唯独存于花名册当中的会话——隶属其他 pager 进程、且尚未被纳入到当前进程中的闲置或潜伏的会话——这样 **空闲**（Idle） 便能够专职聚焦在那些您正积极轮换来回的会话之中。也正因其属于背景杂音范畴，故而 **沉寂起初便呈现出收敛的态势**（借助 `→` / 点击操作来将其展开——详见下文）。

为了确保 **空闲** 组维持易于扫视阅读的特质，系统只会让近期内最前沿的空闲智使停留在可视范围里——也就是最新鲜的 8 个，再加上近一小时以内拥有过活动轨迹的那些智使。而余下的智使，均会被折叠进该组最底部的一个 **“还有 N 个”** 的选项里（标注有 `+` / `-` 的触发记号）；当选中它并点击 `Enter` / `→` （抑或是点击它）时，则会将它们尽数展露，而 `←` 则能实现重新收叠。空闲部分首部则随时随地呈现出毫无差池的总数量。一旦在过滤亦或是搜索正处被激活的状态下，折叠机制也将暂行告停（因此任一匹配结果都会一览无余）。

状态图标与 Codel Build 麾下等侪的各类视图（例如 `tasks_pane`）保持着和谐共振：

- `⋅`/`:`/`⸬`/`⁙` — 用于 **正在运作** 行的灵动旋转动画效果。
- `●` — 应用于 **需要输入**、**已经圆满**、**已遭折戟**、**已遇壁垒** 情况的饱满圆点。藉由色彩（黄 / 绿 / 红 / 琥珀）传递出具体的意涵。
- `○` — 在 **空闲** 以及 **沉寂** 环节采用的空心圆环。

倘若某一行存在持续推进着的后台任务，那么纵使它的那一轮已告终了，它也会依旧保持在 **正在运作** 的状态——无论是处于运转中的后台任务、抑或是一项 `monitor`，又或者是某个活跃当中的规律性 `/loop` 皆如此。活动日志行将会阐明当下有何正在运转（诸如 `1 monitor · 2 loops still running` ），只因其中的随便哪一个都能叫醒智使，为迎接新一轮的周期做足准备。

在这里并未设置内联群组性质的头部提示——依托于排序顺次即可维系相同状态的行彼此比邻，并且各行的 圆点加色彩 组合亦能传达出该行究竟隶属于哪一群体（顺应了其余各式会话列表的做派）。

用来下达分发指令的输入环节采用着和智使视图中的提示输入如出一辙的 `PromptWidget` 的铬合金外壳质感（包括圆角矩形匣子、以 `❯` 作为前缀、带强调色的边框、以及信息行等元素）。一旦敲击 `Ctrl+/` 便会令其切入到 **搜索模式** 当中：由原先的 `❯` 前导标识更易成了一抹醒目的黄色 `Search:` ，同时您所键入的任意字符，其指向的不再是下达新的任务，而将即时过滤筛选那列队而出的各项行。

## 快捷键映射

| 按键 | 行为 |
| --- | --- |
| `↑` / `↓`, `j` / `k` | 在各行乃至组别的题头处穿梭（一旦选中某行，相应的窥视窗亦会顺势启开） |
| `→` / `←` (在组别题头处) | 展开 / 闭合该部分的内容（将所属各行呈现 / 隐匿）；身处 vim 模式之时，`l` / `h` 具备相同的功效 |
| `Enter` (在组别题头处) | 触发针对该部分闭合 / 展开姿态的转换交替 |
| `Enter` (回复框为空) | 将选定的这名智使的对话详情铺满整个屏幕以供端详（详情视图） |
| `Ctrl+S` | 发送窥视窗所编写的回复并且打开这位智使的界面（或者是开启一番新会话并发下任务随即依附过去） |
| `Shift+Enter` / `Alt+Enter` | 在回复或是分发命令输入之时嵌入一次换行（多行输入） |
| `1`–`9` | 当窥探面板列出相关备选项时，在此刻响应一笔悬而未决的 授权请求 / 问询工具 事项 |
| `Enter` (回复框有内容) | 发送起草完毕的回复至这名被选中的智使 / 纳入列队 |
| `/` | 在提示输入中输入字面字符 `/` |
| `Ctrl+/` | 搜索模式切换（能够现场把控过滤这些行） |
| `Ctrl+R` | 为所选定的这一行执行重命名 |
| `Ctrl+T` | 图钉钉选 / 拔出图钉 |
| `Ctrl+G` | 调动分组方式的更迭（状态 ↔ 目录） |
| `Ctrl+X` | 中止 / 强杀（在2秒内双击将彻底了结一次会话） |
| `Shift+↑` / `Shift+↓` | 为已置顶的项进行次序的更替 |
| `Esc` | 在层级间向后退回一步：取消搜索 → 退出窥视（先行清空草创的回复，随即撤销选择） → 清空过滤器 → **把焦点从任务分发输入中移开**（从而能够运用 `↑`/`↓`, `j`/`k` 导航列表） → 撤销行的选中（退入至 `[+ New Agent]` 之处） → 告别面板界面。Esc 将绝不清除你已在分发输入里的文稿起草——这事得借助 `Ctrl+U` / `Ctrl+C` 去做。 |
| `Ctrl+\` | 在置身详情视图之时返还至面板所在，又或退出面板界面 |
| `Ctrl+.` (别名: `?`) | 将快捷键一览的小抄速记铺展开来。当 `Ctrl+.` 投递无果之际，页脚便会推举用 `?` 作为替代。当处于聚焦在列表亦或是草稿留白的情景下，`?` 即可召出求助页面（其余光景下意为正常输入）；在这期间，`Ctrl+X` 停止指令依然生效 |

当以状态分组时，每个群组都配载了一行 **板块抬头**（例如 `Working`, `Idle`），其上会携有一枚指明折叠与否的 `▸`/`▾` 标记符。这行板块抬头也包含在上下导航序列当中：选定某一项并且按下 `→` 展开它（借此表露出名下的这些行），抑或是按 `←` 进行归拢折叠——开启了 vim 模式的当口， `l` / `h` 具备相同效果。**鼠标单击**板块的抬头能切换状态，而悬停**浮掠**其上，会引得上面的字符高亮。折叠状态会在本控制面板敞开之际被记住。关于那个 **沉寂** 组别，每次 pager 启动，它便默认呈现为缩身合拢的姿态；展开它直到您退出才会重置。

打开一行将显示该智使的对话 **详情视图**：顶层有一行（智使的名字在左侧，标志着循环及关闭的 `{i}/{n} [‹][›] [Dashboard]` 在右侧），其位于会话的最上方，而这会话，以 **全宽** 渲染——不存在带有边框的模态窗口——这般做法是为了让其提示区域以及整体的内边距能够与控制面板的列表视图匹配。所有键盘按键将路由到这位处于被附着状态的智使处；`Esc` / `Ctrl+\\`（以及那个 `[Dashboard]` 标牌）返回控制面板，`[‹]` / `[›]` 能够切换至上一名 / 下一名智使，并且在智使自身的快捷工具条里揭露了一项针对 `Ctrl+\\: back to dashboard` 的指引。注意一个小细节——`Esc` 仅仅是返回控制面板；而在智使内键入 `/exit` 实际上会关闭底层的会话（当其返回面板时，会显示“会话已关闭”的提示）。

在详情视图中，`Ctrl+X` 的效果取决于状态。当 **轮换周期正在运行** 时，敲击它如取消这一回合一般——表现得跟 `Ctrl+C` 毫无二致，包括保留分身智使的提示——并且断然不会去关闭会话本身，因此，您为中止回合而连按也不必担忧关闭会话。在别的任何场景下——无论是**空闲**，还是有斜杠命令正在运行（这类命令目前无法被中止），亦或者某项取消正处于积压状态——`Ctrl+X` 将挑起二次确认：快捷工具栏会提示“再次按 Ctrl+x 以关闭此会话”，在 2 秒之内第二次按下便能关闭会话并返回控制面板。按其他任何键会取消确认，在窗口内发生的回合将其降级为取消而不是关闭。（在把 `Ctrl+X` 映射为调取快捷键帮助的终端中，在详情视图内部您仍可通过 `Ctrl+.` 调取帮助。）

要查看所有行为规范（包括注册查找规则以及鼠标事件拦截矩阵），请阅览计划书里的 [§3.10](../../plan/agent-dashboard.md) “快捷键绑定 (v1)”——本指南有意简短并交叉引用计划书作为事实来源。

所有的快捷键挂靠在 `When::DashboardFocused` 之上，可以在 `~/.codel/config.toml` 之内被重新绑定。

## 分发输入区

底部的文本区 **永远只用于生成一个新会话**——它绝非一个回复目标。被选中的某行，只是作为概览导航的游标，而非回复目标；若想跟现成的智使交流，请打开它（导航后敲击 `Enter` ，抑或是点击）并在它自身的视图内回复。

Enter 键的处理器：

- 自由文本 → 孕育出一段归属顶层的新会话，并以您的提示作为种子。文本 **永远不被** 重新解释为过滤器——提示可以以 `/`, `s:`, `a:`, 或 `#` 起头，依旧被逐字派发（过滤是明确的 `Ctrl+/` 搜索模式）。以 `/` 开头运行 pager 全局的斜杠命令。
- 空输入 → 打开被选中的那行（`Attach`），或者当它聚焦在 `[+ New Agent]` 标志处，会创建一个新的智使。

在输入提示后按 `Ctrl+S` 将既分发又附着（跳转入新会话）；单独按 `Enter` 仍留在控制面板，以便您可以连续分发多个会话。`Shift+Enter` / `Alt+Enter` 会插入换行以实现多行提示——该输入框会随着行数的增加而 **高度增长**（达到一个上限，之后将滚动），确保整篇草稿可见。

分发输入框接受任何非空的提示；空白/纯空格的提示被忽略。超过 64 KiB 的提示会被拒绝并显示通知。

### 焦点切换：输入栏 ↔ 概览列表 (`Tab`)

控制面板有两个焦点区域 —— **任务分发框** （输入） 以及 **概览列表** （导航）。`Tab` 键在两者间切换；未聚焦的输入框会变暗其边界并隐藏光标。

打开时，只要至少有一个智使存在，焦点默认落于 **概览列表** （因此 `↑`/`↓` / vim 下 `j`/`k` 立刻进行导航）。当 **没有** 智使时，焦点停留于 **任务分发框**，以便您可以立即输入第一个提示。无论哪种情况，`[+ New Agent]` 按钮都是初始的光标目标（不会预先选中任何智使行）。

- **输入框聚焦**：输入以起草新会话提示。当提示为空时，`↑`/`↓` 将导航行列表（提供便利），否则移动文本光标。`Esc` 将焦点从输入框移走 → 概览列表（您的草稿得以保留） 这样您可以立即导航。
- **概览列表聚焦**：`↑`/`↓` —— 在 **vim 模式**， `j`/`k` ——在智使行之间移动。 `Enter` 打开高亮的智使（在 `[+ New Agent]` 上，发送起草好的提示，否则创建新会话）。 `Esc` **留在此列表上** 并且向后退一步——清除激活的过滤器，接着取消行的选中（→ `[+ New Agent]`），然后退出控制面板。`Tab` 或 `i` (vim) —— 抑或任何其他可打印字符 —— 都会回到输入框。

## 窥视面板

当选中一行时，窥视面板 **默认显示** —— 它 **替换了** 新会话的分发输入框。如果未选中任何行（焦点在 `[+ New Agent]` 按钮上，或者按下 `Esc` 后），分发输入框将再次出现以开启新会话。因此选中某行即是与现有智使交互的方式；取消选中即是开启新会话。

面板从上至下显示一个标头（**上一响应类型** —— `思考中` / `想法` / `响应` / `正予编辑` / `调阅` / `Bash` / … —— 在左侧，**时间** 在最右侧），最近的一次响应内容（**折行显示** 以适应尺寸，最多约 3 行），以及一个即时的 `❯ reply` 输入框。如果最后一行无法显示全部内容，才会出现 `…` 标记。

选中的智使之 **模型**，以及若其处于总是批准 (yolo) 模式之下的 **`always-approve`** 徽章，将显示在面板的 **底边框** 上（右下角）——这与新会话分发输入框使用的配置徽章插槽一致。在问询 / 批准模式下亦如此，以便在您回答时始终显示模型与批准模式。（仪表盘列表行不再重复显示模型或总是批准徽章，保持列表紧凑）。

**`Shift+Tab` 循环窥视智使的模式**（普通 → 筹划模式 → 自动审查（启用时）→ 总是批准 → 普通）——与在智使聊天视图中内部的 Shift+Tab 循环一致，应用于 **实时的** 智使（徽章更新以匹配）。这不同于新会话分发框，在那里的 Shift+Tab 只会为 *下一个* 智使预备模式。

与分发输入框（它只用于派生新会话）不同，窥视的回复框是 **与选定的智使直接通信** 的：

- **输入到 `❯ reply` 中，接着按 `Enter`** 发送。一个 **空闲的** 智使会立即开启这回合；而一个 **忙碌的** 智使会将其 **排队**，等待当前回合结束再发送（这与智使视图自身提示框的排队/消耗行为一致）。`Ctrl+S` 将发送回复 并 打开该智使的详细视图；`Shift+Enter` / `Alt+Enter` 插入换行（多行输入）且回复框会 **高度增长** 以适应草稿内容（直至达到上限后开始滚动）。
- 当回复框 **空** 时，按 `Enter` 打开智使。
- **一旦回复框中有内容，`↑`/`↓` 将在回复内部移动光标**（以便编辑多行草稿）。当回复框为 **空**（或通过 `Tab` 失焦），`↑`/`↓` 转而 **切换选中的智使**——面板跟随选择光标实时刷新，且切换时会清除任何打到一半的草稿以防回复发给错误的智使。（当草稿存在于回复中时，`Tab` 切换至行列表以导航智使。）
- **`Esc` 取消选中**：它首先清除已起草的回复，然后取消选中此行并把焦点移向 `[+ New Agent]` 按钮（呼回新会话输入框）。
- **`Tab`** 在回复输入框与行列表之间切换焦点：失去焦点的回复框边框变暗并隐藏光标；按下可打印字符将使其重新获取焦点并开始输入。
- 该回复框是一个 **完整的提示编辑器**（与分发框和智使提示框使用的组件相同）：粘贴多行文本折叠进 `[Pasted: N lines]` 块中，带有相同的预览层和扩展功能（`Enter` / 双击 / 再次粘贴），鼠标点击/拖曳放置光标选中文本，常规快捷键同样生效（光标跳跃，`Ctrl+A`/`Ctrl+E`, `Alt+Backspace`, `Ctrl+W`/`Ctrl+U`/`Ctrl+K`, 撤销, Shift+方向键选择, `Ctrl+Shift+V` 内联粘贴）。
  输入 **`@`** 将弹出基于 **正被窥视的智使的** 工作目录的上下文文件选择器（因此 `@path` 将相对当前正在回复的智使解析）；其下拉菜单漂浮在面板 **之上**，在其打开时 `↑`/`↓`/`Tab`/`Enter`/`Esc` 将由它接管。
  仪表盘快捷键（`Ctrl+X` 中止，`Ctrl+T` 钉选，`Shift+↑/↓` 重新排序等）在面板开启时优先级依然高于编辑器。
- 当有 **权限 / 请求工具问询** 悬而未决时， `❯ reply` 行隐藏，选项将被列出： **`↑`/`↓` 移动高亮的选项**（标记为 `▸`）并用 **`Enter` 回答** 选项。
  **`1`–`9`** 依旧能够直接回答选项。（回答时，方向键只挑选项，不切换智使。）
- **自由文本行** 接受内联输入答案（跟聊天面板一致）：即权限的 **"No" / 拒绝** 选项 ("不，拒绝 (打字以添加反馈)") 以及请求工具的 **"Other"** 选项 ("其他 (打字写下自己的回答)")。在上方输入并按 `Enter` 将发送带有消息的拒绝 / 自由文本答案。
- 这也涵盖了智使的 **向用户请求工具** (`AskUserQuestion`)：它的选项和 "Other" 行将在窥视面板中出现，按照同样的方式回答。
  **多重提问** 表单被逐个步行回答——有一个 `(i/N)` 的标记显示进度，每次回答将进入下一问，最后一次提问提交。（那些含有 **多项选择** 题目的表单将被留给该智使自身的视图——打开这名智使去回答那些题）。

面板仅在终端足够高时渲染；在较矮的终端，即便选中了一行，分发框依旧显示。

## 搜索 / 过滤 (`Ctrl+/`)

过滤机制被放置在显式的 **搜索模式** 后，使得正常的输入始终是指向任务分发。按 `Ctrl+/` 进行切换：提示前缀从 `❯` 变为黄色的 `Search:` 并且您的每一次按键会即时对各行进行过滤。

在搜索模式内：

- `Enter` — **确认**：保持过滤已应用并返回分发提示框（这些行保持被过滤状态；稍后按下 `Esc` 可以清除过滤）。
- `Esc` 抑或是 `Ctrl+/` — **取消**：清除过滤器并退出搜索。
- `↑` / `↓` — 导航已被过滤的行。

查询支持之前的同样前缀（现在仅在搜索模式*内部*生效）：

- `a:<name>` — 按智使标签过滤（不区分大小写子字符串，匹配人设/角色）。
- `s:<state>` — 按行的状态过滤。接受 `working`, `idle`, `completed`, `failed`, `needs-input`, `blocked` 以及其同义词 (`busy`/`running`/`done`/等)。
- `#<text>` — 按 `#<text>` 子字符串进行匹配（匹配标签中的字面字符 `#` ；预留给日后 PR 过滤使用）。
- 任何其它内容 — 针对标签加上工作目录执行朴素的子字符串匹配。

## 恒定持久化

针对每个用户的控制面板偏好存在于 `~/.codel/config.toml` 下的 `[dashboard]` 中：

```toml
[dashboard]
enabled = true
grouping = "state"   # 抑或 "directory"
pinned   = ["top:<session_id>", "sub:<parent_session_id>:<child_session_id>"]
reorder  = ["top:<session_id>"]
```

钉选/重新排序条目由 **session id (会话 ID)** 作为键，而不是按进程的 `AgentId(usize)` 记录，以便它们能够幸存于重启并在之后也不至于附着在那巧合接下了旧槽位编号的其它智使之上。

设置 `CODEL_AGENT_DASHBOARD=0` 即可在 pager 的单次执行生命期中强制禁用这一功能；斜杠命令以及 CLI 子命令会打印一段友好的提示通知。
