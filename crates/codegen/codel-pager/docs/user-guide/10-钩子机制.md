# 钩子机制（Hooks）

钩子（Hook）允许你在 Codel 会话的关键时刻运行脚本或发送 HTTP 请求。使用钩子可以实现任务自动化、强化学性安全检查、记录日志活动、发送通知以及集成你自己的工具链。

---

## 什么是钩子？

钩子是一个 Shell 命令或 HTTP 终端节点，当特定的生命周期事件发生时 Codel 会自动调用它。钩子可以：

- **拦截并阻止操作** -- `PreToolUse` 钩子可以在高危命令运行前予以拒绝拦截。
- **保持 Agent 继续工作** -- `Stop` 钩子可以阻止 Agent 结束当前轮次，直到满足特定条件（例如测试套件通过），并将原因反馈给模型。
- **响应事件** -- `PostToolUse` 钩子可以将每次工具调用的执行记录保存到文件。
- **初始化上下文环境** -- `SessionStart` 钩子可以导出环境变量或运行初始化脚本。

---

## 常见使用场景

- **安全防护**：在诸如 `rm -rf /` 等高危命令运行前予以拦截。
- **审计日志记录**：将工具使用和会话情况记录到文件或外部服务中。
- **通知提醒**：当任务完成时发送消息通知。
- **自动代码格式化**：在编辑文件后自动运行 `cargo fmt` 或 `prettier`。
- **环境初始化**：在会话启动时导出环境变量。
- **自定义工作流**：在特定事件发生时触发构建、测试或部署。

## 快速上手

1. 创建钩子目录：

   ```sh
   mkdir -p ~/.codel/hooks
   ```

2. 创建一个钩子配置文件，例如 `~/.codel/hooks/session-start.json`：

   ```json
   {
     "hooks": {
       "SessionStart": [
         {
           "hooks": [
             { "type": "command", "command": "echo 'Codel session started in '$(pwd)" }
           ]
         }
       ]
     }
   }
   ```

3. 启动（或重启）Codel 会话。钩子会在 `SessionStart` 事件时自动运行。

4. 在非 VS Code 系列终端上按 `Ctrl+L`（或在任意终端运行 `/hooks` —— 在 VS Code 系列中推荐）并查看 Hooks 标签页以确认其已成功加载。

## 钩子存放位置

钩子从以下多个位置自动发现（所有位置的钩子会被合并）：

| 作用域 | 路径 | 是否受信任？ | 说明 |
|-------|------|----------|-------|
| 全局 | `~/.codel/hooks/*.json` | 始终受信任 | 个人配置的钩子 |
| 全局 | `~/.claude/settings.json` (及 `settings.local.json`) | 始终受信任 | Claude Code 兼容性（可配置） |
| 全局 | `~/.cursor/hooks.json` | 始终受信任 | Cursor 兼容性（可配置） |
| 项目 | `<project>/.codel/hooks/*.json` | 需要显式信任 | 按仓库定制的自动化 |
| 项目 | `<project>/.claude/settings.json` (及 `settings.local.json`) | 需要显式信任 | Claude 兼容性（可配置） |
| 项目 | `<project>/.cursor/hooks.json` | 需要显式信任 | Cursor 兼容性（可配置） |
| 插件 | 已安装插件内部内置 | 按插件划分 | 团队共享钩子 |

Claude 与 Cursor 的钩子来源默认会被自动扫描。若要禁用针对特定厂商的自动扫描，请在 `~/.codel/config.toml` 中设置 `[compat.<vendor>] hooks = false` 或设置对应的环境变量。参阅[系统配置](05-系统配置.md#harness-工具链兼容性)获取详情。

**信任项目：** 首次打开带有钩子的项目时，必须显式授权信任项目后其钩子才会运行 -- 在此之前它们会被静默跳过。运行 `/hooks-trust`（或带着 `--trust` 启动）以授予信任；该决定记录在统一的文件夹信任存储库（`~/.codel/trusted_folders.toml`）中，这与管控仓库本地 MCP/LSP 服务器是同一个门控。位于 `~/.codel/hooks/` 中的全局钩子始终受信任，无需记录。这可以防止未受信任的仓库运行任意代码。

因为钩子被统一收拢在文件夹信任机制下，所以通过 `--trust` / `/hooks-trust` 授权信任会同时信任该文件夹下的 **MCP、LSP 以及 Hooks**，并级联应用于子目录。反之，禁用文件夹信任（设置 `CODEL_FOLDER_TRUST=0` 或 `[folder_trust] enabled = false`）会放开项目钩子连同 MCP/LSP 的门控。

## 钩子事件清单

| 事件名称 | 触发时机 | 是否具备阻塞拦截能力？ |
|-------|---------------|-----------|
| `SessionStart` | 会话启动时。 | 否 |
| `UserPromptSubmit` | 提交 Prompt 时。 | 否 |
| `PreToolUse` | 工具即将运行前。 | 是 — 可予以拒绝拦截 |
| `PostToolUse` | 工具成功执行完毕。 | 否 |
| `PostToolUseFailure` | 工具执行失败。 | 否 |
| `PermissionDenied` | 权限系统拒绝工具调用时。 | 否 |
| `Stop` | Agent 轮次因正常完成而结束（非用户手动中断）。 | 是 — 可阻止停下 |
| `StopFailure` | 轮次因 API 错误而结束。 | 否 |
| `Notification` | Agent 发送通知时。 | 否 |
| `SubagentStart` | 子 Agent 启动时。 | 否 |
| `SubagentStop` | 子 Agent 轮次结束时（在子 Agent 中触发一次，具备停下决策控制能力）。 | 是 — 可阻止停下 |
| `PreCompact` | 对话历史即将在进行压缩前。 | 否 |
| `PostCompact` | 对话历史压缩完成。 | 否 |
| `SessionEnd` | 会话结束时。 | 否 |

`SubagentEnd` 作为 `SubagentStop` 的别名被接受。`PreToolUse` 可以阻止工具调用，`Stop`/`SubagentStop` 可以阻止 Agent 停止（参阅 [Stop 决策控制](#stop-决策控制)）；其他所有事件均是被动的。

### Cursor 钩子兼容性

Codel 接受 Cursor 的驼峰（camelCase）钩子事件名称，因此 `~/.cursor/hooks.json` 无需修改即可直接加载：

| Cursor 事件 | 映射为 Codel 事件 |
|---|---|
| `sessionStart`, `sessionEnd` | `SessionStart`, `SessionEnd` |
| `preToolUse`, `postToolUse`, `postToolUseFailure` | `PreToolUse`, `PostToolUse`, `PostToolUseFailure` |
| `beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile` | `PreToolUse` |
| `afterShellExecution`, `afterMCPExecution`, `afterFileEdit` | `PostToolUse` |
| `afterAgentResponse`, `afterAgentThought` | `PostToolUse` |
| `beforeSubmitPrompt` | `UserPromptSubmit` |
| `subagentStart`, `subagentStop` | `SubagentStart`, `SubagentStop` |
| `preCompact`, `stop` | `PreCompact`, `Stop` |

Cursor 针对单操作的钩子（`beforeShellExecution`、`afterFileEdit` 等）映射为通用的 `PreToolUse`/`PostToolUse` 事件。钩子脚本在 JSON 输入中接收工具名称并可据此过滤，或使用 `matcher` 匹配器。

## 钩子 JSON 配置格式

每个 `.json` 文件可以为多个事件定义钩子：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "bin/safety-check.sh", "timeout": 10 }
        ]
      }
    ],
    "PostToolUse": [
      {
        "hooks": [
          { "type": "command", "command": "bin/log-activity.sh" }
        ]
      }
    ]
  }
}
```

### 关键配置字段

- **事件名称**（顶层 key）：[钩子事件清单](#钩子事件清单)中列出的任意事件。Codel 会跳过无法识别的事件名称，因此共享的 Claude 或 Cursor 配置文件依然可以正常加载。
- **matcher**（可选）：用于选择触发该钩子的调用的正则表达式。具体匹配对象取决于事件类型：工具事件（`PreToolUse`、`PostToolUse`、`PostToolUseFailure`、`PermissionDenied`）匹配工具名称，`Notification` 匹配通知类型，`SubagentStart`/`SubagentStop` 匹配子 Agent 类型（如 `explore`），`SessionStart` 匹配启动来源（`startup`、`resume`等），`SessionEnd` 匹配结束原因，`PreCompact`/`PostCompact` 匹配触发原因（`manual` 或 `auto`），`StopFailure` 匹配错误类型（`rate_limit`、`authentication_failed`、`invalid_request`、`server_error`、`max_output_tokens` 或 `unknown`）。`Stop` 或 `UserPromptSubmit` 上的 matcher 会被忽略并发出警告（这些事件总是触发）。空或省略 matcher 则匹配所有调用。matcher 匹配真实的工具名称；通过内部 `use_tool` 调度器路由的 MCP 调用将显示为限定名称 `server__tool`（如 `linear__save_issue`），因此请对此名称进行匹配，而非调度器名称。
- **type**：`"command"`（运行脚本或 Shell 单行指令）或 `"http"`（将事件 POST 到某个 URL）。
- **command**：可执行文件路径（相对于该 JSON 文件）或内联 Shell 命令。
- **timeout**：超时终止钩子的秒数（默认：5 秒；针对 `Stop`/`SubagentStop` 门控默认为 600 秒，与 Claude Code 一致）。所有钩子失败（超时、崩溃、格式错误的输出、缺失必要的环境变量）均遵循**默认放行（fail-open）**原则：失败会被记录并展示在 UI 滚动历史中，但不会阻止工具调用。只有钩子返回显式的 `deny` 决策才会阻止工具调用。

### 工具名称别名

在 `matcher` 中，Codel 会将 Claude 风格的工具名称映射为其原生工具名称，以便从 Claude 迁移过来的钩子能正确触发。常见的别名包括：

- `Bash` → `run_terminal_command`
- `Read` → `read_file`
- `Edit`、`Write` 与 `MultiEdit` → `search_replace`
- `Grep` → `grep`
- `Glob` 与 `ListDir` → `list_dir`
- `WebSearch` → `web_search`
- `Task` → `spawn_subagent`

matcher 也会保留其原始名称，因此 `Bash` 会同时匹配 `Bash` 和 `run_terminal_command`。

## 编写钩子脚本

### 输入规范

事件作为 JSON 数据通过 **stdin** 发送（例如 `PreToolUse` 事件；载荷中始终包含 `toolUseId` 与 `toolInputTruncated`）：

```json
{
  "hookEventName": "pre_tool_use",
  "sessionId": "abc-123",
  "cwd": "/Users/you/project",
  "workspaceRoot": "/Users/you/project",
  "permissionMode": "default",
  "toolName": "run_terminal_command",
  "toolInput": { "command": "npm test" },
  "timestamp": "2026-04-14T12:00:00Z"
}
```

每个事件都包含相同的通用字段：`hookEventName`、`sessionId`、`cwd`、`workspaceRoot`、`timestamp` 以及 `permissionMode`（`default`、`auto`、`plan` 或 `bypassPermissions`），加上像上述 `toolName` 这样的事件专属字段。

### 输出规范（阻塞拦截类钩子）

对于 `PreToolUse` 钩子，将 JSON 写入 **stdout**：

- **允许 (Allow)**：`{"decision": "allow"}`
- **拒绝 (Deny)**：`{"decision": "deny", "reason": "检测到不安全的命令"}`

### 退出码说明

| 退出码 | 含义 |
|-----------|---------|
| `0` | 成功 / 允许（适用于阻塞类钩子） |
| `2` | 显式拒绝（`PreToolUse`）或阻止停止并将 stderr 作为反馈（`Stop`/`SubagentStop`） |
| 其他 | 默认放行 (Fail-open) — 失败会被记录但不会产生阻塞。对于 `PreToolUse`，只要 stdout JSON 中包含 `deny` 决策，无论退出码为何都会生效。对于 `Stop`/`SubagentStop`，stdout 上有效的决策 JSON 优先于退出码（与 Claude Code 一致）；只有在 stdout 没有可用 JSON 时退出码才起决定作用，此时退出码 2 会将 stderr 作为反馈并进行阻止。 |

### Stop 决策控制

`Stop` 和 `SubagentStop` 钩子在 Agent 即将完成其轮次时运行，并且可以使其保持继续工作（与 Claude Code 兼容）。将 JSON 写入 **stdout**：

- **阻止停止**：`{"decision": "block", "reason": "测试套件尚未运行"}`。该原因会作为用户消息反馈给模型，Agent 会在同一个轮次中继续运行下一轮。
- **非错误反馈**：`{"hookSpecificOutput": {"hookEventName": "Stop", "additionalContext": "结束前请运行 linter check"}}`。同样保持 Agent 继续工作，但会作为钩子反馈展示，而非钩子错误。
- **强制停止**：`{"continue": false, "stopReason": "预算用尽"}`。结束该轮次，覆盖任何阻止。
- **允许停止**：退出码 0 且无输出（或输出非 JSON 内容）。

以退出码 `2` 退出也会阻止停止，并将 **stderr** 内容作为反馈。

钩子输入中包含 `stopHookActive` 与 `lastAssistantMessage`。当 Agent 在本轮中已经因为先前的停止钩子阻止而继续运行时，`stopHookActive` 为 true；请检查它或对话转录，以防在永远无法满足的条件上无限阻止。`lastAssistantMessage` 包含 Agent 在本轮中的最终响应文本，因此钩子无需解析转录即可对其进行操作。在单个轮次中进行 **8 次连续工作**（阻止或非错误反馈）后，门控会被覆盖且轮次强制结束；对于该最终的强制停止将不会再咨询钩子。计数器按轮次计算：下一个用户 Prompt 会重新开始，因此长运行目标可以跨越多个轮次。钩子失败遵循默认放行原則：Agent 会正常停止。

`Stop` 和 `SubagentStop` 钩子默认超时时间为 600 秒（与 Claude Code 一致），因为门控通常会运行构建或测试套件，而超时的钩子遵循默认放行原则，因此 Agent 无论如何都会停止。其他事件保持 5 秒的默认超时值。当门控需要更多时间时可显式设置 `timeout`：`{ "type": "command", "command": "bin/verify.sh", "timeout": 1200 }`。

门控仅在真正的正常完成时触发。手动中断（Esc / Ctrl+C）、拒绝以及达到最大轮次的情况会彻底跳过 Stop 钩子，而 API 错误轮次则会触发 `StopFailure`。在会话结束时还会触发一次独立的 Stop（`reason: "channel_closed"` 或 `"shutdown"`）；其决策输出会被解析但会被忽略，因为已经没有剩余轮次可以继续了。统计或控制 Stop 触发的脚本应该检查 `reason == "end_turn"`，以免会话结束时的触发造成干扰。

`StopFailure` 仅用于观察记录（用于记录失败或发送告警；其输出和退出码会被忽略）。其输入包含 `error`（匹配器测试的分类类型，采用 Claude Code 词汇：`rate_limit`、`authentication_failed`、`invalid_request`、`server_error`、`max_output_tokens` 或运行时无法区分时的 `unknown`；容量错误归入 `rate_limit`，且没有针对 `billing_error` 的信号）、`errorDetails`（原始错误详情，可用时）以及 `lastAssistantMessage`（对话中渲染展示的错误文本；对于此事件，它是错误字符串而非助手输出）。

`Stop` 输入还包含 `backgroundTasks` 和 `sessionCrons`，因此钩子可以区分“会话已完成”与“会话正处于暂停状态并等待后台任务将其唤醒”。当没有正在进行或调度的任务时，这两个数组均为空。每个 `backgroundTasks` 条目描述一个正在进行的任务：`id`、`type`（`shell`、`monitor` 或 `subagent`）、`status` 以及（取决于类型）`command`（仅限 shell 任务）、`description`（monitor 监控的命令行，或子 Agent 的任务描述）和 `agentType`（子 Agent）。每个 `sessionCrons` 条目描述一个调度的唤醒任务（`scheduler_create` 或 `/loop`）：`id`、`schedule`、`recurring` 和 `prompt`。`schedule` 的值是人类可读的时间间隔，例如 `every 5 minutes`；codel 的调度是时间间隔，而非 cron 表达式。自由文本输入字段最多截取 1000 个字符，并附带字符串内的 `… [+N chars]` 标记。

在子 Agent 内部，门控作为 `SubagentStop` 触发（Agent 前言中的 `Stop` 钩子会被自动重新映射）。`Stop` 钩子仅阻揽主 Agent。

`SubagentStop` 在子 Agent 自身的轮次结束时为每个子 Agent 触发一次，与 Claude Code 一致。其输入包含一个保留用于前向兼容的 `phase` 字段（目前始终为 `"gate"`）。

**迁移 Claude Code 停止钩子**：输出词汇（`decision`、`reason`、`continue`、`stopReason`、`additionalContext`）保持不变。请检查以下与 Claude 不一致的区别：

- **驼峰命名 (camelCase) 输入**：codel 的 stdin 格式全面使用 camelCase 字段名，而 Claude 使用 snake_case。读取 `.stop_hook_active`、`.hook_event_name` 或 `.background_tasks[].agent_type` 的脚本必须切换为 `.stopHookActive`、`.hookEventName` 和 `.backgroundTasks[].agentType`（事件值为 `"stop"`）。通过 codel-agent-sdk 注册的钩子会将顶层字段和 `backgroundTasks`/`sessionCrons` 条目字段均转换为 snake_case，因此传输层中的 `.backgroundTasks[].agentType` 在 SDK 中可读取为 `.background_tasks[].agent_type`。
- **`toolResult` 字段**：`PostToolUse` 的工具输出为 `toolResult`（SDK 中为 `tool_result`），而非 Claude 的 `tool_response`；读取 `.tool_response` 的脚本必须切换为 `.toolResult`。
- **会话结束触发**：在会话结束时会多触发一次仅供观察的 Stop；请针对 `reason == "end_turn"` 进行过滤（见上文）。
- **时间间隔调度**：`sessionCrons[].schedule` 为人类可读的时间间隔，绝非 cron 表达式。
- **任务类型**：`backgroundTasks[].type` 仅能为 `shell`、`monitor` 或 `subagent`；不会输出 Claude 的其他标签（`workflow`、`teammate` 等）。
- **StopFailure 分类**：输出集采用 Claude Code 词汇 —— `rate_limit`、`authentication_failed`、`invalid_request`、`server_error`、`max_output_tokens`、`unknown`。codel 输出一个子集：容量错误（503/529）像 Claude 一样归入 `rate_limit`，且绝不输出 `billing_error`（无对应信号），因此 `billing_error` 匹配器不会触发。
- **permission_mode 值**：codel 输出 `default`、`auto`、`plan` 或 `bypassPermissions`。Claude 的 `acceptEdits`/`dontAsk` 没有 codel 的直接对应项（codel 的 `auto` 最为接近），因此像 `permission_mode === "acceptEdits"` 这样的检查绝不会匹配成功。
- **客户端 (SDK) 门控超时时间**：SDK 的 `Stop`/`SubagentStop` 门控默认超时时间像文件钩子一样为 600 秒；`PreToolUse` 客户端门控默认超时时间为 30 秒（交互式热路径）。两者均可在每个匹配器组中通过 `timeoutS` 进行覆盖，上限为 600 秒。
- **`/goal`**：codel 的目标循环是在停止门控之前运行的独立功能；它不是 Prompt 类型的 Stop 钩子。

单个脚本中的完整保持工作策略：

```bash
#!/bin/bash
input=$(cat)
# 仅针对真正的轮次结束进行门控拦截，忽略会话结束时的观察触发。
if [ "$(echo "$input" | jq -r '.reason')" != "end_turn" ]; then exit 0; fi
if ! bin/verify.sh >/dev/null 2>&1; then
  echo '{"decision": "block", "reason": "verify.sh 失败；在结束前请先修复失败项目"}'
fi
```

注册为 `{ "type": "command", "command": "bin/stop-gate.sh", "timeout": 300 }`，其中 `timeout` 根据校验步骤所需时间进行设置。钩子会在每次继续后再次触发，内置的上限会在 8 次后结束该轮次；检查 `stopHookActive` 可以在 Agent 明显无法对其做出响应的反馈上提早放弃。

### 被动型钩子

对于像 `SessionStart` 或 `PostToolUse` 这样的事件，stdout 会被忽略。只需在成功时以退出码 0 退出即可。

### 环境变量

Codel 会为每个钩子进程设置多个环境变量。在编写感知上下文或感知插件的钩子脚本时非常实用。

#### 运行器注入的环境变量（始终可用）

这些变量由钩子运行器为**每一个**钩子进行设置：

| 变量名 | 描述 |
|-----------------------|-------------|
| `CODEL_HOOK_EVENT` | 触发该钩子的事件名称（例如 `pre_tool_use`、`session_start`、`post_tool_use`、`session_end`、`stop`、`notification`）。 |
| `CODEL_HOOK_NAME` | 该特定钩子的配置名称（对于插件提供的钩子，包含插件前缀）。 |
| `CODEL_SESSION_ID` | 当前 Codel 会话的唯一标识符。 |
| `CODEL_WORKSPACE_ROOT` | 当前工作区根目录的绝对路径。 |
| `CLAUDE_PROJECT_DIR` | 工作区根目录的绝对路径。`CODEL_WORKSPACE_ROOT` 的兼容 Claude Code 的别名，为每一个钩子设置。 |

这些变量是**保留项**。你试图在钩子 JSON 的 `env` 字段中为它们设置的任何值都会在加载时被清理（并记录警告），运行器在启动时总是注入真实的值。

#### 插件钩子环境变量

当钩子来源于某个插件时，Codel 还会额外注入以下变量：

| 变量名 | 描述 |
|----------------------|-------------|
| `CODEL_PLUGIN_ROOT` | 插件安装目录的绝对路径。 |
| `CODEL_PLUGIN_DATA` | 插件可写数据目录的绝对路径（用于存储插件状态、缓存等）。 |

这些值由插件系统提供。对于四个插件相关的 key（`CODEL_PLUGIN_ROOT`、`CODEL_PLUGIN_DATA` 及其 Claude 别名），插件适配器会确保官方的插件值总是优先于钩子 `env` 映射中由用户声明的任何值。

#### 用户自定义环境变量

你可以使用 `env` 字段为单个钩子处理程序提供额外的环境变量：

```json
{
  "type": "command",
  "command": "bin/my-hook.sh",
  "env": {
    "MY_SECRET": "value",
    "LOG_LEVEL": "debug"
  }
}
```

这些变量会被透传给钩子进程，但它们无法覆盖上述列出的保留运行器或插件变量。

#### 在 `command` 和 `url` 字段中使用环境变量

`command` 与 `url` 均支持 `${VAR}` 和 `$VAR` 路径展开。

## HTTP 类型的钩子

除了本地脚本外，还可以调用远程终端节点：

```json
{ "type": "http", "url": "https://hooks.example.com/codel-event", "timeout": 15 }
```

完整的事件信封数据将作为 JSON 通过 POST 发送。

## 在 TUI 中管理钩子

### Hooks 标签页

在非 VS Code 系列终端上按 `Ctrl+L` 打开扩展模态框（Plugins 标签页），或运行 `/hooks`（任意终端；在 VS Code 系列上必须使用，因为 `Ctrl+L` 用于插话）在 Hooks 标签页上打开它。在 **Hooks** 标签页中：

| 按键 | 操作 |
|-----|--------|
| `r` | 从磁盘重新加载所有钩子 |
| `a` | 通过路径添加自定义钩子 |
| `x` | 移除选中的钩子来源（会要求确认；按小写 `y` 确认） |
| `Space` | 启用或禁用选中的钩子 |
| `f` | 循环切换状态过滤器（全部 / 已启用 / 已禁用） |

钩子按来源分组展示：**Global**（全局）、**Project**（项目）、**Plugin**（插件）以及 **Custom**（自定义）。

每个钩子均显示：
- 触发它的 **事件**
- 运行的 **命令** 或 **URL**
- **超时** 时间
- **状态** -- 启用或 `[disabled]`

### 斜杠指令

```
/hooks-list           # 显示在本会话中加载的钩子
/hooks-trust          # 信任此项目以执行钩子
/hooks-add <path>     # 添加自定义钩子文件或目录
/hooks-remove <path>  # 移除自定义钩子
/hooks-untrust        # 撤销对此项目的信任
```

在 TUI Pager 中，单独的 `/hooks-*` 指令不会显示在斜杠指令列表中。`/hooks` 模态框涵盖了列出、添加、移除以及启用或禁用钩子；项目信任通过 `/hooks-trust`（或模态框的 Trust 操作）进行管理，它会写入上述统一的文件夹信任存储库中。

### 单钩子级别的启用/禁用

在运行期间，在 Hooks 标签页中按 `Space`（空格键）可以启用或禁用单个钩子。修改会控制立即生效，无需重启会话。

### 会话中途重新加载

在 Hooks 标签页中按 `r` 键可以从磁盘重新加载所有钩子。Codel 会重新读取每个钩子来源，因此这会拾取你在会话期间对钩子文件做出的修改。

## 示例：安全的 Shell 防护钩子

拦截不安全的 Shell 命令：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "bin/safe-shell.sh", "timeout": 5 }
        ]
      }
    ]
  }
}
```

其中 `bin/safe-shell.sh` 的内容：

```bash
#!/bin/sh
INPUT=$(cat)
CMD=$(echo "$INPUT" | jq -r '.toolInput.command // empty')

# 拦截破坏性命令模式
if echo "$CMD" | grep -qE '(rm -rf /|mkfs|dd if=|:(){ :|& };:)'; then
  echo '{"decision": "deny", "reason": "已拦截可能带有破坏性的命令"}' 
  exit 2
fi

echo '{"decision": "allow"}'
```

## 安全注意事项

- 全局钩子（`~/.codel/hooks/`）以你用户的权限运行 -- 请像对待 Shell 脚本一样谨慎对待它们。
- 项目钩子需要文件夹信任（`/hooks-trust` 或 `--trust`，与仓库本地 MCP/LSP 为同一个门控），以防止恶意仓库的供应链攻击。
- HTTP 类型的钩子会发送会话数据 -- 请仅使用受信任的终端节点。

---

## 最佳实践

1. **保持钩子运行高效快速** -- 长时间运行的钩子会阻塞 UI。尽量使用后台进程（`&`）或异步方式。
2. **使用显式的 `deny` 进行拦截** -- 钩子在出现任何错误时均遵循默认放行原则，因此崩溃的钩子不会阻塞工具。要强制执行策略，你的钩子必须运行直至完成并在 stdout 上输出 `{"decision":"deny","reason":"..."}`。请始终在脚本内部处理错误，以便其能返回显式的决策。
3. **使用绝对路径或相对于钩子文件的相对路径** -- 在 JSON 文件旁的 `bin/` 中的脚本最具可移植性。
4. **使用模态框进行测试** -- 在依赖它们之前，按 `Ctrl+L`（非 VS Code 系列）或运行 `/hooks` 以验证钩子已被成功加载和匹配。
5. **对项目钩子进行版本控制** -- 将 `.codel/hooks/` 提交到 Git（但绝不要提交敏感密码/密钥）。

## 故障排查

- **钩子没有运行？** 在非 VS Code 系列上按 `Ctrl+L`（或在任意终端运行 `/hooks`）以查看其是否已被加载并匹配。
- **项目钩子被忽略？** 项目文件夹可能未受信任。运行 `/hooks-trust`（或带着 `--trust` 重新启动）。
- **未找到脚本？** 检查路径是否相对于 `.json` 文件且具备可执行权限（`chmod +x`）。
- **看到错误信息？** 带着 `RUST_LOG=debug CODEL_LOG_FILE=/tmp/codel.log codel` 启动以捕获日志，然后检查 `/tmp/codel.log`。
