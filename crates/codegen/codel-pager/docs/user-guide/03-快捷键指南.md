# 快捷键指南

本文档为 Codel Build TUI 界面中的快捷键参考说明。内置快捷键目前不支持重新映射。

---

## 输入模式

Codel 提供了两种控制滚动历史（Scrollback）浏览与导航的输入模式：

- **简单模式**（默认）：使用方向键导航，`Shift+方向键` 在轮次间跳转，`Space` 聚焦输入框，按任意字母键会自动聚焦输入框并开始输入。
- **Vim 模式**（需手动开启）：使用 `j`/`k` 导航，`H`/`L` 在轮次间跳转，`J`/`K` 在模型响应间跳转，`h`/`l` 折叠/展开，`e`/`E` 切换折叠状态/展开全部，`i`/`Tab`/`Space` 聚焦输入框。

简单模式默认处于激活状态。如需切换到 Vim 模式，请在 `~/.codel/config.toml` 的 `[ui]` 部分设置 `vim_mode = true`，或在运行时通过 `/vim-mode` 快捷命令切换。详情参阅[系统配置](05-系统配置.md)。

下表记录了两种模式下的快捷键绑定。"按键"列显示 Vim 模式的按键绑定，"备选按键"列显示简单模式下的对应按键（方向键等）。

> **需要 Vim 模式**：在**滚动历史（Scrollback）**上下文中，单字母及 `Shift+字母` 绑定（`j/k`、`h/l`、`g/G`、`L/H`、`y/Y`、`o/O`、`r`、`x`、`e/E` 以及 `i` 进入插入模式备选键）需要在 `~/.codel/config.toml` 中配置 `[ui].vim_mode = true`（或通过 `/vim-mode` 切换）。方向键、`Tab`、`Esc`、`Space`、`PageUp/Down` 以及所有 `Ctrl+字母` 快捷键在两种模式下均可正常工作。

| `⇧K` | | 跳转到上一条助手响应 |
| `g` | | 跳转到滚动历史顶部 |
| `⇧G` | | 跳转到滚动历史底部 |

|-----|---------|--------|
| `h` | `Left` | 折叠选中的条目 |

| `⇧E` | | 展开全部 / 折叠全部条目 |

## 焦点切换

在输入框与滚动历史面板之间切换焦点。

| 按键 | 备选按键 | 上下文 | 操作 |
|-----|---------|---------|--------|
| `Tab` | `Space`（Vim 模式下包含 `i`） | 聚焦滚动历史 | 聚焦到 Prompt 输入框 |
| `Tab` | | 聚焦 Prompt 输入框 | 聚焦到滚动历史（简单模式和 Vim 模式通用） |
| `Enter` | | 聚焦 Prompt 输入框 | 发送当前 Prompt |

**Esc 不是焦点切换键。** 它遵循下述取消 / 清除 / 撤销语义。只有运行过程中的取消这一分支受 `[ui].vim_mode` 控制（滚动历史导航）；没有逻辑依赖 `[ui].simple_mode`（Prompt 编辑器）。覆盖层、模态框、斜杠/文件下拉框、语音、搜索及文本选中依然优先拦截 Esc。

## Esc 键逻辑

| 状态 | 触发手势 | 效果 |
|--------|---------|--------|
| 轮次运行中，**极简模式或 Vim 滚动历史模式关闭（默认）** | `Esc` | 立即取消（无论焦点在输入框还是滚动历史，即使存在草稿也会**予以保留**，与 Ctrl+C 先清除草稿的手势不同）。 |
| 轮次运行中，**全屏 Vim 模式** | `Esc` | 空操作（**不会**取消）。请使用 `Ctrl+C`（或命令面板/其他取消入口）。 |
| 轮次正在取消中 | `Esc` | 在**所有**模式下重新发送取消指令（若第一次确认丢失可进行重试）。在此状态下按 `Ctrl+C` 会升级为退出程序。 |
| 空闲 + Prompt 非空（文本或图片碎片），**聚焦 Prompt** | **800ms 内连按 2 次 `Esc`** | 清空 Prompt；非空文本将保存至输入历史。第一次按下时提示“再次按下以清空”。 |
| 空闲 + Prompt 为空 + 包含对话消息，**聚焦 Prompt 或滚动历史** | **800ms 内连按 2 次 `Esc`** | 打开撤销选择器（与 `/rewind` 效果相同）。第一次按下静默无提示。 |
| 空闲 + 为空 + 无消息，**或聚焦滚动历史且带有草稿 / 带有模式 (`!` `#` 反馈) 的编辑框 / 待处理的交互模态框 / 打开的历史搜索** | `Esc` | 空操作（不会聚焦滚动历史）。清空草稿仅限输入框面板；撤销要求编辑器处于空的 Normal 模式、无待处理模态框且无打开的历史搜索 —— 浏览滚动历史绝不会改变你的草稿、编辑模式、等待回答的问题或进行中的搜索。 |

**取消后的宽限期：** 由 Esc 触发取消后的大约 1 秒内，空闲撤销触发机制会被抑制 —— 连续快速按 Esc 停止轮次不会意外打开撤销选择器。仅抑制撤销触发，其他所有 Esc 行为不受影响。

**优先拦截 Esc（在轮次中取消/忽略以及清空/撤销之前执行）：** 覆盖层、模态框、斜杠/文件/补全下拉菜单、历史搜索、滚动历史搜索、文本选择、链接高亮、语音以及当 Prompt 为空时的 **Bash / Remember 模式退出**（Esc 会离开 `!` / `#` 模式并返回普通 Prompt —— 即使在轮次运行时也有效）。

**Ctrl+C 与 Esc 的对比：** 当轮次运行中且存在非空草稿时，Ctrl+C 会清空草稿并保持轮次运行；在空 Prompt 上再次按 Ctrl+C 则取消轮次。Esc 会立即取消并保留草稿（在全屏 Vim 模式下它不会取消 —— 仅在取消过程中进行重试）。空闲非空时按 Ctrl+C 一次即可清空；Esc 则需要在 800ms 内连按两次。

## Agent 会话级别操作

影响 Agent 会话的操作，可在 Agent 主界面使用。

| 按键 | 上下文 | 操作 |
|-----|---------|--------|
| `Ctrl+P` | Agent 界面 | 打开命令面板 |
| `?` (Shift+/) | Agent 界面 | 打开命令面板（备选绑定） |
| `Ctrl+M` | Agent 界面 | 打开模型选择器 / 切换模型 |
| `Ctrl+M` | 聚焦 Prompt | 切换多行输入模式 |
| `Ctrl+C` | Agent 界面 | 取消当前轮次（或先清空非空草稿；参阅 Esc 键逻辑表） |
| `Ctrl+O` | Agent 界面 | 切换始终自动批准（YOLO）模式 |
| `Ctrl+S` | Agent 界面 | 打开会话选择器（恢复历史会话） |
| `Ctrl+;`（备选：`Ctrl+'`） | Agent 界面 | 切换 Prompt 队列面板（非空时）。**仅限本地 macOS** VS Code 系列：主快捷键为 **`Ctrl+4`**（`;` / `'` 仍为备选）。SSH 和非 Mac 系统保持 **`Ctrl+;`** / **`Ctrl+'`**。 |
| `Shift+Tab` | 聚焦 Prompt | 循环切换模式（Normal → Plan → Always-approve） |
| `Ctrl+B` | Agent 界面 | 将前台运行中的命令推送到后台 |
| `Ctrl+T` | Agent 界面 | 切换 Todos 面板 |
| `Ctrl+G` | Agent 界面（完整 TUI） | 切换 Task 任务面板 |
| `Ctrl+G` | 普通编辑器（极简模式） | 在外部编辑器中编辑当前草稿而不直接发送。如果终端占用了此组合键，请从命令面板中选择 **Edit Prompt in External Editor**。 |
| `Ctrl+L` | Agent 界面 | 打开扩展模态框（**仅限非 VS Code 系列**；在 VS Code / Cursor / Windsurf / Zed 中，`Ctrl+L` 代表轮次中**插话**，扩展通过 `/plugins` / `/hooks` 打开） |
| `↑` | 聚焦 Prompt（空 Prompt，普通输入模式） | 打开历史面板并填入上一条 Prompt；`↑`/`↓` 遍历历史条目（每条都会填入输入框），在最新条目按 `↓` 将关闭面板，直接打字可以原地编辑调出的 Prompt。调出的 `!` Shell 命令会重新进入 Shell 模式。`↓` 绝不会主动打开历史。 |
| `!` | 聚焦 Prompt | 进入 Shell 模式（在空 Prompt 上输入 `!`） |
| `Ctrl+.`（备选：`Ctrl+X`） | Agent 界面 | 打开快捷键帮助文档 |
| `F2`（备选：`Ctrl+,` / `Cmd+,`） | Agent 界面 | 打开设置模态框 |

**注意：** `Ctrl+M` 依赖于上下文环境。当焦点在 Prompt 输入框时，它用于切换多行模式；否则用于打开模型选择器。

**注意：** 极简模式下的外部编辑会依次解析 `$VISUAL`、`$EDITOR` 以及 `vi`。环境变量值可以包含带引号的参数。保存文件将仅替换草稿；空文件会清空草稿。带有粘贴内容/文件/图片碎片的草稿必须在编辑器中直接修改，以防附件被平铺打散。

**注意：** `Ctrl+'` 是 Windows 上 `Ctrl+;` 的备选组合键 —— 部分 Windows 终端会在标点符号键上丢弃 `Ctrl` 修饰键。

**注意：** `Ctrl+.` 需要 Kitty 键盘协议（或 tmux 设置 `extended-keys on` 以便透传协议）。在 VS Code / Cursor / Windsurf / Zed 集成终端、VTE、Apple Terminal、Windows Terminal、JetBrains、未开启 `extended-keys` 的 tmux、screen 等不支持 KKP 的环境下，Codel 推荐 **`Ctrl+X`** 作为快捷键速查表的主按键。即使 `Ctrl+.` 失效，**`Ctrl+X` 也能作为经典控制字符正常工作**。如果在 tmux 中修改后的按键行为异常，请运行 `/doctor`。

## 图片粘贴与拖拽

| 操作 | macOS | Linux | Windows |
|---|---|---|---|
| 从文件管理器将图片拖入 Prompt | Finder ✓ | Files / Dolphin ✓ | Explorer ✓ |
| 在文件管理器中复制文件，然后粘贴 | `Cmd+V` | `Ctrl+V` | `Ctrl+V` |
| 截图或剪贴板中“复制图片”，然后粘贴 | `Cmd+V` | `Ctrl+V` | **`Alt+V`** |

非图片文件会将绝对路径作为纯文本插入，而非图片碎片。

> **Windows 上的 `Alt+V`** 为 Codel 专属。Windows Terminal 默认的 `Ctrl+V` 仅粘贴纯文本并静默丢弃剪贴板中的图片；`Alt+V` 可绕过拦截器。若想使用 `Ctrl+V` 粘贴图片，请在 Windows Terminal 的 `settings.json` 的 `actions` 中添加 `{ "command": null, "keys": "ctrl+v" }`。

### Linux PRIMARY 与 CLIPBOARD 剪贴板

Linux X11 拥有两个独立的文本选择区：

- `Ctrl+V` 读取 **CLIPBOARD**（显式复制/剪切选择区）。它绝不会退回到 PRIMARY。若要使用 `xclip` 将文本放入该区，请使用 `printf %s "text" | xclip -selection clipboard`。
- 在 Codel 中未修改的鼠标中键点击仅在 `DISPLAY` 非空时读取 **PRIMARY**（当前鼠标选择区）。纯 X11 环境可以使用其原生读取回退；XWayland 需要在 `PATH` 中配备 `xclip` 或 `xsel`，以便 Codel 读取 X11 选择区而非 Wayland PRIMARY。按下操作仅处理一次，松开不会二次粘贴。
- `Shift+Insert` 是终端原生粘贴选中文本的方式。许多终端还支持 `Shift+鼠标中键` 绕过应用程序的鼠标事件上报。

在 SSH 环境下，远程 Codel 进程通常无法访问终端本地的 X11 选择区。请使用终端原生的 `Shift+Insert` 或 `Shift+鼠标中键`，以便本地终端将选中文本通过 PTY 发送。

## 在活跃轮次中（Agent 运行中）

当 Agent 正在生成内容时：

- **普通 `Enter`**（编辑器中有文本）将**排队**后续消息。排队的消息将在当前轮次结束后运行 —— 并且当 Agent 因等待后台任务或子 Agent 而阻塞时，它们会故意**保持**（会有提示说明保持状态以及如何立即发送）。
- **在已清空的编辑器中再次按 `Enter`**（双击 Enter）会立即发送**队首**的排队消息。
- **立即发送**快捷组合键为 **取消并发送**：它会停止当前轮次（后台任务、子 Agent 及其余队列继续运行），并将你的消息作为下一轮次发送，因此它始终出现在转录记录的最底部：
  - **编辑器非空** → 立即取消并发送该文本。
  - **编辑器为空** + 有排队消息 → 立即发送**队首**排队消息（无需聚焦队列面板）。在队列面板上，相同的组合键（或 **[Send now]** 按钮）会发送**当前选中**的行。
  - **空闲状态**，或**编辑器为空且无排队消息** → 该按键为空操作。
- 当 Agent 处于**阻塞等待**状态（等待任务输出或子 Agent）时，带有文本的普通 `Enter` 也会立即交付 —— Shell 会取消被阻塞的轮次并紧接着运行你的消息。

| 终端 | 主快捷键 | 备选快捷键 | 操作 |
|----------|---------|------------|--------|
| 默认 | `Ctrl+Enter` | `Ctrl+I` | 立即发送（取消当前轮次，紧接着运行你的消息） |
| Apple Terminal | `Ctrl+O` | `Ctrl+Enter`, `Ctrl+I` | 立即发送 |
| VS Code 系列 (VS Code, Cursor, Windsurf, Zed) | **`Ctrl+L`** | *(无)* | 立即发送（不使用 `Ctrl+I` —— 避免与 Tab/宿主聊天冲突；插件通过 `/plugins` 打开） |

在 `/multiline` 多行模式下，`Shift+Enter`（或 `Alt+Enter`）用于发送，而普通 `Enter` 插入新行 —— 除非在轮次中且编辑器**为空**且存在排队消息时，普通 `Enter` 仍会**立即发送**队首消息（与普通模式相同）。（在非 VS Code 系列中绑定 `Ctrl+Enter` 可在轮次中立即发送；它不会提交新的空闲轮次。）

“立即发送”设计上具有打断性 —— 语义表达为“停止你正在做的事并优先处理这个”。如果要在**不停止** Agent 的情况下向其传递说明，请使用普通 `Enter` 排队；Agent 会在下一个轮次边界处获取该指令。

> **WezTerm**：这些修改后的 Enter 键需要在你的 WezTerm 配置中设置 `enable_kitty_keyboard = true`。完整步骤及单行变通方案请参阅[终端支持指南](21-terminal-support.md#problem-ctrlenter-doesnt-interject-in-wezterm)。

> **Windows（非 VS Code 系列）**：部分终端控制台会在 `Ctrl+Enter` 上丢弃 `Ctrl` 修饰键（可能退化为普通 `Enter` 或 `Ctrl+J`）。请使用 `Ctrl+I` 作为备选键 —— 字母键组合在所有环境下均稳定可用。在 VS Code 系列中，请使用 **`Ctrl+L`**。

> **VS Code 系列 `Ctrl+L`**：Codel 将其用于插话，并保持扩展快捷键未绑定（通过 `/plugins` 或命令面板打开插件）。如果你的终端配置文件仍将 **Clear**（或其它命令）映射到 `Ctrl+L`，则宿主绑定可能会拦截该组合键 —— 请重新绑定或移除它，以便 PTY 能接收换页符（`\x0c`）。

## 全局快捷键

可在任何屏幕界面使用的操作。

| 按键 | 备选按键 | 操作 | 二次确认 |
|-----|---------|--------|-------------|
| `Ctrl+N` | | 创建新会话（可选在 git worktree 中） | 是（1000ms 内连按两次） |
| `Ctrl+Q` | `Ctrl+D` | 退出应用程序 | 是（1000ms 内连按两次） |

**VS Code 系列终端**（VS Code、Cursor、Windsurf、Zed 集成终端）：`Ctrl+Q` 会被宿主拦截，因此 Codel 将 **`Ctrl+D` 作为唯一的退出快捷键**（未绑定 `Ctrl+Q`）。向下滚动半页重新绑定为单独的 **`Shift+D`**。轮次中插话使用 **`Ctrl+L`**（无备选键），因为 `Ctrl+Enter` / `Ctrl+I` 无法稳定到达 PTY；扩展通过 `/plugins` 打开而非 `Ctrl+L`。

> **返回欢迎界面没有专属快捷键** — 请在会话内部使用 `/home` 斜杠指令（别名 `/welcome`）。参阅[斜杠指令](04-斜杠指令.md)。

### 破坏性操作确认

确认列标记为“是”的操作需要在 1000ms 内连按两次。按一次可查看确认提示，再次按下以确认。这可以防止意外丢弃会话。

## 欢迎界面

仅在欢迎界面（尚未打开任何 Agent 会话前）生效的绑定。

| 按键 | 操作 |
|-----|--------|
| `Ctrl+S` | 恢复会话（打开会话选择器） |
| `Ctrl+W` | 打开新建 Worktree 对话框（仅在 git 仓库内部有效） |
| `Ctrl+I` | 导入 Claude 设置（可用时） |
| `Ctrl+Shift+I` | 忽略 Claude 导入行（可用时） |

`Ctrl+W`、`Ctrl+I` 和 `Ctrl+Shift+I` 仅在欢迎界面激活。`Ctrl+S` 在欢迎界面和 Agent 会话内部均可打开会话选择器（在会话内以模态框形式叠加展示，与 `/resume` 命令一致）。`Ctrl+Q` 与上述全局退出绑定完全相同，非欢迎界面专属。

## 命令面板

按下 `Ctrl+P` 或 `?` 即可打开命令面板 —— 一个可搜索的操作列表。面板展示：

- 所有快捷键及其当前绑定
- 所有斜杠指令
- 可用的技能扩展

打字过滤选项，然后按 `Enter` 执行选中的操作。

---

## 快捷键状态栏

TUI 底部显示上下文快捷键栏，展示与当前状态最相关的按键绑定。提示内容会根据以下条件动态变化：

- 当前聚焦的面板（滚动历史 vs. Prompt）
- Agent 当前是否在运行
- 当前选择的条目类型

---

## 鼠标支持

TUI 支持鼠标交互：

- **点击** 滚动历史条目以选中它
- **滚轮** 浏览滚动历史
- **点击** Prompt 区域以聚焦它
- **悬停** 在 Prompt 上以查看高亮效果（可通过 `pager.toml` 配置）
- **鼠标中键点击**（Linux X11/XWayland）粘贴 PRIMARY 选择区文本

## 快捷键速查卡

### 当聚焦滚动历史时（简单模式 — 默认）

```
导航:             Up/Down (上一条/下一条)  Shift+Left/Right (上一轮/下一轮)
滚动:             Ctrl+J/K (单行)  PgUp/PgDn (整页)  Ctrl+U/D (半页)
聚焦 Prompt:      Space 或任意字母键 (自动聚焦并打字)
```

### 当聚焦滚动历史时（Vim 模式）

```
导航:             j/k (上/下)  H/L (上一轮/下一轮)  K/J (上一条/下一条响应)  g/G (页首/页尾)
滚动:             Ctrl+J/K (单行)  Ctrl+U/D (半页; VSCode 中 D=Shift+D)  PgUp/PgDn (整页)
折叠:             h/l (收起/展开)  e (切换)  E (全部)
内容操作:         y (复制)  Y (复制命令)  Enter (全屏查看)
视图切换:         r (原始 Markdown)  Ctrl+E (思考过程)
聚焦 Prompt:      i, Tab, 或 Space
```

### 当聚焦 Prompt 输入框时

```
发送:             Enter
换行:             Shift+Enter 或 Alt+Enter
多行模式:         Ctrl+M (切换)
粘贴:             Ctrl+V (macOS/Linux 上的文本、文件、截图)
选中文本:         鼠标中键 或 Shift+Insert (Linux X11/XWayland PRIMARY)
粘贴图片:         Alt+V (仅限 Windows — 用于截图 / "复制图片")
全选:             Cmd+A (仅限 macOS Ghostty — 详见下方说明)
离开输入框:       Tab (返回滚动历史)
取消 (运行中):    Ctrl+C (空 Prompt; 非空草稿会先清空)
清空 (空闲):      800ms 内连按 Esc Esc (非空 Prompt)
撤销 (空闲):      800ms 内连按 Esc Esc (空 Prompt + 包含消息)
```

> **Cmd+A 仅限 Ghostty。** Codel 内置的 `Cmd+A` 处理逻辑仅在检测到终端为 Ghostty 时才会生效。其他终端要么在终端层拦截 `Cmd+A`（Apple Terminal、默认 iTerm2），要么应用其自身的“全选”行为（Kitty、WezTerm）。在非 Ghostty 终端上，该绑定不起作用，按键将退回到终端原生行为。
>
> 在 Ghostty 上，将单行解绑配置添加到 `~/.config/ghostty/config`，以便按键能送达运行中的 TUI：
>
> ```ini
> keybind = cmd+a=unbind
> ```
>
> Ghostty 重新加载（它会自动监听配置文件）后，Prompt 中的 `Cmd+A` 将选中 Prompt 缓冲区中的每个字符，包括粘贴的图片碎片。图片碎片始终不包含路径（显示为 `[Image #N]`）；文件路径（如果已知）仅在悬停或光标位于碎片上/碎片后时的图片预览覆盖层中显示。

### 始终可用

```
命令面板:         Ctrl+P 或 ?
模型选择器:       Ctrl+M (在滚动历史面板中)
取消:             Ctrl+C (参阅 Esc 键逻辑表)
始终自动批准:     Ctrl+O (切换 YOLO 模式)
新建会话:         Ctrl+N (再次按下，选择普通/worktree)
退出:             Ctrl+Q (或 VSCode 中为 Ctrl+D)
```
