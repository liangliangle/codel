# 快速入门

Codel Build 是一款终端 AI 编程助手。它以 TUI（终端用户界面）的形式运行，能够深入理解您的代码库、执行 Shell 命令、编辑文件、检索 Web 信息并高效管理任务。

您既可以将其作为全屏 TUI 进行交互式使用，也可以在无头模式（Headless）下运行以进行脚本编写与 CI/CD 集成，或者通过 Agent Client Protocol (ACP) 将其嵌入编辑器中。

---

## 安装指南

### 前置依赖

- **Rust 工具链**：[rustup](https://rustup.rs)（含 cargo）
- **protoc**：`brew install protobuf`（macOS）或系统包管理器安装

### 本地编译

```bash
git clone <仓库地址> && cd codel

# release 构建并安装到 ~/.local/bin/codel（可在任意目录执行）
./release.sh

# 或者只构建不安装
./build.sh              # release 构建
./build.sh --debug      # debug 构建（更快）
```

验证安装：

```bash
codel --version
```

## 首次启动

Codel 本身不提供模型服务，您需要使用**自己的模型站点**（如 OpenAI、Anthropic、阿里云百炼、本地 Ollama 等）。第一步是配置模型与 API 密钥。

从您的模型服务商控制台获取 API 密钥，然后在 `~/.codel/config.toml` 中配置模型。Codel 支持三种 API 协议，请根据您的模型站点选择对应的一种：

### 协议一：OpenAI Chat Completions（默认，最常见）

适用于 OpenAI、阿里云百炼、DeepSeek、本地 Ollama 等绝大多数 OpenAI 兼容端点：

```toml
# ~/.codel/config.toml
[models]
default = "my-model"

[model.my-model]
model = "gpt-4o"                          # 发往 API 的模型标识
base_url = "https://api.openai.com/v1"    # 你的模型站点地址
api_backend = "chat_completions"          # 默认值，可省略
api_key = "sk-..."                        # 从你的模型站点获取的 API 密钥
context_window = 128000
```

### 协议二：OpenAI Responses

适用于 OpenAI 新一代 Responses 接口（`/v1/responses`）：

```toml
[models]
default = "my-responses-model"

[model.my-responses-model]
model = "gpt-4o"
base_url = "https://api.openai.com/v1"
api_backend = "responses"
api_key = "sk-..."
context_window = 128000
```

### 协议三：Anthropic Messages

适用于 Anthropic Claude 系列（`/v1/messages`）：

```toml
[models]
default = "claude"

[model.claude]
model = "claude-opus-4-6"
base_url = "https://api.anthropic.com/v1"
api_backend = "messages"
context_window = 200000
extra_headers = { "x-api-key" = "sk-ant-...", "anthropic-version" = "2023-06-01" }
```

### 用环境变量持有密钥（推荐）

为避免把密钥明文写入配置文件，可用 `env_key` 指向一个环境变量：

```toml
[model.my-model]
model = "gpt-4o"
base_url = "https://api.openai.com/v1"
env_key = "MY_API_KEY"                    # 存放密钥的环境变量名
context_window = 128000
```

```bash
export MY_API_KEY="sk-..."
codel
```

配置完成后运行 `codel` 即可启动。完整的模型配置说明（提供商继承、全部字段、辅助模型、模型切换等）详见 [模型配置](02-模型配置.md)。

## 基础交互

配置好模型后，Codel 将呈现一个包含两大核心区域的全屏 TUI：

- **历史回溯区 (Scrollback)** —— 对话历史记录，展示您的提示语、Codel 的回复、工具调用、文件编辑等丰富信息。
- **提示编辑区 (Prompt)** —— 位于底部的输入区域，用于键入消息。

键入消息并按 `Enter` 即可发送。Codel 会根据需要读取文件、运行命令与修改代码。每次工具调用的过程均会实时流式推送至历史回溯区。

按 `Tab` 键可在提示输入区与历史回溯区之间切换焦点。当一轮思考推进中时，按 `Esc` 可终止本轮（全屏 Vim 滚动模式例外，此时中途 `Esc` 为无操作；极简模式下即便是 Vim 模式亦会取消）；当输入框清空后，按 `Ctrl+C` 可终止 — 若存在草稿，首次按下仅会清空草稿。空闲时，800ms 内连按两次 `Esc` 可清空非空输入框，或（在输入框为空且存在历史消息时）开启回滚功能 — 详见 [快捷键指南](03-快捷键指南.md#escape)。在历史回溯区获焦时，使用方向键选择条目，并对其进行折叠或展开。若希望通过 `j`/`k` 进行导航以及通过 `h`/`l` 折叠/展开，请开启 Vim 模式。

### 文件引用操作

在提示输入框中使用 `@` 符可便捷附带文件：

```
@src/main.rs              # 附带单个文件
@src/main.rs:10-50        # 附带文件的第 10 至 50 行
@src/                     # 浏览目录结构
```

`@` 操作符会唤起模糊匹配文件选择器。默认情况下它会遵循 `.gitignore` 并隐藏点开头的文件。添加前缀 `!` 可搜索隐藏文件：

```
@!.github                 # 搜索隐藏文件
@!.env                    # 附带 .env 配置文件
```

### 权限管理

默认情况下，Codel 在执行 Shell 命令或编辑文件前会请示授权。您可以逐项批准，亦可切换至始终批准模式：

- 按 `Ctrl+O` 快捷键切换始终批准模式
- 在启动时传入 `--yolo` 标识：`codel --yolo`
- 在提示框中键入 `/always-approve` 命令切换该模式

## 核心概念

### 会话 (Sessions)

每一次对话即为一次**会话**。会话会自动保存至 `~/.codel/sessions/` 中，以便后续随时恢复。每次会话均跟踪完整的对话历史、工具调用、文件编辑与任务状态。

- 开启新会话：`Ctrl+N` 或 `/new`
- 恢复历史会话：TUI 内键入 `/resume`，或在 CLI 中使用 `--resume <ID>`
- 延续最近一次会话：`codel -c`

### 历史回溯区 (Scrollback)

历史回溯区为核心展示面板。它包含：

- **用户提示语** —— 您的消息，以吸顶标头形式渲染
- **智使回复消息** —— Codel 的回复，具备完整的 Markdown 渲染与语法高亮
- **思考过程块 (Thinking)** —— Codel 的推理推演过程（可折叠）
- **工具调用** —— 文件编辑（含行内 Diff）、命令执行、搜索结果等
- **任务清单** —— 用于追踪进度的 TODO 项

使用 `左`/`右` 方向键（或 Vim 模式下的 `h`/`l` 与 `e`）折叠或展开所选条目。在 Vim 模式下，按 `y` 复制其内容，按 `Y` 复制其元数据（例如运行的命令）。按 `Enter` 可在全屏查看器中打开它（任意模式下）。

### 工具集 (Tools)

Codel 内置了丰富的工具：

| 工具名称 | 功能描述 |
|------|-------------|
| `read_file` / `search_replace` | 读取与行级精准编辑文件 |
| `grep` | 基于 ripgrep 的代码库正则表达式搜索 |
| `list_dir` | 列出目录结构内容 |
| `run_terminal_command` | 执行终端 Shell 命令 |
| `web_search` / `web_fetch` | 检索 Web 信息与抓取 URL 内容 |
| `todo_write` | 创建与管理任务清单 |
| `spawn_subagent` | 衍生并行分身智使会话 |
| `memory_search` | 检索跨会话长期记忆库 |

工具可以通过 [MCP服务器](05-系统配置.md#mcp-servers) 进行无缝扩展，以集成 GitHub、数据库等外部系统。

### 斜杠指令 (Slash Commands)

在提示框中键入 `/` 即可使用快捷指令。无需撰写完整提示语即可快速执行操作：

```
/model codel-build                 # 切换 AI 模型
/compact                          # 压缩对话历史
/always-approve                   # 切换始终批准模式
/new                              # 开启全新会话
```

完整参考请阅读 [斜杠指令](04-斜杠指令.md)。

## 常用启动选项

```bash
# 启动交互式 TUI 并将初始提示语作为首轮提交
codel "修复失败的 auth 测试并运行校验"

# 在全新的 Git Worktree 中启动初始提示。使用 --worktree=<名称> (带 `=`) 
# 以防提示语被误解析为 worktree 名称
codel --worktree=feat "重构模块 X"

# 基于特定分支（如 main）而非当前 HEAD 建立 worktree:
codel -w --ref main "基于 main 实现新特性"

# 在特定项目目录中启动
codel --cwd ~/projects/my-app

# 注入项目专属的自定义规则
codel --rules "始终使用 TypeScript，优先采用函数式组件。"

# 自动批准所有工具调用
codel --yolo

# 指定使用的 AI 模型
codel -m codel-build

# 恢复特定的历史会话
codel --resume <session-id>

# 延续最近一次会话
codel -c

# 体验实验性的滚动原生渲染模式。此设置具备记忆性：后续直接执行 `codel` 
# 将沿用此前通过 --minimal/--fullscreen 选择的模式
codel --minimal

# 恢复至标准全屏 TUI 模式
codel --fullscreen

# 无头模式（适用于脚本自动化）
codel -p "解读此代码库的架构"
```

## 无头交互模式 (Headless Mode)

在非交互场景下运行 Codel，以满足脚本撰写、CI/CD 与自动化需求：

```bash
codel -p "在此输入您的提示语"
```

输出格式选择：

| 格式名称 | 标志位 | 功能说明 |
|--------|------|-------------|
| `plain` | (默认) | 人类可读的文本格式 |
| `json` | `--output-format json` | 包含 `text`、`stopReason`、`sessionId` 与 `requestId` 的单 JSON 对象 |
| `streaming-json` | `--output-format streaming-json` | 用于实时处理的 NDJSON 事件流 |

CI/CD 集成示例：

```bash
codel -p "审查代码变更中的潜在 Bug" --output-format json --yolo | jq -r '.text'
```

## 项目规范律条 (AGENTS.md)

在您的代码仓库中创建 `AGENTS.md` 文件即可添加项目专属指令。Codel 会自动读取这些文件，并在对话开启时将其作为项目规范消息注入：

```
~/.codel/AGENTS.md           # 全局律条（适用于所有项目）
<repo-root>/AGENTS.md       # 仓库级律条
<cwd>/AGENTS.md             # 目录级律条（拥有最高优先级）
```

嵌套更深的文件具备更高优先级。Codel 同时兼容读取 `CLAUDE.md` 文件。
