# 自定义模型

配置模型是使用 Codel 的**第一步**。Codel 本身**不附带任何内置默认模型**——你必须先在 `config.toml` 中声明至少一个模型（或通过 CLI / 环境变量指定），程序才能正常启动。本手册完整覆盖模型配置的全部内容：认证、API 后端协议、模型条目、提供商、全局默认、辅助模型、模型选择与过滤，以及完整的环境变量速查表。

---

## 概述

### 无内置默认模型

Codel 的内置模型目录为空（`default_models.json` 内容为 `{"models": []}`），`default_model()` 返回 `None`。这意味着：

- **没有**开箱即用的默认模型，也**没有** `codel login` 浏览器登录流程。
- Codel 通过 **API 密钥**（`Authorization: Bearer`）进行认证。
- 你**必须**自行配置模型（在 `~/.codel/config.toml` 的 `[model.<id>]` 中声明，并设置 `[models] default` 或用 `-m` 指定），否则会话无法启动。

> 这是最重要的前提：先配模型，再用 Codel。下文[快速开始](#快速开始最小可用配置)给出一个 5 分钟内可跑起来的最小配置。

### 配置文件位置

主配置文件位于 `~/.codel/config.toml`。配置目录由 `$CODEL_HOME` 指定，未设置时为 `~/.codel`（`codel-config/src/paths.rs:35`）。

Codel 的配置分为多个层级，按优先级从高到低合并：

| 层级 | 文件 | 用途 |
|------|------|------|
| 用户配置 | `~/.codel/config.toml` | 你个人的模型与设置 |
| 托管配置 | `~/.codel/managed_config.toml` | 组织统一下发的托管设置 |
| 策略配置 | `~/.codel/requirements.toml` | 组织强制策略（不可放宽） |
| 项目配置 | `<git_root>/.codel/config.toml` | 项目级覆盖（模型相关字段主要从用户配置加载） |

模型配置（`[models]`、`[model.<id>]`、`[model_providers.<id>]`）主要写在用户配置 `~/.codel/config.toml` 中。

## 快速开始：最小可用配置

下面是一个最简单的、能立即跑起来的配置：声明一个 OpenAI 兼容模型，并设为默认。

**第 1 步**：编辑 `~/.codel/config.toml`：

```toml
[models]
default = "my-model"            # 新会话默认使用的模型

[model.my-model]
model = "gpt-4o"                # 发往 API 的模型标识符（slug）
base_url = "https://api.openai.com/v1"   # 兼容 OpenAI 的终端节点
context_window = 128000         # 上下文窗口（必填，用于自动压缩）
env_key = "OPENAI_API_KEY"      # 从该环境变量读取 API 密钥
```

**第 2 步**：导出 API 密钥并启动：

```bash
export OPENAI_API_KEY="sk-..."
codel
```

就这样，两个字段（`model` + `base_url`）加一个必填的 `context_window`，再配上密钥来源，Codel 即可工作。

> **提示**：每个模型都必须配置自己的密钥来源（`api_key` 或 `env_key`），Codel 不提供全局密钥回退。

列出当前可用的所有模型，验证配置是否生效：

```bash
codel models
```

## 认证与 API 密钥

Codel 使用 API 密钥认证，请求时以 `Authorization: Bearer <key>` 发送（Anthropic 等使用自定义请求头的提供商除外，见 [API 后端协议](#api-后端协议)）。

**每个模型都必须单独配置密钥**——通过模型条目的 `api_key` 或 `env_key` 字段。Codel 不提供全局密钥环境变量，密钥始终与具体模型绑定。

### 每模型密钥：api_key 与 env_key

在 `[model.<id>]` 中可以单独指定该模型的密钥来源：

- `api_key`：直接写入密钥字符串（不推荐，明文落盘）。
- `env_key`：指定保存密钥的环境变量名。可以是**字符串**或**数组**；数组时使用**首个已设置且非空**的值（例如 SSH `LC_*` 透传场景）：

```toml
[model.my-model]
env_key = "OPENAI_API_KEY"
# 或数组形式：
# env_key = ["ANTHROPIC_AUTH_TOKEN", "LC_ANTHROPIC_AUTH_TOKEN"]
```

### 凭据解析顺序

对于每个请求，Codel 按以下顺序解析 API 密钥（`resolve_credentials`，`config.rs:4446-4502`）：

1. **模型自身凭据** —— `[model.<id>]` 的 `api_key`，或由 `env_key` 解析出的环境变量值。
2. **全局 API 密钥** —— `CODEL_API_KEY`（由 `/setApiKey` 写入 `auth.json`，或直接导出环境变量）。
3. **都没有** —— 请求不带 API 密钥（若配置了 `env_key` 但变量未设置，Codel 会打印警告）。

优先级从高到低，命中即停。因此务必为每个模型配置 `api_key` 或 `env_key`。

## API 后端协议

Codel 支持三种 API 后端协议。在 `[model.<id>]` 中通过 `api_backend` 字段选择（`codel-sampling-types/src/types.rs:1013`）：

| 值 | API 协议 | 端点 | 是否默认 |
|----|----------|------|----------|
| `"chat_completions"` | OpenAI Chat Completions | `/v1/chat/completions` | 是 |
| `"responses"` | OpenAI Responses | `/v1/responses` | |
| `"messages"` | Anthropic Messages | `/v1/messages` | |

省略 `api_backend` 时，Codel 使用 `chat_completions`。

### 认证请求头差异

- `chat_completions` / `responses`：使用标准的 `Authorization: Bearer <key>`。
- `messages`（Anthropic）：使用 `x-api-key` 请求头而非 `Authorization: Bearer`，并通常需要 `anthropic-version` 请求头。请通过 `extra_headers` 传递：

```toml
[model.claude]
model = "claude-opus-4-6"
base_url = "https://api.anthropic.com/v1"
api_backend = "messages"
context_window = 200000
extra_headers = { "x-api-key" = "sk-ant-...", "anthropic-version" = "2023-06-01" }
```

Codel 会把 `extra_headers` 中的请求头原样附带在发往终端节点的每个请求中。

## 配置模型条目 `[model.<id>]`

在 `~/.codel/config.toml` 的 `[model.<id>]` 段中声明一个模型。`<id>` 是你在 Codel 中引用该模型的目录键名（例如 `/model <id>`、`-m <id>`）。

字段定义见 `ConfigModelOverride`（`config.rs:3660`）。完整字段清单如下：

### 连接与身份（核心字段）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `model` | string | **是** | 发往 API 的模型标识符（routing slug）。 |
| `base_url` | string | **是** | 终端节点基础 URL，例如 `https://api.openai.com/v1`。 |
| `context_window` | integer | **是** | 上下文窗口总 Token 数（`NonZeroU64`）。用于自动压缩阈值计算。BYOK 用户必须显式设置。 |
| `name` | string | 否 | 在模型选择器中显示的名称。 |
| `description` | string | 否 | 模型描述。 |
| `api_base_url` | string | 否 | 覆盖用于 API 调用的基础 URL（与 `base_url` 分离时使用）。 |

> 当你**从零定义**一个新模型时，`model`、`base_url`、`context_window` 三者必填。当你**覆盖**一个已知模型（用其名称作为 section 键）时，未指定的字段会继承原有默认值，此时只需写你要改的字段。

### 凭据字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `api_key` | string | 该模型的 API 密钥（明文，优先级最高）。 |
| `env_key` | string 或 array | 保存 API 密钥的环境变量名；数组时取首个已设置且非空的值。 |
| `model_provider` | string | 指向某个 `[model_providers.<id>]` 提供商，从提供商继承连接配置（见下文）。 |

### 采样与请求字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `api_backend` | string | `"chat_completions"`（默认）、`"responses"` 或 `"messages"`。 |
| `temperature` | float | 采样温度。 |
| `top_p` | float | 核采样参数。 |
| `max_completion_tokens` | integer | 单次响应最大 Token 数。 |
| `extra_headers` | map | 附加到每个请求的请求头（原样发送）。 |
| `query_params` | map | 附加到每个请求 URL 的查询参数。 |
| `env_http_headers` | map | 请求头名 → 环境变量名的映射，在构建客户端时解析（敏感值不落盘）。 |
| `stream_tool_calls` | bool | 是否流式返回工具调用。少数终端节点需保持未设置，可在此单独关闭。 |
| `max_retries` | integer | 请求重试次数。 |
| `inference_idle_timeout_secs` | integer | 推理空闲超时秒数。 |

### 行为与能力字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `agent_type` | string | 该模型使用的 Agent 配置类型。默认 `codel-build-plan`。 |
| `auto_compact_threshold_percent` | integer | 每模型自动压缩阈值（0-100），占用上下文窗口该百分比时触发压缩。 |
| `system_prompt_label` | string | 每模型系统 Prompt 身份标识。 |
| `use_concise` | bool | 启用精简模式（紧凑系统 Prompt、精简工具输出、缩减工具集）。 |
| `hidden` | bool | 隐藏该模型（仍可通过 `-m` 使用）。 |
| `supported_in_api` | bool | 标记该模型是否可在 API 中使用。设置了 `api_key`/`env_key` 时默认为 `true`。 |
| `reasoning_effort` | string | 该模型的推理努力程度。 |
| `supports_reasoning_effort` | bool | 是否支持推理努力程度。`messages` 后端默认为 `true`。 |
| `reasoning_efforts` | array | 可选的推理努力程度选项列表。 |
| `supports_backend_search` | bool | 是否支持服务端（后端）Web 搜索。 |
| `compactions_remaining` | - | 压缩剩余次数配置（别名 `send_compactions_remaining`）。 |
| `compaction_at_tokens` | - | 按 Token 数触发压缩的配置。 |
| `show_model_fingerprint` | bool | 是否显示模型指纹。 |

### 完整示例

```toml
[model.my-model]
model = "model-id"                        # 发送到 API 的模型标识符（必填）
base_url = "https://api.example.com/v1"   # 兼容 OpenAI 的终端节点 URL（必填）
context_window = 128000                   # 上下文窗口总 Token 数（必填）
name = "Display Name"                     # 在模型选择器中显示的名称
description = "Model description"         # 可选描述
api_key = "sk-..."                        # 该提供商的 API 密钥（可选）
env_key = "PROVIDER_API_KEY"              # 保存 API 密钥的环境变量名（可选；字符串或数组）
api_backend = "chat_completions"          # "chat_completions"、"responses" 或 "messages"
temperature = 0.7                         # 采样温度
top_p = 0.95                              # 核采样参数
max_completion_tokens = 8192              # 单次响应最大 Token 数
extra_headers = { "x-api-key" = "sk-..." } # 额外的请求头，原样发送（可选）
query_params = { api-version = "2026-07-22" } # 附加到每个请求 URL 的查询参数（可选）
env_http_headers = { "X-Tenant" = "TENANT_TOKEN" } # 来自环境变量的请求头（可选）
```

### 模型通知 (Notice)

`notice` 在模型被选中期间会在输入框上方显示一条消息。该横幅无法关闭；切换到没有通知的模型后即消失。

```toml
[model.legacy]
model = "legacy-model"
base_url = "https://gateway.example/v1"
notice = { severity = "warning", text = "该模型将于 10 月 15 日弃用，请切换到新模型。", label = "deprecated" }
```

`severity` 决定横幅颜色，可选 `info`、`warning`、`critical`，默认为 `info`。`text` 必填，长文本会自动换行。`label` 是显示在文本前的可选短标签。自定义模型端点可在模型条目上以 `notice` 或 `_meta.notice` 发送同一对象。要移除内置或远程模型自带的通知，设置 `notice = { text = "" }`。

### 覆盖内置/已知模型

你可以仅覆盖某个已知模型的特定字段，而无需重新定义所有配置。用该模型的名称作为 section 键，只写要改的字段：

```toml
# 仅覆盖默认模型的 API 密钥
[model.codel-build]
api_key = "my-api-key"

# 覆盖采样温度并添加自定义 API 密钥
[model.codel-build]
temperature = 0.5
api_key = "sk-custom"
```

覆盖时，Codel 从该模型的默认配置（包括正确的 `base_url`）开始，然后仅应用你指定的字段，未指定字段继续继承默认值。

### 上下文窗口默认值

`context_window` 告知 Codel 何时触发自动压缩。不同来源的默认值：

- **内置 JSON 回退**：200,000（`config.rs:3486`）。
- **远程预取模型**（从 `/v1/models` 拉取）：256,000（`remote/client.rs:695`）。
- **`ModelEntryConfig.context_window` 本身必填**：BYOK 用户从零定义模型时必须显式设置，请匹配你的提供商实际窗口大小。

### 请求查询参数（query_params）

某些网关基于查询字符串进行路由或版本控制。`query_params` 将 URL 编码的查询参数附加到 Codel 为该模型发出的每一个请求上：

```toml
[model.my-gateway]
model = "my-model"
base_url = "https://gateway.example/v1"
context_window = 128000
api_backend = "responses"
env_key = "GATEWAY_API_KEY"
query_params = { api-version = "2026-07-22" }
```

同时出现在 `base_url` 查询字符串中的 Key 会被覆盖（以最后一个值为准）而非重复拼接。查询参数会保存在会话中，因此**切勿**将敏感值放在其中——敏感值请使用 `env_http_headers`。

### 环境变量请求头（env_http_headers）

`env_http_headers` 将请求头映射到提供其值的环境变量名，因此单次请求的敏感值绝不需要写进 `config.toml`：

```toml
[model.gateway]
model = "my-model"
base_url = "https://gateway.example/v1"
context_window = 128000
env_http_headers = { "X-Tenant-Token" = "GATEWAY_TENANT_TOKEN" }
```

Codel 在为会话构建客户端时读取每个变量，并仅将该值放置在请求头中，绝不会保存在磁盘上。当对应变量未设置或为空时，该请求头会被跳过，且解析后的值会覆盖同名的 `extra_headers` 条目。静态值用 `extra_headers`，来自环境变量的值用 `env_http_headers`。

这两个字段在共享的 `[model_providers.<id>]` 块上同样有效。

## 配置提供商 `[model_providers.<id>]`

当多个模型共享同一套连接配置（相同的 `base_url`、凭据、请求头等）时，可以把公共部分抽取到一个**提供商**块 `[model_providers.<id>]`，再让模型用 `model_provider = "<id>"` 继承（`ModelProviderConfig`，`model_providers.rs:9-24`）。

### 字段清单

| 字段 | 类型 | 说明 |
|------|------|------|
| `base_url` | string | 提供商终端节点基础 URL。 |
| `api_base_url` | string | 覆盖用于 API 调用的基础 URL。 |
| `env_key` | string 或 array | 保存 API 密钥的环境变量名。 |
| `api_key` | string | 提供商级 API 密钥。 |
| `api_backend` | string | `"chat_completions"`、`"responses"` 或 `"messages"`。 |
| `extra_headers` | map | 附加到每个请求的请求头。 |
| `query_params` | map | 附加到每个请求 URL 的查询参数。 |
| `env_http_headers` | map | 请求头名 → 环境变量名映射。 |
| `auth_provider` | string | 凭据助手名称。 |
| `auth` | table | 内联凭据助手配置（见下）。 |
| `context_window` | integer | 提供商级上下文窗口默认值。 |

内联凭据助手 `auth` 的字段（`AuthProviderConfig`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `command` | string | 要运行的命令（无 `args` 时用平台 shell，有 `args` 时直接 exec）。 |
| `token_ttl_secs` | integer | 输出未携带 `expires_in` 时的回退令牌有效期。 |
| `timeout_secs` | integer | 等待命令的最大秒数（默认 30，限制在 1..=600）。 |

### 继承规则

模型用 `model_provider = "<id>"` 指向提供商后，按以下规则继承：

- **连接类字段**（`base_url`、`api_base_url`、`api_backend`、`context_window`、凭据等）：**逐字段回退**——模型自身未设置的字段，回退到提供商的值。
- **`extra_headers` / `query_params` / `env_http_headers`**：**整体继承**——仅当模型自身对应字段为空时，才整体继承提供商的映射；模型一旦设置了自己的映射，就不继承（而非按键合并）。
- **凭据**：仅当模型自身**没有任何**凭据（无 `api_key`、无 `env_key`、无 `auth_provider`）时，才继承提供商的凭据。

### 示例

```toml
# 定义一个共享提供商
[model_providers.my-gateway]
base_url = "https://gateway.example/v1"
env_key = "GATEWAY_API_KEY"
api_backend = "responses"
context_window = 128000
extra_headers = { "X-Org" = "acme" }

# 模型继承提供商配置，只需写差异部分
[model.gateway-fast]
model = "fast-model"
model_provider = "my-gateway"
name = "Fast Model"

[model.gateway-large]
model = "large-model"
model_provider = "my-gateway"
name = "Large Model"
context_window = 256000        # 覆盖提供商的 context_window
```

## 全局默认 `[models]`

`[models]` 段设置全局默认值与目录级行为（`ModelsConfig`，`config.rs:1029-1100`）。

### 字段清单

| 字段 | 类型 | 说明 |
|------|------|------|
| `default` | string | 新会话默认使用的模型。 |
| `default_reasoning_effort` | string | 默认模型的推理努力程度。 |
| `web_search` | string | `web_search` 工具使用的模型。 |
| `session_summary` | string | 会话标题/摘要生成使用的模型。 |
| `image_description` | string | 图像描述（视觉转写）使用的模型。 |
| `prompt_suggestion` | string | 下一条 Prompt 建议（Tab 自动补全）使用的模型。 |
| `allowed_models` | array | glob 白名单，限制用户可选的模型（详见[模型过滤](#模型过滤)）。 |
| `hidden_models` | array | 强制对这些模型 ID 设置 `hidden = true`（仍可通过 `-m` 使用）。 |
| `disabled_models` | array | 从目录中完全移除这些模型 ID（优先于 `hidden_models`）。 |
| `agent_type` | string | 无每模型覆盖时的回退 `agent_type`。 |
| `extra_headers` | map | 应用于**每个**模型的全局默认请求头。 |
| `temperature` | float | 每个模型的全局默认温度（模型自身设置优先）。 |
| `top_p` | float | 每个模型的全局默认 top_p。 |
| `max_completion_tokens` | integer | 每个模型的全局默认最大补全 Token 数。 |
| `max_retries` | integer | 每个模型的全局默认重试次数。 |
| `inference_idle_timeout_secs` | integer | 每个模型的全局默认推理空闲超时。 |
| `stream_tool_calls` | bool | 每个模型的全局默认流式工具调用开关。 |

### 全局默认请求头

若要将相同的请求头应用于目录中的*每一个*模型（内置、远程预取或自定义），在 `[models]` 设置一次即可：

```toml
[models]
extra_headers = { "X-Request-Tags" = "team=example,env=prod" }
```

单模型的 `[model.<id>].extra_headers` 条目可以按 **Key**（不区分大小写）覆盖全局默认值：模型上设置的 Key 优先，纯全局的 Key 仍会被该模型继承。这些请求头附带在模型的推理调用中（而非图像生成等独立服务），非常适合归因标签（如成本跟踪）。

### 全局默认采样值

部分通用的单模型设置也可以在 `[models]` 下设置一次，作为*每个*模型的默认值。单模型的 `[model.<id>]` 设置值总是优先；全局设置仅在模型未设置该字段时补充：

```toml
[models]
temperature                 = 0.7
top_p                       = 0.95
max_completion_tokens       = 8192
max_retries                 = 8
inference_idle_timeout_secs = 600
stream_tool_calls           = true
```

这是一组小而固定的环境级调节开关。用于标识特定模型的设置（`model`、`base_url`、`api_key`、`context_window` …）无法通过这种方式设置默认值。

> **关于 `stream_tool_calls` 的说明**：该选项影响请求的*形态*，而不仅仅是采样。少数终端节点期望将其保持未设置；如果全局 `stream_tool_calls = true` 导致此类模型出现问题，请在该模型的 `[model.<id>]` 块中用 `stream_tool_calls = false` 单独关闭。

## 常见提供商配置示例

### OpenAI（Chat Completions）

```toml
[models]
default = "gpt-4o"

[model.gpt-4o]
model = "gpt-4o"
base_url = "https://api.openai.com/v1"
name = "GPT-4o"
context_window = 128000
env_key = "OPENAI_API_KEY"
```

`api_backend` 默认为 `"chat_completions"`，因此 OpenAI 无需显式设置。

### OpenAI（Responses API）

如果你的提供商支持更新的 Responses API：

```toml
[model.gpt-4o-responses]
model = "gpt-4o"
base_url = "https://api.openai.com/v1"
name = "GPT-4o (Responses)"
api_backend = "responses"
context_window = 128000
env_key = "OPENAI_API_KEY"
```

### Anthropic（Claude）

通过 Anthropic Messages API 直接使用 Claude 模型：

```toml
[model.claude-opus]
model = "claude-opus-4-6"
base_url = "https://api.anthropic.com/v1"
name = "Claude Opus 4.6"
api_backend = "messages"
context_window = 200000
extra_headers = { "x-api-key" = "sk-ant-...", "anthropic-version" = "2023-06-01" }
```

`messages` 后端使用 Anthropic Messages 协议。Anthropic 使用 `x-api-key` 请求头而非 `Authorization: Bearer` 进行身份验证，因此通过 `extra_headers` 传递密钥，Codel 会原样发送。

### Ollama（本地部署模型）

通过 [Ollama](https://ollama.ai) 在本地运行模型：

```toml
[model.ollama-codellama]
model = "codellama"
base_url = "http://localhost:11434/v1"
name = "CodeLlama (Ollama)"
context_window = 16384
```

确保 Ollama 正在运行（`ollama serve`）并且模型已被拉取（`ollama pull codellama`）。本地模型通常无需 API 密钥。

### 其他 OpenAI 兼容端点

实现了 OpenAI Chat Completions 或 Responses API 的任何服务器（Together AI、vLLM、本地推理服务等）：

```toml
[model.together-mixtral]
model = "mistralai/Mixtral-8x7B-Instruct-v0.1"
base_url = "https://api.together.xyz/v1"
name = "Mixtral 8x7B"
context_window = 32768
env_key = "TOGETHER_API_KEY"

[model.local-llama]
model = "llama-3.1-70b"
base_url = "http://localhost:8080/v1"
name = "Local Llama"
context_window = 128000
temperature = 0.8
```

## 自定义端点

将 Codel 指向自定义的、兼容 OpenAI 的 `/v1/models` 终端节点。当你的模型部署在企业网关或私有化推理服务之后时使用。

### 环境变量

| 变量名 | 是否必填 | 描述 |
|--------|----------|------|
| `CODEL_MODELS_BASE_URL` | 是 | 推理的基础 URL。Codel 会从 `{base_url}/models` 获取模型列表。 |
| `CODEL_MODELS_LIST_URL` | 否 | 当模型列表 URL 与 `{base_url}/models` 不同时用于覆盖。 |

### 设置示例

```bash
export CODEL_MODELS_BASE_URL="https://api.acme.com/v1"
codel
```

### 配置文件替代方案

```toml
[endpoints]
models_base_url = "https://api.acme.com/v1"

# 仅覆盖特定模型的 API 密钥
[model.codel-build]
api_key = "my-api-key"
```

`[endpoints]` 段对应 `EndpointsConfig`，相关字段还包括 `cli_chat_proxy_base_url`（`CODEL_CLI_CHAT_PROXY_BASE_URL`）、`codel_api_base_url`（`CODEL_API_BASE_URL`）、`models_list_url`（`CODEL_MODELS_LIST_URL`）。当你使用 `[endpoints]` 与部分模型覆盖时，Codel 会从 endpoints 配置继承 `base_url`，无需在每个 `[model.*]` 段重复指定。

### 身份验证行为

当你设置 `models_base_url` 时，Codel 的模型列表请求仅使用 `CODEL_API_KEY` 认证（`Authorization: Bearer`）。该请求永远不会使用登录会话。若未设置 `CODEL_API_KEY`，获取会失败并提示您设置它。发往自定义主机的推理请求单独认证：为每个模型设置 `api_key` 或 `env_key` 可让这些请求同样使用 API 密钥。

## 辅助模型

除主模型外，Codel 的若干内置功能各自使用一个独立的辅助模型。它们都在 `[models]` 段配置，并有对应的环境变量覆盖。

| 功能 | `[models]` 字段 | 环境变量 | 说明 |
|------|----------------|----------|------|
| Web 搜索 | `web_search` | `CODEL_WEB_SEARCH_MODEL` | `web_search` 工具的结果综合模型。 |
| 会话摘要 | `session_summary` | `CODEL_SESSION_SUMMARY_MODEL` | 会话标题/摘要生成模型。 |
| 图像描述 | `image_description` | `CODEL_IMAGE_DESCRIPTION_MODEL` | 视觉模型，用于转写用户提供的图像。 |
| Prompt 建议 | `prompt_suggestion` | `CODEL_PROMPT_SUGGESTIONS_MODEL` | 下一条 Prompt 建议（Tab 自动补全幽灵文本）模型。 |

### 配置示例

```toml
[models]
web_search = "my-search-model"
session_summary = "my-summary-model"
image_description = "my-vision-model"
prompt_suggestion = "my-suggest-model"
```

或通过环境变量：

```bash
export CODEL_WEB_SEARCH_MODEL="my-search-model"
export CODEL_SESSION_SUMMARY_MODEL="my-summary-model"
export CODEL_IMAGE_DESCRIPTION_MODEL="my-vision-model"
export CODEL_PROMPT_SUGGESTIONS_MODEL="my-suggest-model"
```

如果你将某个辅助功能指向自定义模型，你还需要一个对应的 `[model.<id>]` 条目，以便 Codel 能连接到它。

### 后端 Web 搜索

服务端（"后端"）Web 搜索仅在模型设置了 `supports_backend_search = true`（且构建版本启用了后端搜索）时才会运行；它不依赖于 `api_backend`：

```toml
[models]
web_search = "my-custom-model"

[model.my-custom-model]
model = "my-custom-model"
base_url = "https://api.example.com/v1"
context_window = 128000
supports_backend_search = true
```

## 模型选择与切换

### 默认模型解析优先级

Codel 按以下优先级确定默认模型（从高到低，`resolution.rs:56-73`）：

1. **CLI 标志** `-m` / `--model`
2. **环境变量** `CODEL_DEFAULT_MODEL`
3. **配置文件** `[models] default`
4. **远程设置** `remote_settings.default_model`

> **注意**：环境变量层使用的是 `CODEL_DEFAULT_MODEL`（**不是** `CODEL_MODEL`）。

### 运行时切换方式

| 方式 | 用法 | 作用域 |
|------|------|--------|
| CLI 标志 | `codel -p "Hello" -m my-model` | 本次调用 |
| 斜杠命令 | `/model my-model`（别名 `/m my-model`） | 当前会话 |
| 模型选择器 | 在滚动历史面板按 `Ctrl+M` | 当前会话 |
| 配置文件 | `[models] default = "my-model"` | 持久化默认 |
| 列出模型 | `codel models` | 查看所有可用模型 |

```bash
# 列出所有可用的模型（包括自定义模型）
codel models

# 无头模式中使用
codel -p "Hello" -m my-model
```

在 TUI 中，`/model my-model` 可在会话期间随时切换。模型选择器（`Ctrl+M`）列出所有内置和自定义的可选模型，允许一键切换。

> 当焦点位于 Prompt 编辑框时，`Ctrl+M` 用于切换多行输入模式——请使用 `/model` 在不离开编辑框的前提下切换模型。

## 模型过滤

`[models]` 提供三个字段控制模型目录的可见性与可选性：

| 字段 | 行为 |
|------|------|
| `allowed_models` | glob 白名单。限制用户可选的模型（选择器、`/model`、`-m`）。不匹配的模型仍留在目录中，但绝不显示、不作为默认、不可选。特殊/内部模型（`web_search`、`image_description`、子 Agent、fork 副模型）豁免。glob 模式（`*`、`?`、`[...]`）匹配模型 id 或目录键，区分大小写。空 = 不限制；被排除的显式 `default`/`-m` 会在启动时被拒绝。 |
| `hidden_models` | 强制对这些模型 ID 设置 `hidden = true`（仍可通过 `-m` 使用）。 |
| `disabled_models` | 从目录中**完全移除**这些模型 ID。优先于 `hidden_models`。 |

```toml
[models]
# 仅允许以 team- 开头的模型可选
allowed_models = ["team-*"]

# 隐藏实验性模型（仍可用 -m 指定）
hidden_models = ["experimental-model"]

# 完全移除某模型
disabled_models = ["deprecated-model"]
```

## 完整配置示例

一个综合性的企业部署 `config.toml`，涵盖默认模型、提供商、辅助模型与过滤：

```toml
# ── 全局默认 ──────────────────────────────────────────
[models]
default = "company-codel"                 # 新会话默认模型
default_reasoning_effort = "high"         # 默认推理努力程度
web_search = "company-search"             # Web 搜索辅助模型
session_summary = "company-codel"         # 会话摘要辅助模型
extra_headers = { "X-Request-Tags" = "team=platform,env=prod" }
temperature = 0.7
max_completion_tokens = 8192
max_retries = 8
inference_idle_timeout_secs = 600
stream_tool_calls = true
allowed_models = ["company-*"]            # 仅允许 company- 前缀的模型可选

# ── 共享提供商 ────────────────────────────────────────
[model_providers.company-gateway]
base_url = "https://codel-proxy.acme.com/v1"
env_key = "ACME_GATEWAY_KEY"
api_backend = "chat_completions"
context_window = 128000

# ── 主模型（继承提供商）──────────────────────────────
[model.company-codel]
model = "codel-build"
model_provider = "company-gateway"
name = "Codel Build (Company Proxy)"

# ── Web 搜索模型 ─────────────────────────────────────
[model.company-search]
model = "search-model"
model_provider = "company-gateway"
name = "Company Search"
supports_backend_search = true

# ── 直接配置密钥的独立模型 ───────────────────────────
[model.claude-opus]
model = "claude-opus-4-6"
base_url = "https://api.anthropic.com/v1"
name = "Claude Opus 4.6"
api_backend = "messages"
context_window = 200000
extra_headers = { "x-api-key" = "sk-ant-...", "anthropic-version" = "2023-06-01" }

# ── 自定义端点（可选）────────────────────────────────
[endpoints]
models_base_url = "https://codel-proxy.acme.com/v1"
```

配合环境变量：

```bash
export ACME_GATEWAY_KEY="..."
codel
```

## 故障排查

### 未找到模型（Model Not Found）

```bash
# 列出可用的模型
codel models

# 检查 config.toml 中 [model.*] 部分是否存在拼写错误
# 确认 [models] default 指向的模型 id 确实存在
```

### 连接错误

验证终端节点是否可达：

```bash
curl -s https://api.example.com/v1/models \
  -H "Authorization: Bearer $MY_API_KEY"
```

### 请求未带 API 密钥

若日志出现 "model has env_key configured but none of the environment variables are set"，说明 `env_key` 指向的环境变量未设置。检查变量是否已导出，或改用 `api_key` 直接写入配置。

### 调试日志记录

```bash
RUST_LOG=debug CODEL_LOG_FILE=/tmp/codel.log codel
tail -f /tmp/codel.log
```

查找包含 `model`、`sampling` 或 `resolved credentials` 的日志条目，以跟踪模型选择与 API 调用过程。
