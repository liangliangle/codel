# 会话管理

Codel 会自动将每次对话保存到磁盘。无论您是在 TUI、[无头交互模式](14-无头交互模式.md)还是通过智使 stdio 工作，Codel 都会将会话记录保存下来。您可以恢复、回溯或压缩会话。本文档描述了如何管理会话。

---

## 什么是会话

会话是一个包含完整历史记录的持久化对话。它包括：

- 所有用户提示词和智使回复
- 工具调用及其结果
- 待办事项/任务列表状态
- 用于回溯的文件快照
- token 用量和轮次计数
- 分身智使会话 (启用时)

会话由唯一的会话 ID (Codel 生成时为 UUIDv7；客户端可使用 `-s` 提供自己的 ID) 标识，并存储在磁盘的 `~/.codel/sessions/` 目录下。设置 `CODEL_HOME` 以覆盖基础目录；未设置时，Codel 使用 `~/.codel`。

---

## 存储布局

Codel 将每个会话存储在自己的目录中，按工作目录分组。它对工作目录进行 URL 编码以命名组。当编码的名称超过 255 个字节时，它将转而使用 slug 加上哈希值，并将原始路径记录在组内的 `.cwd` 文件中。

```
~/.codel/sessions/<encoded-cwd>/<session-id>/
  summary.json            # 元数据：摘要/标题、时间戳、模型 ID、消息计数
  updates.jsonl           # ACP 会话更新流 (对话 + 工具调用)
  chat_history.jsonl      # 发送到模型的原始聊天消息
  plan.json               # 待办事项/任务列表状态
  rewind_points.jsonl     # 用于 /rewind 撤销的文件快照
  signals.json            # 会话信号 (token 用量，工具/轮次计数器)
  compaction_checkpoints/ # 保存压缩 (手动或自动) 后的状态
  subagents/              # 每个分身智使的元数据 (meta.json)；子会话存在于常规会话树中
```

`summary.json` 是索引条目。它记录了会话摘要和生成的标题、模型 ID、创建和更新时间戳、消息计数，以及派生或恢复会话的父会话引用。`updates.jsonl` 是驱动 `/resume` 和会话恢复的权威对话日志。

## 开始和结束会话

### 新会话

TUI 在您每次启动时都会创建一个新会话。要在会话中途明确地重新开始：

```
/new
```

这将清除当前上下文并开始新的对话。别名：`/clear`。

### 退出

结束会话并退出 Codel：

```
/quit
```

别名：`/exit`。若要离开当前会话但保留在 Codel 中，请使用 `/home` 返回欢迎屏幕。

---

## 恢复会话

### 从 TUI 恢复

使用 `/resume` 命令浏览并恢复之前的会话：

```
/resume
```

这会打开一个会话选择器，列出当前工作区的近期会话。选择一个会话以恢复它。该命令不接受任何参数。

在选择器中输入内容会按标题过滤列表，并在您输入时搜索您的对话内容；内容匹配项出现在“扩展搜索结果 (Extended search results)”标题下。按 `Ctrl+/` 可立即搜索而无需短暂的停顿。

要在当前活动的会话 (父会话和任何派生分支) 之间切换、重命名或关闭它们，请改为使用 `/dashboard` (或其别名 `/sessions`)。

### 从命令行恢复

通过 ID 或标题恢复特定会话：

```bash
codel --resume <session-id-or-title>
```

不是会话 ID 的值将与当前目录的会话标题进行匹配，忽略大小写 (简单的转小写比较) — 在 `/rename` 之后非常方便。如果几个会话具有相同的标题，手动重命名的单一会话优先于自动生成的重复会话；否则命令将报错并列出匹配的 ID。UUID 格式的值始终被视为会话 ID，而不是标题。脚本应首选 ID。

不带值运行 `codel --resume` 以恢复当前目录中最新的会话。

### 从欢迎屏幕恢复

当您启动 `codel` 时，欢迎屏幕会列出当前目录的近期会话。选择一个即可恢复它。

## 派生与重命名会话

### 派生 (Fork)

将当前会话派生 (branch) 为一个平行智使，它从对话的副本开始：

```
/fork [--worktree|--no-worktree] [directive]
```

传递可选的 `directive` 来设置新会话的第一个提示词。使用 `--worktree` 或 `--no-worktree` 来选择分支是否在新的 git 工作树中运行；两者都省略的话则每次都会询问。当前版本不支持 `--at <turn>` 标志。

### 重命名 (Rename)

重命名当前会话的标题：

```
/rename <title>
```

别名：`/title`。

---

## /rewind 命令

`/rewind` 通过将文件恢复到对话早期状态来撤消最近的更改。用它来从错误中恢复。

```
/rewind
```

当您运行 `/rewind` (或者在闲置状态下、提示词和对话消息为空时在 800 毫秒内按两次 **Esc Esc**) 时，Codel：

1. 显示一个回溯点列表 (每个用户提示词一个)
2. 让您选择要回溯到哪个点
3. 将所有文件恢复到该时间点的状态
4. 将对话历史记录截断至该时间点

文件快照在每次提示词时都会被记录，因此您可以回到任何以前的状态。

**重要提示：** `/rewind` 会修改磁盘上的文件。除非您已将它们提交到 git 中，否则它恢复的更改将会丢失。

---

## /compact 命令

`/compact` 压缩对话历史记录，以节省上下文窗口空间。在早期消息不再相关的长会话中使用它。

```
/compact
```

### 自动压缩

当上下文窗口接近其限制时，Codel 会自动压缩对话。当自动压缩触发时，您将看到一条通知。模型配置上的 `context_window` 设置控制何时达到此阈值。

---

## /session-info 命令

查看有关当前会话的详细信息：

```
/session-info
```

这会显示：

- 会话标题 (已设置时)
- Shell 版本
- 验证方法 (API key) 以及在哪里管理账户和积分 (API 密钥的网址是 console.codel.dev)
- 会话 ID
- 工作目录
- 模型 (编码模型带有模型哈希)
- API 后端和沙盒环境配置文件 (已设置时)
- 上下文窗口使用量 (已用和总 token 数，附带使用百分比)

## 无头交互模式中的会话管理

在无头交互模式中，您通过命令行标志来管理会话：

```bash
# 每次新建会话 (默认)
codel -p "Hello"

# 通过 ID 或标题恢复现有会话 (如果不存在则报错)
codel -p "Continue where we left off" -r <session-id-or-title>

# 在当前目录中继续最近的会话
codel -p "What were we doing?" -c
```

在[无头交互模式](14-无头交互模式.md)中，使用 `-r`/`--resume` 恢复现有会话，如果会话不存在则报错；或使用 `-c`/`--continue` 继续当前目录中最近的会话。非 ID 的值会与当前目录的会话标题进行匹配并忽略大小写 (在重复标题中，仅手动重命名的单一匹配项优先；其余重复项报错并提示其 ID；UUID 格式的值始终走 ID 路径) — 脚本应传递来自 JSON 输出 (见下文) 的会话 ID 给 `-r`。

仅在带有 **UUID** **创建**新会话时才使用 `-s`/`--session-id` (如果该值不是 UUID，或者如果该 ID 在目标会话目录下已有一个会话，则报错)。它**不**恢复现有会话 — 那是旧的隐藏式 upsert 行为；请改用 `-r`/`-c`。只有在同时传递 `--fork-session` (将历史分支到新 ID；可选的 `-s` 命名子 UUID) 时，才将 `-s` 与 `-r`/`-c` 组合使用。这符合 Claude Code 的防覆盖模式 (写入 cwd 下的客户端预检；顺序使用是可靠的，并发的相同 ID 使用是尽力而为的)。

要读回会话 ID，请求 JSON 输出：

```bash
codel -p "Hello" --output-format json | jq -r '.sessionId'
```

## 智使 stdio 的会话管理

当使用 ACP 构建时，会话通过协议方法进行管理：

```typescript
// 创建新会话
const { sessionId } = await connection.request("session/new", {
  cwd: "/path/to/project",
  mcpServers: [],
});

// 加载现有会话
await connection.request("session/load", {
  sessionId: "existing-session-id",
  cwd: "/path/to/project",
  mcpServers: [],
});
```

智使自动保留所有的会话更新。客户端可以通过 ID 重新连接并加载之前的会话。

## codel sessions 子命令

从命令行列出或搜索会话。`codel sessions` 需要一个子命令：

```bash
# 列出当前目录的近期会话
codel sessions list

# 限制结果数量 (默认 20)
codel sessions list --limit 50

# 按关键字搜索会话 (匹配标题和提示词)
codel sessions search "rate limit"
```

`codel sessions list` 显示当前工作目录的会话，并按工作树标签进行分组。每行都会列出会话 ID，创建和更新日期，来源状态以及摘要。`codel sessions search` 将本地的 SQLite 索引与远程结果结合。

## 工作树会话 (Worktree Sessions)

当使用[分身智使](16-分身智使.md)或会话派生 (forks) 时，Codel 可以为每个会话创建隔离的 git 工作树。每个工作树都有自己的一份工作目录副本，因此一个会话中的文件更改不会影响另一个会话。

工作树会话是通过内部的 `codel.dev/git/worktree/*` 扩展方法进行管理的。关键操作：

- **创建 (Create)**：为隔离的会话创建一个新的工作树
- **应用 (Apply)**：将工作树中的更改合并回主工作目录
- **移除 (Remove)**：在会话完成时清理工作树

使用 `codel -w -r <session-id>` 在一个全新的工作树中恢复会话。

`codel worktree create [NAME]` 会创建与 `codel -w [NAME]` 相同的工作树，但不启动会话。它会打印会话本应打开的目录。该路径是 stdout 上的唯一输出，因此 `cd "$(codel worktree create my-fix)"` 可以直接使用。默认情况下，工作树从 HEAD 开始，并复制您未提交的更改。传入 `--ref <ref>` 可从分支、标签或提交的干净检出开始。如果新工作树中缺少您运行命令时所在的目录（例如 `--ref` 检出的版本早于该目录，或该目录被忽略），命令会打印工作树根目录。

## 会话存储详情

### 持久化格式

Codel 将对话存储为以换行符分隔的 JSON (JSONL)。`updates.jsonl` 中的每一行都是一个自包含的 ACP 会话更新事件。此格式支持：

- 增量写入 (在会话期间仅追加)
- 高效的流式读取 (用于会话恢复)
- 轻松的调试 (每行都是有效的 JSON)

较小的状态文件 -- `summary.json`, `plan.json` 和 `signals.json` -- 是纯 JSON 而不是 JSONL。JSONL 是会话内容的数据真理；`codel sessions search` 额外在会话标题和提示词之上维护一个本地 SQLite FTS5 索引，以实现快速的关键字搜索。

### 会话元数据

`summary.json` 记录了 (除了其他字段外)：

- `info` -- 会话 ID 和工作目录
- `session_summary` 和 `generated_title` -- 会话摘要及其模型生成的标题
- `created_at` 和 `updated_at` -- 创建和最后更新时间戳
- `num_messages` 和 `num_chat_messages` -- 更新和聊天消息计数
- `current_model_id` -- 正在使用的模型
- `parent_session_id` -- 派生或恢复来源的父会话
- `agent_name` -- 上次保存会话时激活的智使定义

### 磁盘使用情况

在修改大量文件的会话中，回溯点快照 (已修改文件的副本) 是磁盘使用量最大的部分。使用 `/compact` 以减小历史记录的大小。

---

## 提示

- 当您当前的上下文不再相关时，使用 `/new` 全新开始。
- 在长会话中主动使用 `/compact` 来保持上下文窗口的有效。
- 使用 `/rewind` 撤销错误；它恢复实际的文件快照，而不是依赖于智使重建早期状态。
- 在[无头交互模式](14-无头交互模式.md)中，从 JSON 输出捕获 `sessionId` 并将其传递给 `-r`，以构建维持上下文的多步自动化过程。
- 检查 `/session-info` 查看使用了多少上下文窗口。
