# 斜杠指令

在 Prompt 中输入 `/` 即可打开指令菜单。它支持打字时的模糊匹配，选择一项指令将立即运行。

指令来源于两个地方：由 Agent 后端（codel-shell）处理的 **Shell 内置指令**，以及由 TUI 前端（codel-pager）处理的 **Pager 内置指令**。两者都会在同一个菜单中展示，且任何启用了 `user-invocable: true` 标记的技能扩展（Skill）也会出现在这里。

下面列出的每一条指令在其拥有别名时均已标记出来。少数指令仅在特定功能或会话状态启用时才可见，这些情况已在文内单独说明。

---

## 会话管理

### `/new`

开启一个全新的会话并清空当前对话历史。别名：`/clear`。

### `/resume`

打开会话选择器，以便从磁盘中重新加载历史会话。

### `/compact`

压缩对话历史记录以回收上下文窗口空间。

```
/compact
```

当上下文窗口占用率达到 85% 时，Codel 也会自动触发压缩（可通过 `[session] auto_compact_threshold_percent` 配置调整此阈值）。

### `/context`

显示当前上下文窗口的使用情况：按类别拆分（系统 Prompt、消息内容、推理与开销、剩余空间），以及关于工具定义、技能扩展列表和 MCP 服务器公告及其预计 Token 消耗的提示信息。

### `/session-info`

显示会话详细信息 —— 身份验证方式、当前模型、轮次数及上下文占用量。别名：`/status`、`/info`。

### `/fork`

将当前会话派生为一个新的 Agent，同时保留截至目前的全部历史记录。

### `/rewind`

将对话回滚到早先的某个轮次，并丢弃该轮次之后的所有内容。

### `/edit-prompt`

在极简模式（Minimal Mode）下，为空的编辑框打开外部编辑器。Codel 会依次解析 `$VISUAL`、`$EDITOR` 以及 `vi`；环境变量值可以包含带引号的参数。保存文件将仅替换草稿而不直接发送，保存空文件则会清空草稿。此指令在极简模式之外隐藏。

```
/edit-prompt
```

当终端或复用器占用了 `Ctrl+G` 时，如需编辑**已有**草稿，请打开命令面板并选择 **Edit Prompt in External Editor**。该直接路径可保留现有文本，且不会将粘贴内容、文件引用或图片碎片打散。在编辑框中直接打字输入 `/edit-prompt` 必然会覆盖原有输入，因此它总是从空草稿开始。

### `/copy`

将最近一条响应内容复制到剪贴板。可以传入数字以复制倒数第 N 条响应，或传入文件路径直接将文本写入文件而非剪贴板（在无法访问本地剪贴板的 SSH 远程环境中非常实用）。

```
/copy
/copy 2
/copy out.txt
/copy 2 ~/exports/last-reply.md
```

每次复制的内容还会同步写入备份文件 —— 默认为 `~/.codel/last-copy.txt`，或在设置了 `CODEL_COPY_FILE` 时写入该文件 —— 浮动提示（Toast）会明确告知你文本的具体保存位置，因此即使剪贴板无法访问或复制作为此终端无法确认的 OSC 52 转义序列发出时，你依然可以获取到内容。

### `/export`

将对话导出为文件或复制到剪贴板。

### `/quit`

退出应用程序。别名：`/exit`。

### `/home`

离开当前会话并返回欢迎界面。别名：`/welcome`。

### `/rename`

重命名当前会话。别名：`/title`。

```
/rename 新会话标题
```

## 模型与模式

### `/model <name>`

切换模型。接受模型 ID 或显示名称（不区分大小写）。当模型提供多个上下文窗口时，可随后传入窗口大小。对于支持推理努力程度的模型，最后可传入推理努力程度（Effort level）。选择器按相同顺序询问：模型、窗口、努力程度。别名：`/m`。

```
/model codel-build
/model Codel Build
/model Reasoning X high
/model Reasoning X 500k high
```

### `/effort <level>`

在不重新选择模型的情况下，为**当前**模型设置推理努力程度。可选级别为 `low`、`medium`、`high` 和 `xhigh`，且仅在当前模型支持推理努力程度时生效。

```
/effort high
```

### `/context-window <size>`

为当前模型设置上下文窗口。仅当模型支持多个窗口大小时，该指令才会列出。它接受简短标签或原始 token 数。该选择在会话内持续有效，并会延续到支持相同大小的新模型。若选择的大小小于当前用量，将触发一次自动压缩。

```
/context-window 500k
/context-window 256000
```

### `/always-approve` 与 `/auto`

两者均为权限模式的开关：它们保留在菜单中，再次运行当前已处于激活状态的模式将关闭该模式。

| 指令 | 关闭状态下 | 已开启状态下 |
|---|---|---|
| `/always-approve` | 跳过所有权限确认提示 | 退回为每次询问 (ask) |
| `/auto` | 自动审查：由分类器批准安全工具（高危工具仍可能提示确认） | 退回为每次询问 (ask) |

当一种模式正激活时运行另一种模式将切换模式 —— 例如，在始终自动批准开启时运行 `/auto` 会切换为自动审查模式。`/auto` 仅在启用了自动审查模式功能时显示。你也可以通过 `Shift+Tab`（在 Normal / Plan / 自动审查（启用时）/ Always-approve 之间循环切换）、`Ctrl+O` 或 `/settings` 来更改模式。

### `/multiline`

切换多行输入模式。开启后，按 `Enter` 插入新行，按 `Shift+Enter`（或 `Alt+Enter`）发送消息。在轮次进行中，在空编辑框上单独按 `Enter` 仍会强制发送队首排队的后续消息。别名：`/ml`。

### `/history`

打开 Prompt 历史搜索：以最新的优先模糊搜索当前会话的 Prompt，按 `Enter` 或 `Tab` 将匹配项填回输入框。

如需快速调出，可在空 Prompt 上直接按 `↑` 键。面板打开时会预填最近一条 Prompt；按 `↑`/`↓` 遍历历史条目（每条都会填入输入框），在最新条目后按 `↓` 关闭面板，直接打字可以原地编辑调出的 Prompt。

### `/compact-mode`

切换紧凑显示模式 —— 减少边距与行间距，提供更高密度的输出显示。

### `/vim-mode`

切换 Vim 风格的滚动历史导航按键（`j`/`k`、`h`/`l`、`g`/`G`、`y`/`Y` 等）。关闭时（默认状态），在滚动历史中单独按字母或 `Shift+字母` 仅会聚焦输入框并输入该字符。此设置会持久化到 `[ui] vim_mode`。

### `/minimal` 与 `/fullscreen`

在另一种渲染模式中重新打开当前会话。`/minimal`（在全屏模式下提供）切换到实验性的基于滚动历史原生的极简模式；`/fullscreen`（在极简模式下提供；别名 `/full`）切换回标准切屏 TUI 模式。两者都会在同一个会话的当前对话上重新启动 Pager —— 它们不会修改 `config.toml`，且重新启动的横幅会提示你如何切换回来。CLI 标志 `--minimal` / `--fullscreen` 也具有相同的会话作用域。若想让普通 `codel` 命令默认在某种模式下打开，请使用 `/settings` → **Default screen mode** 或设置 `[ui] screen_mode`。

### `/plan`

进入 Plan 计划模式。

```
/plan [任务描述]
```

### `/view-plan`

预览当前保存的计划。别名：`/show-plan`、`/plan-view`。

## 记忆与上下文（Memory）

`/flush`、`/dream` 和 `/memory` 要求开启记忆功能（使用 `--experimental-memory` 或设置 `CODEL_MEMORY=1`）；`/memory` 还要求配置有后端记忆服务。`/remember` 则始终可用。

### `/memory`

浏览、查看及管理已保存的记忆。传入 `on` 或 `off` 以启用或禁用记忆功能。别名：`/mem`。

```
/memory
/memory off
```

### `/flush`

立即将当前会话的知识保存至记忆库中，触发大模型对重要内容进行摘要总结。在历史压缩之前，或任何想要锁定上下文的时候均可使用该命令。

### `/dream`

运行记忆整合 —— 将会话日志合并归纳为有条理的主题模块。

### `/remember`

立即将一条笔记保存至记忆库中，无需等待自动摘要。

```
/remember 预发环境部署使用 eu-west 集群
```

## 钩子与插件（Hooks and Plugins）

`/hooks`、`/plugins`、`/marketplace` 和 `/skills` 均会打开同一个扩展模态框，分别对应各自的标签页。

### `/hooks`

打开扩展模态框并定位到 Hooks 标签页，在其中可以查看已加载的钩子、添加或删除自定义钩子，以及单独切换开启/关闭。该模态框不负责授予项目信任 —— 信任模型参阅 [10-钩子机制.md](10-钩子机制.md)。

Shell 端还提供了独立的 `/hooks-list`、`/hooks-trust`、`/hooks-add`、`/hooks-remove` 和 `/hooks-untrust` 指令；在 TUI Pager 中，这些均已被整合至 `/hooks` 模态框。

### `/plugins`

打开扩展模态框并定位到 Plugins 标签页，以查看已安装的插件、从市场安装新插件以及管理信任关系。

Shell 端另外支持子命令（`/plugins list`、`/plugins install <source>`、`/plugins uninstall <name>`、`/plugins update`、`/plugins reload`）。在 TUI 中，模态框提供了可视化操作。

### `/marketplace`

打开扩展模态框并定位到 Marketplace 标签页，以浏览和安装插件。

### `/skills`

打开扩展模态框并定位到 Skills 标签页，以查看已安装的技能扩展。

## 媒体生成

### `/imagine <description>`

根据文本描述生成图片。

```
/imagine a golden sunset over a calm ocean with silhouetted palm trees
```

### `/imagine-video <description>`

根据文本（或图片）描述生成视频。它会规划分镜、生成源图像并使用 `image_to_video` 将其转化为动画。


## 定时与循环任务

### `/loop [interval] <prompt>`

按循环时间间隔定期运行 Prompt。将时间间隔指定为 `30m`、`1 hour` 或 `every 2 days`；若省略，Codel 会主动提示询问。

```
/loop 30m check deploy status
/loop check deploy status every hour
```

时间间隔支持 `Ns`（秒，最小为 60）、`Nm`（分钟）、`Nh`（小时）或 `Nd`（天）；任何低于 60 秒的值都会提高至最小值。循环任务会在 7 天后自动到期，你可以使用创建循环时返回的 Task ID 通过 `scheduler_delete` 取消任务。

## 工作流与目标（Workflows and Goals）

### `/goal`

设定、管理或检查自主目标。Codel 可以跨多轮次工作，并且仅在独立的证据审查确认结论后才将目标标记为完成；如果审查无法复现结果或缺乏可用证据，目标将保持激活状态，或因具体差距而暂停。

```
/goal 将身份验证模块迁移至新 API
/goal status
/goal pause
/goal resume
/goal clear
```

参数格式为 `<objective> [--budget <tokens>]`，或者为 `status`、`pause`、`resume`、`clear` 之一。这里的 `--budget` 指目标运行的 **Token 预算**，与工作流使用的 Agent 数量预算相互独立。当会话启用了目标模式时，`/goal` 将在菜单中可见。具体由哪个驱动运行取决于后台工作流：在开启后台工作流时，宿主会评估每个模型轮次并对完成候选目标进行对抗性验证；在关闭时，由传统的面向模型的 `update_goal` 路径汇报进度并触发验证。

### `/deep-research <query>`

启动后台深度研究工作流。它会规划一组边界明确的问题，收集带来源证据的结构化论断，在独立的验证分片上交叉核对每个论断，并仅渲染通过验证的论断及其验证过的来源定位符。失败的分片、被丢弃的论断以及研究员的不确定性将作为覆盖局限性进行汇报；只要存在任何局限，报告就会被标记为 **Partial**（部分完成）。

```
/deep-research 对比 PostgreSQL 17 与 MySQL 9 的迁移风险
```

该命令会立即返回 —— 进度可以在 `/workflows` 中跟踪，最终的报告会自动出现在对话中。

模型启动的工作流可以在 `workflow` 工具上设置 `agent_budget`。它是对逻辑子 Agent 调用的绝对累计上限：每一次 `agent()` 调用以及 `parallel()` 面板中的每一个项目都会消耗一个名额，而 Schema 纠错重试则不消耗。默认上限为 128，显式设置范围为 1–1,024，任何可能超出剩余预算的面板都会在启动任何子项前被直接拒绝。`budget()` 会将上限汇报为 `total`，已批准的调用汇报为 `spent`，`reserved`（始终为零），以及 `remaining`。命名斜杠指令启动时使用默认预算。

### `/workflow`

启动已保存的工作流，或通过 `/workflows` 中显示的会话唯一显示名称管理运行中的工作流。如果多次启动同一个工作流，显示名称会自动附加编号（`review-changes`、`review-changes-2`）；你绝不需要使用内部的 Run ID。

```
/workflow review-changes {"target":"origin/main...HEAD"}
/workflow pause review-changes
/workflow resume review-changes
/workflow stop review-changes-2
/workflow save review-changes
```

项目级工作流保存在 `.codel/workflows/*.rhai` 中；用户级工作流保存在 `~/.codel/workflows/*.rhai` 中。同进程下的暂停/恢复（Pause/Resume）会基于已提交的宿主调用结果继续运行原始不可变的脚本、参数和 `agent_budget` 上限 —— 如需迭代更新，请编辑返回的脚本副本并作为新的运行启动。

预算受限的运行有所不同：它仅能通过由模型/工具发出的、提供高于已批准 Agent 数量的 `agent_budget` 的恢复请求来恢复。单纯的 `/workflow resume <name>` 无法提高上限，因此会拒绝预算受限的运行。因进程重启中断的运行根本无法恢复，因为外部效应不具备跨进程的稳定性。且恢复并非恰好一次（Exactly-once）：未在同进程暂停前提交结果的外部效应可能会重新运行。

### `/workflows`

打开实时工作流**运行**仪表板 —— 展示活跃和保留的运行记录，而非已保存定义的目录。每一行显示运行的显示名称、阶段、Agent 列表、进度和结果。在运行的详情视图中，按 `p` 暂停，按 `r` 恢复普通暂停，按 `x` 停止。预算受限的运行无法直接恢复：按 `r` 会返回 Shell 的拒绝提示（需通过提供更高 `agent_budget` 的模型/工具恢复请求提高上限），而按 `x` 仍可停止。按 `s` 可以保存该运行的脚本，但对于已知内置工作流和带编号的重复句柄会被隐藏 —— 对于这些工作流，请选择一个新的唯一 `meta.name` 并显式保存编辑后的脚本。

## 其他指令

### `/theme`

切换 TUI 颜色主题。别名：`/t`。

### `/btw`

在不中断当前任务的前提下向 Agent 发送补充说明/旁白。在极简模式（`--minimal`）下，答复会显示在输入框上方的可关闭面板中：按 `Esc` 可将其关闭，已完成的答复会保存到原生滚动历史中，而对已被关闭面板的延迟回复将被丢弃。旁白问题及其答复不属于主轮次的一部分。

```
/btw 顺便检查一下错误处理逻辑
```

### `/mcps`

打开 MCP 服务器管理模态框。

### `/doctor`

诊断当前会话的终端、剪贴板、颜色、输入、通知及沙盒问题。Doctor 会展示检测到的问题及对应的解决办法。运行 `/doctor fix` 可以列出可用的自动修复选项；其他检测项包含手动操作步骤。`/terminal-setup`、`/terminal-check` 和 `/terminal-info` 仍保留为别名。

### `/release-notes`

查看当前版本的更新日志。别名：`/changelog`。

### `/docs`

浏览 TUI 内置的操作指南、打开在线 Build 文档，或通过标题直接跳转至特定指南。别名：`/howto`、`/guides`。

```
/docs
/docs web
/docs Getting Started
```

- 单独运行 `/docs`（或 `/docs how-to`）将打开操作指南选择器。
- `/docs web` 将在浏览器中打开 https://docs.codel.dev/build/overview。
- `/docs <title>` 通过不区分大小写的标题匹配打开指定的指南。

### `/tutorial`

打开新手入门教程：包含简短的主题列表（你的第一个 Prompt、附带上下文、导航、斜杠指令、Worktree、Plan 模式、自定义、从其他 Agent 工具迁移）—— 每项均需约 30 秒阅读，按 `→` 键可直接跳转到下一个主题。没有任何内容会自动展示 —— 该指令（或命令面板）是唯一的入口。

```
/tutorial
```

别名：`/tour`、`/onboarding`

### `/import-claude`

打开 Claude 导入模态框，将 `~/.claude` 的设置导入进来：包括权限、环境变量、MCP 服务器、Hooks 和路径。

## 作为斜杠指令的技能扩展（Skill）

任何在其 SKILL.md 前言（Frontmatter）中包含了 `user-invocable: true` 的已启用技能扩展都会显示为斜杠指令。（通过 `/skills` 关闭某个技能扩展后，它将停止展示。）例如位于 `~/.codel/skills/commit/SKILL.md` 的技能扩展可以通过以下方式运行：

```
/commit fix typo in README
```

来自插件的技能扩展运行方式完全相同。当两个不同作用域的技能扩展重名时，可以使用前缀加以区分：

```
/local:commit      # 项目级作用域技能扩展
/user:commit       # 用户级作用域技能扩展
```

内置指令总是优先于同名的技能扩展。如果将一个技能扩展命名为 "compact"，`/compact` 依然会运行内置指令 —— 但 `/local:compact` 会调用该技能扩展。

## 自动补全

菜单支持模糊搜索：在 `/` 后输入字符即可过滤选项。每个条目均显示指令名称、描述、接受参数时的参数提示以及来源（builtin 内置、技能扩展作用域或插件名称）。按 `Tab` 或 `Enter` 键以接受高亮选中的指令。
