# 无头交互模式与脚本化 (Headless Mode and Scripting)

无头交互模式（Headless Mode）会在命令行中以非交互方式运行 Codel。它接受一个提示（prompt），并带着所有的工具权限执行该提示，然后返回结果。该模式常被用来自动化任务、编写脚本工作流、进行集成构建，以及程序化解析输出结果。

---

## 基本用法 (Basic Usage)

以非交互方式传入提示即可触发无头交互模式。最常用的方法是使用 `-p` 标志（`--single` 的缩写）；此外 `--prompt-json` 和 `--prompt-file` 也可触发此模式：

```bash
codel -p "Your prompt here"
```

Codel 会处理该提示，调用所需工具，并将结果输出到 stdout。响应完成后进程将退出。

---

## 命令行选项 (Command-Line Options)

| 标志 | 描述 |
| ----------------------- | ----------------------------------------------------- |
| `-p, --single <PROMPT>` | 要发送的提示词（或使用 `--prompt-json` / `--prompt-file`） |
| `-m, --model <MODEL>`   | 使用的模型 (如 `codel-build`) |
| `-s, --session-id <ID>` | 使用此 **UUID** 创建一个 **新** 会话 (如果提供无效 UUID 或该 ID 已在目标会话目录下存在，则报错；不会继续会话 — 续传请使用 `-r`/`-c`) |
| `--fork-session`        | 与 `-r`/`-c` 搭配，不再附加到原始会话中，而是分支出一个新的会话 ID |
| `-r, --resume <ID_OR_TITLE>` | 通过 ID 或标题 (当前目录下，忽略大小写) 继续现有会话。如果按标题匹配到多个项，则保留手动重命名的唯一匹配项，否则如果都是自动生成的标题则报错并打印所有 ID。UUID 格式的字符串始终视为 ID 路径；编写脚本应优先使用 ID。 |
| `-c, --continue`        | 在当前目录中继续最近的一次会话 |
| `--cwd <PATH>`          | 设置工作目录 |
| `--output-format <FMT>` | 输出格式：`plain`, `json`, `streaming-json` |
| `--yolo`                | 自动同意所有的工具执行操作 |
| `--rules <TEXT>`        | 针对系统提示词的自定义规则 |
| `--tools <TOOLS>`       | 内置工具的白名单（逗号分隔）。若未显式拒绝，MCP 的元工具仍可用。仅无头模式可用。 |
| `--disallowed-tools <TOOLS>` | 内置工具的拒绝名单（逗号分隔）。支持 `Agent`（智使）相关内容。仅无头模式可用。 |
| `--max-turns <N>`       | 自动终止前最多运行的智能回合数。仅无头模式可用。 |
| `--reasoning-effort` / `--effort <LEVEL>` | 推理模型的推理计算力投入程度。规范层级有：`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`。也可接收各模型自己的枚举值。TUI 交互端和无头交互模式下均支持。 |
| `--permission-mode <MODE>` | 权限模式。传入 `bypassPermissions` 可强制通过此标志始终通过所有申请（见 [22-权限与安全.md](22-permissions-and-safety.md)）；如果想要默认拒绝，请在 `.claude/settings.json` 中配置 `defaultMode`。 |
| `--allow <RULE>`        | 权限白名单规则，支持通配符模式（可多次指定）。TUI 和无头模式均支持。 |
| `--deny <RULE>`         | 权限黑名单规则，支持通配符模式（可多次指定）。TUI 和无头模式均支持。 |
| `--prompt-json <JSON>`  | 传入以 JSON 形式定义的内容块提示词 |
| `--prompt-file <PATH>`  | 从文件中读取提示词 |
| `--verbatim`            | 将所给的提示词原样发送 |
| `--no-auto-update`      | 在本次会话中禁用自动检查更新 |
| `--sandbox <PROFILE>`   | 使用指定的沙盒安全环境配置来管理文件系统/网络访问 |

> **注意：** `--tools`、`--disallowed-tools`、`--max-turns` 和 `--agents` 是仅限于无头模式的标志。如果在交互式 TUI 中使用，程序将打印警告并忽略该标志。`--reasoning-effort`/`--effort`、`--permission-mode`、`--allow` 和 `--deny` 在两种模式下均可工作。有关其他标志（分身智使和 worktree 工作树），请参阅 [附加无头标志](#附加无头标志-additional-headless-flags)。

### 工具过滤 (Tool Filtering)

使用 `--tools` 将智使限制为显式允许的工具集（白名单），或者使用 `--disallowed-tools` 从默认集合中移除特定工具（黑名单）。两项都接受逗号分隔的工具名称。

注意：工具名称是工具的内部 ID（例如，shell 工具的 ID 是 `run_terminal_cmd`，而不是 `bash`）。

```bash
# 只允许只读工具
codel -p "Explain this codebase" --tools "read_file,grep,list_dir"

# 移除网络访问和文件编辑权限
codel -p "Review this code" --disallowed-tools "web_search,web_fetch,search_replace"

# 取消 shell 执行权限
codel -p "Review this code" --disallowed-tools "run_terminal_cmd"
```

`--disallowed-tools` 还支持针对控制分身智使创建的特定 `Agent` 内容：

| 内容 | 作用 |
| ---------------------- | --------------------------------------- |
| `Agent`                | 阻止创建所有的分身智使 |
| `Agent(explore)`       | 只阻止类型为 `explore` 的分身智使 |
| `Agent(explore, plan)` | 阻止多种特定类型的分身智使 |

```bash
# 阻止智使孵化出任意分身智使
codel -p "Fix this bug" --disallowed-tools "Agent"

# 仅阻止探索（explore）类型分身
codel -p "Refactor this module" --disallowed-tools "Agent(explore)"
```

`--tools` 会保留所选智使配置下的注入策略：预置配置会先注入已开启的可选工具然后再适用白名单，精简版配置则更严格。最终的工具集保留了申请的工具，以及常驻的 MCP 元工具。当白名单与黑名单共存时，`--disallowed-tools` 会优先生效。

### 权限规则 (Permission Rules: `--allow` / `--deny`)

权限规则控制特定的工具调用是否被自动批准、拒绝，或是需要用户手动确认。不同于 `--disallowed-tools` (将工具完全剥除)，权限规则保留了工具本身可用性，仅对其执行进行权限把关。

规则使用 `ToolPrefix(glob_pattern)` 的语法形式：

| 前缀 | 规则适用对象 |
| ------------- | ---------------------------------- |
| `Bash(...)`   | Shell 命令执行 |
| `Edit(...)`   | 文件编辑（路径的 glob 匹配） |
| `Write(...)`  | 文件写入（路径的 glob 匹配） |
| `Read(...)`   | 文件读取（路径的 glob 匹配） |
| `Grep(...)`   | 搜索操作（路径的 glob 匹配） |
| `WebFetch(...)` | URL 获取（glob 或 `domain:host` 形式） |
| `MCPTool(...)` | MCP 工具调用 |

对于路径类的规则 (`Read`, `Edit`, `Write`, `Grep`)，`*` 是单层级通配符，而 `**` 则支持递归层级。对于 `Bash` 规则，`*` 可匹配任何字符（包含空格）。没有括号的纯前缀会匹配该类型下的任何调用。`Bash(cmd:*)` 等价于在命令最前方进行前缀匹配。有关完整的匹配语意，请见 [22-权限与安全.md](22-permissions-and-safety.md#rule-matching-reference)。

```bash
# 拒绝任何 "rm*" 的 Shell 命令
codel -p "Clean up this project" --deny "Bash(rm*)"

# 允许 npm 命令自动执行，但拒绝 sudo 命令
codel -p "Set up the project" --allow "Bash(npm*)" --deny "Bash(sudo*)"

# 允许所有 bash 命令（自动批准不提示）
codel -p "Build the project" --allow "Bash"
```

`--allow` 和 `--deny` 都支持多次传入。拒绝规则优先级高于允许规则。

## 输出格式 (Output Formats)

无头交互模式支持三种输出格式，可通过 `--output-format` 指定。

### plain (默认)

适合直接在终端中显示，或者是进行管线传递的纯文本：

```
Here's a summary of the codebase...
```

### json

等到响应完成时返回的单个 JSON 对象格式：包含响应内容、结束原因、会话 ID、请求 ID（以及有推理过程时的 `thought` 字段）。当提示被成功发送到模型后，此 JSON 对象还会包含耗量（spend）字段（`usage`，`num_turns`，`modelUsage`，以及对应开销成本）。

```json
{
  "text": "Here's a summary of the codebase...",
  "stopReason": "EndTurn",
  "sessionId": "abc123",
  "requestId": "xyz789",
  "num_turns": 7,
  "usage": {
    "input_tokens": 7210,
    "cache_read_input_tokens": 41000,
    "output_tokens": 1893,
    "reasoning_tokens": 412,
    "total_tokens": 50103
  },
  "modelUsage": {
    "codel-build": {
      "inputTokens": 7210,
      "outputTokens": 1893,
      "cacheReadInputTokens": 41000,
      "modelCalls": 7,
      "costUSD": 0.01268905
    }
  },
  "total_cost_usd": 0.01268905,
  "total_cost_usd_ticks": 126890500
}
```

使用说明：

- `usage` 汇总了用于处理提示的总 Token 数目，这包含了已在回合结束前完毕的分身智使消耗的 Token（同时也记录在各自的 `modelUsage` 键下）。压缩 (Compaction) 以及其他侧边模型的调用不会计算在内。
- **Token 数据策略 (无头模式 / `end` 事件 / 错误耗量):**
  - `usage.input_tokens` 和 `modelUsage.*.inputTokens` 指的是 **未命中缓存的** Token 数。
  - `cache_read_input_tokens` / `cacheReadInputTokens` 表示缓存命中的 Token 数。
  - `total_tokens` 为全部输入输出（包含缓存），即：`total_tokens = input_tokens + cache_read_input_tokens + output_tokens`。
  - ACP 里的 `_meta.usage.inputTokens` 仍统计 **全部的** 输入；只有无头模式中的字段减去了缓存部分。自动统计脚本建议以无头模式中的数据为准。
- `num_turns` 是主智能体记录在调用回合中的模型计次，分身智使并不累加到此处。各项包含分身智使的细分模型计次保存在 `modelUsage.*.modelCalls` 下。这和 `--max-turns` 使用同一套计数，不过遇到大门槛等原因可能略有细微出入。
- 只有服务端确实返回了 **完整** 的额度数据时才会存在 `total_cost_usd` 字段。缺少它仅仅代表没回报额度，并不等于是免费。额度一般通过 API 密钥获得；通过 OAuth 的方式一般不会在服务器完成盖章以前返回该内容。当有些调用没有结算时，`cost_is_partial` 置为真，且 **所有** 相关的花费会被略过不展示。
- `total_cost_usd_ticks` 用精确整数描述相同内容（1 USD = 10^10 ticks），且只有在相同条件达成时才显示，适合对账计算，防止出现浮点数缺失。
- 当有分身智使的 Token 未正确结算，存在内部分身智使数据缺失，或等待回调任务超时（最长 120 秒），则视作结算残缺（`usage_is_incomplete`），将省略各项相关额度字段。如果结算残缺且没有任何 Token 记账数据时，则只会发回 `usage_is_incomplete`（不存在值为 0 的 `usage` 记录块）。
- 若根本没有传递到大模型，则省略相关字段。

在返回的结果中，`sessionId` 字段有助于后续通过 ID 唤起历史会话。

对于出错的情境下，Codel 输出（并有非 0 退出代码）：当错误发生于提示阶段，只要曾有过开销数据也会带上 `usage`。

```json
{"type":"error","message":"Couldn't start session: ..."}
```

### streaming-json

支持以行为单位输出基于事件状态通知机制的 JSON。每一行独立包含完整的 JSON 体，内有 `type` 定义：

```json
{"type":"text","data":"Here's"}
{"type":"text","data":" a summary"}
{"type":"thought","data":"Analyzing the directory structure..."}
{"type":"end","stopReason":"EndTurn","sessionId":"abc123","requestId":"xyz789","usage":{...},"num_turns":7,"modelUsage":{...}}
```

事件类型（Event types）：

| 类型       | 描述                                                    |
| ---------- | -------------------------------------------------------------- |
| `text`     | 智使回复的一块文本切片                            |
| `thought`  | 内部推理信息块                            |
| `end`      | 最终结算事件，带有相关参数与开销总结       |
| `error`    | 发生异常中止的事件报告  |

`end` 必定在最末尾抛出。`end` 内记载的 `usage` 结算符合单个 json 中的形式标准（如 `input_tokens` 即代表了没命中的耗量，而安全的开销小数也如此记载）。
Codel 可能还会送出 `max_turns_reached` 与 `auto_compact_*` 等事件。需要对 `type` 进行 switch 分类。

## 在无头交互模式中的会话管理 (Session Management in Headless Mode)

在默认状态下，每一次使用 `codel -p` 都会创建独立的新会话。要承继先前的环境上下文，需要指定相应的会话标志位。

### 指定名称开启 (`-s`)

要在多次调用之间保存上下文状态，请使用 `-r/--resume` 和 `-c/--continue`。请注意 `-s/--session-id` 仅用于为 **新** 会话分配具体的 **UUID** 标识。历史版本那种 `-s` 作为读写的二合一功能的场景已剔除，在现今请分门别类采用对应参数。若将 `-s` 搭配 `-r`/`-c` 使用，还需要传入 `--fork-session` 以分支出来：

```bash
# 启动会话并抓取 ID
codel -p "Review the changes in this PR" --output-format json | jq -r '.sessionId'

# 接力会话
codel -p "Now check for security issues" --resume "<id>"

# 可选：用指定的新 UUID 开启 (目标不应已经存在)
codel -p "hello" --session-id "$(uuidgen | tr '[:upper:]' '[:lower:]')" --output-format json
```

> **注意：** `-s/--session-id` 只创建新会话（合法的 UUID；冲突报错）。接续历史使用 `-r`。

### 恢复接力会话 (`-r`)

`-r/--resume` 根据会话 ID，或者利用会话标题来从工作目录的历史中唤起某次会话（忽略大小写等）。假如标题名字冲突且系统判定不出是哪一次的手动重命名，则会弹回错误及历史所有 ID。只要传入的符合 UUID 的正则表达式结构，都会按 ID 路径唤醒：

```bash
# 获取之前的 sessionId
codel -p "Remember: the secret number is 42" --output-format json
# 输出包含了 "sessionId": "abc123"

# 精准接力
codel -p "What's the secret number?" --resume abc123
```

### 继续最新的会话 (`-c`)

使用 `-c/--continue` 可以使当前目录的最近一次历史会话立刻继续：

```bash
codel -p "Continue where we left off" -c
```

### 提取会话 ID (Extracting Session IDs)

启用 `--output-format json` 然后解析其中的 `sessionId`：

```bash
codel -p "Hello" --output-format json | jq -r '.sessionId'
```

## 管道输入与输出 (Piping Input and Output)

无头模式自然支持在 Unix 的管道间穿梭导流。

### 标准输出 (Standard Output)

```bash
# 导入文件
codel -p "Generate a README" > README.md

# 使用 jq 解析 JSON
codel -p "List files" --output-format json | jq -r '.text'
```

### 标准输入 (Standard Input)

对于通过管道（如 `| codel -p ...`）写入的情形，并不会直接进入到对话内容。请采用反引号，命令替换（`$()`）等，或是直接 `--prompt-file` 读取：

```bash
# 利用 git diff 的返回内容植入为上下文
codel -p "Write a concise commit message for these changes:

$(git diff --staged)"

# 或者从文本引入
codel --prompt-file ./prompt.txt
```

```bash
codel -p "Review changes for bugs and security issues." \
```

### Git pre-commit Hook

```bash
codel -p "Review staged changes for obvious bugs. Reply OK if fine, or list issues." \
  --yolo --output-format json | jq -r '.text' | grep -q "^OK" || exit 1
```

```bash
for file in src/*.js; do
  codel -p "Migrate $file from CommonJS to ES modules." --yolo
done
```

## 脚本编写模式 (Scripting Patterns)

### Python 封装套壳 (Python Wrapper)

Codel 无头模式可以很顺畅地封装为类似 OpenAI 的流式接口请求。

```python
import asyncio
import json
import os

class CodelChat:
    """Simple OpenAI-compatible wrapper using headless mode."""

    def __init__(self, cwd="."):
        self.cwd = cwd
        self.env = {**os.environ}

    def _build_cmd(self, prompt, model, stream):
        return ["codel", "-p", prompt, "-m", model, "--cwd", self.cwd,
                "--output-format", "streaming-json" if stream else "json",
                "--yolo"]

    async def create(self, messages, model="codel-build", stream=False):
        prompt = messages[-1]["content"] if len(messages) == 1 else "\n".join(
            f"{m['role']}: {m['content']}" for m in messages
        )
        cmd = self._build_cmd(prompt, model, stream)

        if stream:
            return self._stream(cmd)

        proc = await asyncio.create_subprocess_exec(
            *cmd, env=self.env, stdout=asyncio.subprocess.PIPE
        )
        stdout, _ = await proc.communicate()
        data = json.loads(stdout.decode()) if stdout else {"text": ""}
        return {
            "choices": [{
                "message": {"role": "assistant", "content": data.get("text", "")},
                "finish_reason": "stop"
            }]
        }

    async def _stream(self, cmd):
        proc = await asyncio.create_subprocess_exec(
            *cmd, env=self.env, stdout=asyncio.subprocess.PIPE
        )
        async for line in proc.stdout:
            if not line.strip():
                continue
            event = json.loads(line)
            if event.get("type") == "text":
                yield {"choices": [{"delta": {"content": event["data"]}}]}
            elif event.get("type") == "end":
                yield {"choices": [{"delta": {}, "finish_reason": "stop"}]}


async def main():
    client = CodelChat(cwd=".")
    response = await client.create(
        [{"role": "user", "content": "What files are here?"}]
    )
    print(response["choices"][0]["message"]["content"])

asyncio.run(main())
```

### Shell Script

```bash
#!/bin/bash
# Run a code review and exit with failure if issues are found

RESULT=$(codel -p "Review this PR for bugs. Output JSON with 'issues' array." \
  --output-format json --yolo | jq -r '.text')

ISSUE_COUNT=$(echo "$RESULT" | jq '.issues | length' 2>/dev/null || echo "0")

if [ "$ISSUE_COUNT" -gt 0 ]; then
  echo "Found $ISSUE_COUNT issues"
  echo "$RESULT" | jq '.issues[]'
  exit 1
fi

echo "No issues found"
```

## 全自动运行模式 (`--yolo`)

`--yolo` 用于一直无差别自动通行。这种授权等价于在文件内定义为 `--permission-mode bypassPermissions` 或命令行里的 `--always-approve`。不会针对各种权限读写作额外确认。当遇到明确拒绝或者拦截（比如 `PreToolUse` 的挂钩设定），才会停止。见 [22-权限与安全.md](22-permissions-and-safety.md)。这是脱手自动化必须的标志：

```bash
# 格式化所有文件无需手工确认
codel -p "Format all files" --yolo

# 运行各种测试，自己决定怎么修复并重试
codel -p "Run the tests and fix any failures" --cwd ~/projects/my-app --yolo
```

**请谨慎使用 `--yolo` 标志。** 它赋予了智使最大的自由去覆写、操作命令。应该只能用于安全受控的区域，或是限制了范围明确无风险的指令内。

## 环境变量指引 (Environment Variables for Headless)

能够对无头交互模式产生影响的环境变量参数：

| 变量                        | 描述                                                   |
| ------------------------------- | ------------------------------------------------------------- |
| `CODEL_API_KEY`        | 设定 API key 用于鉴权调用大模型   |
| `CODEL_HOME`                    | 覆盖当前的设置文档读取位置 (默认: `~/.codel`)                |
| `CODEL_LOG_FILE`                | 直接引导打印内容的写出日志位置 (在 TUI 及无头均适用，继承自 `RUST_LOG`) |
| `RUST_LOG`                     | 用于调试（如 `debug` 级过滤日志），打印往 stderr 中     |

对于 CI 此类无法正常浏览器验证的执行环境中，可以自行使用 `CODEL_API_KEY`（在 [console.codel.dev](https://console.codel.dev) 申请获取）：

```bash
export CODEL_API_KEY="codel-..."
codel -p "Run the test suite" --yolo
```

## 退出状态码 (Exit Codes)

| 代码 | 具体含义                              |
| ---- | ------------------------------------ |
| `0`  | 成功执行 -- 指令已正常收尾完毕 |
| `1`  | 失败报错 -- 遇到如认证失败，网络问题或其它错误 |
| `130` | 遇到 SIGINT 强行退出 (Ctrl+C)                                   |
| `143` | 由于 SIGTERM 中止执行进程                                            |

## 用于无头环境的身份验证 (Authentication for Headless Environments)

无头模式的身份验证推荐途径：

- **`CODEL_API_KEY`** — 对 CI 系统和无浏览器环境最友好。如上方 [环境变量指引](#环境变量指引-environment-variables-for-headless) 介绍的那样。

设置好 API 密钥后，Codel 会自动读取并用于认证。

## 技巧与说明 (Tips)

- 默认情境下无头交互模式每次调取都是产生一个 **新的会话**，必须使用 `-r/--resume` 和 `-c/--continue` 来连缀会话状态。
- 在 `--output-format json` 打印数据中必定包含 `sessionId` 的哈希用于连缀会话。
- 采用 `--yolo` 时，如果想再增加特定防护限制，可以使用 `--rules "Never delete files"`。
- 需要查验问题出在何处？请启用日志调试 `RUST_LOG=debug codel -p "..." 2> debug.log`。

## 项目根目录定位 (Project Root Discovery)

当 Codel 启动后，它会在由 `--cwd` 传入的工作目录下往上探寻查验直至它找到第一层的 `.git` 数据区。

注意：如果你是在一个巨大的代码库深处使用 `--cwd` 指定起始点，Codel 仍然会将其全部当作根目录搜集项目内容。会导致大批检索如技能、分身智使等造成延迟，务必注意工作路径的选定。

## 文件位置一览 (File Locations)

Codel 在默认 `~/.codel` 目录下存放相关材料 (可以用 `CODEL_HOME` 替换)：

| 路径                     | 内容                              |
| ------------------------ | ------------------------------------- |
| `config.toml`            | 用户相关的程序配置文件                    |
| `auth.json`              | 已缓存好的 API 验证/账号密码票据         |
| `version.json`           | 检查自动更新时的版本状态号       |
| `sessions/`              | 各个对话保存内容的转储（SQLite）          |
| `memory/`                | 长期记忆数据中心            |
| `logs/`                  | 相关日志与信息打印（譬如 `unified.jsonl`） |
| `logs/mcp/`              | 记录所有启动并互动的 MCP 后端日志                       |
| `skills/`                | 用户专属自定义技能存放区                |
| `personas/`              | 个性化的角色扮演智使            |
| `crash/`                 | 崩溃报告记录                         |
| `trace-exports/`         | 被导出的跟踪回放                 |
| `worktrees/`             | 记录工作树相关的核心信息                 |

### 对 `~/.codel` 执行只读化 (Read-Only `~/.codel`)

针对一些对容器、流水线上有强要求锁死的 `~/.codel`：

- 可预先放进写好的 `auth.json` 或者采用 `CODEL_API_KEY`
- 会默认丢弃并忽略存回本地的会话保存（成为短暂会话）
- 更新的提示将仅仅作为一则不执行的日志报警忽略过去

```bash
export CODEL_API_KEY="codel-..."
export CODEL_DISABLE_AUTOUPDATER=1
codel -p "..." --no-auto-update
```

## 更新屏蔽方案 (Update Check Suppression)

| 方案途径                          | 效力持续周期     |
| ------------------------------- | --------- |
| `--no-auto-update`              | 一次会话内   |
| `CODEL_DISABLE_AUTOUPDATER=1`    | 伴随环境   |
| 发现终端非 TTY 输入环境 (已内建侦听)  | 自动阻止并抑制 |
| `[cli] auto_update = false`     | 持久生效|

`CODEL_DISABLE_AUTOUPDATER` 会自动转意一些关闭状态词汇。SDK 开发环境中也是藉由这一环境变量封锁了不必要的分身智使升级通知。非官方渠道安装可能不会在背景中自动提示更新。

所有的更新预报信息都会推向 **stderr**，标准流 stdout 不受任何干扰。有关 [环境变量指引](#环境变量指引-environment-variables-for-headless) 继续参照前文。

## 无头交互被强行中断的逻辑 (Interrupted Headless Runs)

若抛出 SIGINT / SIGTERM 中断，将会：

- 会话状态停在最后一个完整生效的工具轮次节点。
- 所有产生在工具内如硬盘等处的改动，将 **不能** 得到任何回调性质的回退（rollback）。
- 在检测为 Ctrl+C 中断的返回值为 `130` (`128 + 2`) 而被终止杀死抛出退出值为 `143` (`128 + 15`)，方便在 CI 这种流水线作业中过滤一般情况遇到的程序报错 `1` 并特殊关照它们。
- 请采用如下连缀手法重连 `codel -p "continue" --resume "<id>"` 或 `codel -p "continue" --continue`。

有关接力重连和读取操作参阅 [在无头交互模式中的会话管理](#在无头交互模式中的会话管理-session-management-in-headless-mode) 中的相应细节。
