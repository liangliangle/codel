# 分身智使与人设

分身智使 (Subagents) 是独立的子会话，可并行处理任务。每个分身智使都拥有自己独立的上下文窗口，因此主智使可以将工作（如研究、实现、测试和代码审查）委托给它们，而不会消耗自身的上下文限制。分身智使向父级完成报告时通常只返回摘要。

分身智使默认开启。

---

## 智使 vs 人设 (Agents vs Personas)

智使和人设都可以自定义行为，但它们在不同层面上运作：

| | **智使 (Agents)** | **人设 (Personas)** |
|---|---|---|
| **配置内容** | 整个会话：模型、工具、提示词模式、系统提示词 | 添加到分身智使提示词中的行为覆盖层 |
| **作用范围** | 主会话或分身智使 | 仅限分身智使 |
| **设置方式** | 在启动时，或通过智使定义（在 `.codel/agents/` 或 `~/.codel/agents/` 中的 `.md` 文件） | 在 `config.toml` (`[subagents.personas]`) 或 `.codel/personas/` 下的 `.toml` 文件中；在分身智使解析时应用 |
| **控制内容** | 模型、工具可用性、提示词主体、技能 | 语气、输出格式、任务焦点以及输入/输出契约 |
| **编辑者** | 用户 -- 在智使面板中创建、删除或切换，或通过编辑文件 | 用户 -- 在配置或文件中定义自定义人设；内置人设为只读 |
| **示例** | `codel-build`, `explore`, `plan` | `researcher`, `concise` |

智使定义了会话本身。人设塑造了分身智使在会话中的行为。分身智使总是作为某一种智使类型运行（例如，`general-purpose`），而解析过程可以在其上叠加一个人设。

可以在智使面板中管理这两者。使用 `/config-agents` (别名 `/agents`) 打开它，或者使用 `/personas` 直接打开“人设”选项卡。该面板有两个选项卡：**Agents** 和 **Personas**。

---

## 禁用分身智使

使用环境变量或配置文件禁用分身智使：

```bash
export CODEL_SUBAGENTS=0              # 环境变量
```

```toml
# ~/.codel/config.toml
[subagents]
enabled = false
```

---

## 分身智使如何工作

当主智使识别出需要委托的工作时，它会调用 `spawn_subagent` 工具来启动一个子会话。子会话运行于：

- 独立于父级的自身上下文窗口
- 由其智使类型和可选的能力模式 (capability mode) 决定的工具集
- 在解析期间应用的可选人设指令

当子级完成时，父级会收到子级的输出——通常是一个摘要。

---

## 内置智使类型

`spawn_subagent` 工具接受一个 `subagent_type` 参数，用于选择子级的角色：

| 类型              | 描述                                                 |
| ----------------- | ---------------------------------------------------- |
| `general-purpose` | 默认类型。适用于任何任务的全能力智使。               |
| `explore`         | 研究智使。搜索、阅读、使用 grep 并运行 shell 命令，但不编辑文件。将其用于代码库调查。 |
| `plan`            | 计划智使。探索代码库并生成结构化的实现计划；不编辑文件。 |

项目或用户定义的智使可以添加新类型，或者通过名称覆盖这些内置类型。

---

## 人设 (Personas)

人设是一种具名的行为覆盖层。它的指令作为 `<system-reminder>` 注入到分身智使的会话中，这将在不改变分身智使的智使类型、模型或工具的情况下塑造语气、输出格式和任务焦点。

在 `config.toml` 或 `.toml` 文件中定义人设：

```toml
[subagents.personas.researcher]
instructions = "You are a thorough researcher. Always cite specific file paths."
description = "Deep investigator."
```

Codel Build 会按照以下优先级顺序从这些位置发现基于文件的人设：

- `.codel/personas/*.toml` (项目)
- `~/.codel/personas/*.toml` (用户)
- 捆绑的人设目录 (最低优先级)

每个文件定义一个人设，不带扩展名的文件名将成为人设名称。内联在 `config.toml` 中的人设优先级高于文件。仅发现 `.toml` 文件。

在智使面板 (`/personas`) 的 Personas 选项卡中管理人设。捆绑的人设是只读的；您定义的人设是可编辑的。

> **注意：** Codel Build 通过分身智使解析和角色应用人设，而不是通过 `spawn_subagent` 参数。主智使在生成子级时不会传递人设名称。

### 人设字段

| 字段                | 描述                                                                |
| ------------------- | ------------------------------------------------------------------- |
| `instructions`      | 作为人设层应用的内联指令文本。                                      |
| `instructions_file` | 指令文件的路径，在生成时加载，并在 `instructions` 之后合并。        |
| `description`       | 人设目录中显示的简短摘要。如果未提供，则回退到 `instructions` 的第一段。 |
| `inputs` / `outputs`| 声明的输入和输出契约 (见下文)。                                     |
| `model`             | 使用该人设时应用的模型覆盖。                                        |
| `reasoning_effort`  | 使用该人设时应用的推理努力程度。                                    |
| `default_isolation` | 默认的隔离模式 (`none` 或 `worktree`)。                             |

### 输入/输出契约

人设可以声明它期望的输入和产生的输出。父级智使读取这些信息以了解提供什么上下文以及期待什么工件。这使您能够串联人设，以便一个人设的输出文件成为下一个人设的输入：

```toml
[[subagents.personas.reviewer.inputs]]
name = "review_file"
io_type = "file"
required = true
description = "Path to the code under review"

[[subagents.personas.reviewer.outputs]]
name = "summary_file"
io_type = "file"
required = false
description = "Path to write review notes"
```

每个字段都有一个 `name`，一个 `io_type` (默认为 `file`)，一个 `required` 标志和一个 `description`。

### 人设解析

应用人设时，Codel Build 按照以下顺序（从高到低优先级）解析有效的模型和推理努力程度：

1. 显式的生成时覆盖
2. 角色默认值
3. 人设默认值
4. 父会话

隔离遵循相同的前三个步骤顺序，但默认为 `none` (无工作树)，而不是从父会话继承。

如果请求了一个人设但无法解析——未找到、没有指令，或者其 `instructions_file` 无法读取——则生成失败。

## 生成分身智使

主智使调用 `spawn_subagent` 工具。它的参数如下：

| 参数              | 描述                                                             |
| ----------------- | ---------------------------------------------------------------- |
| `prompt`          | 分身智使的完整任务提示词。                                       |
| `description`     | 任务的简短标签 (3-5 个单词)。                                    |
| `subagent_type`   | 要启动的智使类型。默认为 `general-purpose`。                     |
| `background`      | 在后台运行分身智使并立即返回一个分身智使 ID。默认为 `false`。    |
| `capability_mode` | 限制分身智使的工具：`read-only`, `read-write`, `execute`, 或 `all`。 |
| `isolation`       | `none` (共享工作区，默认) 或 `worktree` (隔离的 git 工作树)。    |
| `resume_from`     | 继续一个已完成的分身智使的会话。传入其分身智使 ID。              |
| `cwd`             | 分身智使的工作目录。与 `isolation: worktree` 互斥；当设置了 `resume_from` 时将被忽略 (恢复的子级继承其来源的目录)。 |

在后台运行分身智使时，可以稍后通过 `get_command_or_subagent_output` 检索其结果。

---

## 能力模式 (Capability Modes)

能力模式是对分身智使工具的一个可选的粗略过滤器：

| 模式         | 读取 | 写入 | 执行 | 描述                                         |
| ------------ | ---- | ---- | ---- | -------------------------------------------- |
| `read-only`  | 是   | 否   | 否   | 读取、搜索和检查 (以及 web search 和 LSP)；没有文件编辑或 shell。 |
| `read-write` | 是   | 是   | 否   | 读取，以及创建、编辑、删除和移动文件。没有 shell。 |
| `execute`    | 是   | 否   | 是   | 读取，以及运行 shell 命令和后台任务。没有文件编辑。 |
| `all`        | 是   | 是   | 是   | 不受限制的工具访问。                         |

如果您省略 `capability_mode`，则分身智使使用其智使类型的工具集。内置的 `explore` 和 `plan` 类型可以读取、搜索和运行 shell 命令，但不能编辑文件；`general-purpose` 则带有完整的工具集。

## 上下文继承

### resume_from

`resume_from` 参数允许一个新的分身智使从一个已完成的分身智使中断的地方继续，这对于多阶段工作流非常有用：

1. 生成一个研究分身智使来调查问题。
2. 生成第二个分身智使，将 `resume_from` 设置为第一个分身智使的 ID，这样它就能在拥有全部研究上下文的情况下接续工作。

新的分身智使继承了源的对话记录、工具状态和模型；它的系统提示词和工具则从当前的智使定义中重新渲染。源必须已完成 (未在运行)，属于当前会话，并使用相同的智使类型。

---

## 隔离：工作树模式

对于修改文件的任务，可以使用 `isolation: worktree` 在隔离的 git 工作树中运行分身智使。这可防止子级的编辑与父级的编辑发生冲突：

- 分身智使在工作树自己的副本中工作。
- 它的更改与父级保持隔离，直到您将它们合并。
- 分身智使的结果包括工作树的路径。

Codel Build 通过 `codel.dev/git/worktree/*` 扩展方法管理工作树，包括将更改合并回主工作目录的 apply 操作。

## 配置

### 按类型切换与模型覆盖

禁用特定的智使类型，或者将它们路由到不同的模型：

```toml
[subagents.toggle]
explore = true                       # 默认值 -- 省略以保持启用
plan = false                         # 禁用计划分身智使

[subagents.models]
explore = "codel-build"               # 将 explore 路由到特定的模型
```

按类型指定的模型覆盖适用于任何父级。如果没有覆盖，分身智使将继承父级的模型。

### 自定义角色与人设

定义具有自身能力和模型默认值的自定义角色：

```toml
[subagents.roles.researcher]
description = "Deep research agent"
default_capability_mode = "read-only"
model = "codel-build"
prompt_file = ".codel/prompts/researcher.md"
```

定义具有行为指令的自定义人设：

```toml
[subagents.personas.concise]
instructions = "Be concise. No filler words."
# instructions_file = ".codel/personas/concise.md"  # 或从文件加载
```

Codel Build 还会从 `.codel/roles/*.toml` 发现角色，从 `.codel/personas/*.toml` 发现人设。内联在 `config.toml` 中的定义优先级高于文件。

## 任务窗格 (TUI)

Codel Build 在智使屏幕的侧面窗格中显示正在运行和已完成的工作：

- 按 `Ctrl+G` 切换任务窗格，它列出了活动的和已完成的分身智使和后台命令及其状态。
- 按 `Ctrl+T` 切换单独的待办事项 (todo) 窗格。

要查看可用的智使类型和人设，请按 `Ctrl+P` 打开命令面板，然后选择 **Manage Agents** (`/config-agents`)。

分身智使出现在任务窗格顶部它们自己的可折叠“Subagents”组中。

---

## 在 TUI 中查看分身智使

分身智使出现在交互式 TUI 中的几个地方：

### 回滚区 (Scrollback, 父会话历史)

生成分身智使时，会在*父级*的回滚区添加一个紧凑的生命周期块：

- `Subagent running: "do the thing" (Implementer · codel-3) — Thinking`
- 或者对于后台的分身智使：`Subagent started: "..."`

运行期间，该块会显示从子级的轮次跟踪器中提取的实时活动后缀 (例如 "Running: cargo test", "Compacting", "Retrying (2/3)")。项目符号的动画 (或颜色) 会根据状态进行更新。

在该块上按 **Enter** (或 Ctrl-F) 即可打开分身智使的完整对话记录。

对于阻塞式分身智使，单个条目会在子级完成时更新其项目符号的颜色。对于后台分身智使，会追加后续的 `Subagent completed/failed/cancelled in Xs: "..."` 块。

### 任务窗格 (Ctrl+G)

如上所述 — 在“Subagents”下分组，带有加载指示器、已用时间以及用于终止或检查的快速访问。

### 全屏框架视图 (子级对话记录)

当您打开分身智使时 (从回滚区块或任务窗格中)，父视图将被一个包含子级完整对话记录的带边框框架所替换：

- 框架内部的标题栏：状态图标 (spinner / ✓ / ✗)、标签 + 加粗说明 + 模型、可选的 "resumed"/"forked" 徽章、实时活动 · 经过时间以及 [✗] 关闭按钮。
- 子级自己的回滚区、思考过程、工具调用和 (有限的) 提示词区域在框架内渲染。
- 分身智使视图很大程度上是观测性的 — 通常您不能像对父会话那样直接向它们发送新的顶层提示词。

使用 `q`，`Esc`，或单击关闭按钮以弹回父视图。父级的回滚区将继续显示分身智使的状态。

## 深度限制

只有顶层会话才能生成分身智使。分身智使不能生成它自己的分身智使：最大嵌套深度为一。如果一个分身智使调用 `spawn_subagent`，该调用会因为深度限制错误而失败。这保持了智使树的扁平化，并防止了失控的生成。

## 何时使用分身智使

**合适的用例：**

- 在父级继续其它工作的同时研究代码库
- 在父级实现更改的同时并行运行测试
- 在提交之前审查生成的更改
- 委托不相互依赖的独立任务

**不适合的用例：**

- 父级可以直接处理的简单任务
- 需要与用户进行紧密往返交互的任务，因为分身智使自动运行，不适合交互式交流
- 上下文设置成本超过并行化收益的任务
